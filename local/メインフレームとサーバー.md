## 1. メインフレームとは

メインフレーム（Mainframe）とは、銀行・保険・官公庁・大企業などの
**大規模な基幹システムで利用される高性能・高信頼な大型コンピュータ**。

大量のデータやトランザクションを、安定して処理することを得意とする。

### 主な利用分野

- 銀行の勘定系システム
- 保険の契約管理
- クレジットカードの決済処理
- 証券取引
- 官公庁システム
- 大企業の基幹業務
- 大量の夜間バッチ処理

特に、

> 「大量の処理を確実に行う」
> 「24時間365日、極力止めない」

ことが重要なシステムで利用されている。

## 2. メインフレームの代表的なメーカー

| メーカー | 代表的な製品・シリーズ |
|---|---|
| IBM | IBM Z |
| 富士通 | GS21 |
| NEC | ACOS |
| Unisys | ClearPath |

### IBM系の代表的な構成

    IBM Z
      ↓
    z/OS
      ↓
    ├─ COBOL：業務プログラム
    ├─ JCL：ジョブ・バッチ実行
    ├─ CICS：オンライン処理
    └─ DB2：データベース

銀行・保険などの金融系システムでよく登場する。

# 3. サーバーとは

サーバーとは、

**他のコンピュータにサービスや機能を提供するコンピュータ**

の総称。

例えば、

- Webサーバー
- APサーバー
- DBサーバー
- ファイルサーバー
- メールサーバー
- DNSサーバー

などがある。

そのため、厳密には

    メインフレームも
        ↓
    広い意味ではサーバーの一種

と考えることができる。

ただし実務では、

- メインフレーム
- UNIXサーバー
- x86サーバー
- クラウド

などを区別して呼ぶことが多い。

---

# 4. メインフレームと一般的なサーバーの違い

| 項目 | メインフレーム | 一般的なサーバー |
|---|---|---|
| 主な用途 | 大規模基幹システム | Web・DB・業務システムなど |
| 処理規模 | 非常に大きい | 小規模～大規模 |
| 信頼性 | 極めて高い | 高い |
| 大量処理 | 非常に強い | 強い |
| OS | z/OSなど | Linux / Windows Serverなど |
| 代表例 | IBM Z | Dell / HPEなど |
| コスト | 非常に高い | 比較的安い |
| 主な業界 | 金融・公共・大企業 | ほぼ全業界 |

# 5. オンプレ環境の代表的な3つの世界

大規模企業では、次のようなシステムが混在していることがある。

## ① メインフレーム系

    IBM Z
      ↓
    z/OS
      ↓
    COBOL / JCL / CICS / DB2
      ↓
    勘定系・契約管理など

非常に重要な基幹処理を担当。

---

## ② UNIX系

例えばIBMの場合、

    IBM Power
      ↓
    AIX
      ↓
    DB2 / WebSphere / JP1など
      ↓
    業務システム

AIXはメインフレームOSではなく、IBMのUNIX系OS。

---

## ③ x86・仮想化系

    物理サーバー
      ↓
    VMware ESXi
      ↓
    ├─ VM
    │   └─ Linux
    │
    ├─ VM
    │   └─ Windows Server
    │
    └─ VM
        └─ RHEL

現在の一般的なオンプレ環境でよく利用される構成。

複数のESXiホストをまとめてクラスタ化し、
HAなどを利用して可用性を高めることも多い。

---

# 6. 「ホスト」という言葉に注意

金融・基幹系では「ホスト」という言葉が複数の意味で使われる。

### ホスト系

金融系などで、

    ホスト系システム

と言った場合、

**メインフレーム系システム**

を意味することが多い。

例：

    「ホストからデータを取得する」
    「ホストとAPI連携する」
    「ホスト側のバッチ処理」

---

### ESXiホスト

VMwareの場合は意味が異なる。

    物理サーバー
      ↓
    ESXi ← ホスト
      ↓
    VM

この場合、

**VMを動かしている物理サーバー**

という意味。

したがって「ホスト」という言葉は文脈で判断する必要がある。

---

# 7. 従来の大規模システム

以前の金融・大企業では、

    メインフレーム
          ↓
       基幹処理
          ↓
       データベース
          ↓
       バッチ処理

のように、重要な処理を大型システムへ集中させる構成が多かった。

メリット：

- 高信頼
- 高性能
- 大量処理に強い
- 長期間安定して利用できる

一方で、

- コストが高い
- 専門技術者が必要
- COBOLなどの技術者不足
- システム変更が難しい
- クラウドとの連携が難しい場合がある

といった課題もある。

---

# 8. 現在の流れ

現在は単純に

    メインフレーム
        ↓
    全部クラウド

という流れではない。

重要なのは、

**適材適所でシステムを分割すること。**

例えば、

    ┌─────────────────┐
    │ メインフレーム       │
    │ 勘定・契約など       │
    └────────┬────────┘
             │
             │ API / MQなど
             ↓
    ┌─────────────────┐
    │ オープン系           │
    │ Linux / Windows     │
    └────────┬────────┘
             │
             ↓
    ┌─────────────────┐
    │ クラウド             │
    │ AWS / Azureなど     │
    └─────────────────┘

というハイブリッド構成も多い。

---

# 9. 今後の大きな流れ

## ① メインフレームをそのまま利用

重要な基幹処理については、

    メインフレーム
        ↓
    継続利用

という選択肢もある。

特に金融では、安定稼働している巨大システムを
無理に全面刷新すること自体が大きなリスクになる。

---

## ② メインフレームをモダナイズ

メインフレーム自体は残しながら、

    Webシステム
        ↓
      API
        ↓
    メインフレーム

のようにAPIなどを利用して外部システムと連携する。

これを

**レガシーモダナイゼーション**

などと呼ぶ。

---

## ③ オープン系へ移行

    メインフレーム
          ↓
    Linux / Windows
          ↓
    仮想化基盤

のように移行するケースもある。

---

## ④ クラウドへ移行

さらに、

    オンプレ
      ↓
    AWS / Azure / GCP

というクラウド移行も進んでいる。

ただし大規模基幹システムでは、
一度にすべて移行するのではなく段階的に移行するケースが多い。

---

## ⑤ クラウドネイティブ化

新しいシステムでは、

    クラウド
      ↓
    コンテナ
      ↓
    Kubernetes
      ↓
    マイクロサービス
      ↓
    API

といった構成も増えている。

---

# 10. システムの流れを大きく見る

大まかな技術の流れとしては、

    メインフレーム
          ↓
       UNIX
          ↓
    x86サーバー
          ↓
       仮想化
    VMwareなど
          ↓
       クラウド
    AWS / Azure
          ↓
    コンテナ
    Docker / Kubernetes
          ↓
    マイクロサービス
          ↓
    クラウドネイティブ

と整理すると分かりやすい。

ただし、

**新しい技術が古い技術を完全に置き換えているわけではない。**

実際の大企業では、

    メインフレーム
          ＋
        AIX
          ＋
    VMware / RHEL
          ＋
      AWS / Azure

のように、複数世代の技術が共存していることも珍しくない。

---

# 11. 重要ポイント

### メインフレーム

- 大規模基幹処理向け
- 金融・保険・公共などで利用
- 高信頼・大量処理に強い
- IBM Zなどが代表的

### 一般的なサーバー

- Web・AP・DBなど幅広く利用
- Linux / Windows Serverなど
- 仮想化して利用することも多い

### 現在

    メインフレーム
          +
    オンプレ仮想化
          +
       クラウド

というハイブリッド環境も多い。

### 今後

単純な「脱メインフレーム」ではなく、

**既存システムを活かしながら、API化・クラウド化・モダナイズしていく**

という考え方が重要。
