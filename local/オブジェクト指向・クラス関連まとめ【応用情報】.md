## 1. まず基本

```text
クラス = 設計図
インスタンス = クラスから作った実体
```

例：

```java
class Car {
    String color;
}

Car car1 = new Car();
Car car2 = new Car();
```

* `Car` → クラス
* `car1`, `car2` → インスタンス（オブジェクト）
* `color` → インスタンス変数

---

## 2. クラス変数（静的フィールド）

**クラス全体で1つだけ存在し、全インスタンスで共有する変数。**

Javaでは `static` を付ける。

```java
class Car {
    static int count = 0;
    String color;
}
```

```text
Carクラス
 ├─ count ← 全員で共有
 │
 ├─ car1
 │   └─ color = "red"
 │
 └─ car2
     └─ color = "blue"
```

### ポイント

`count`

→ **クラス変数 / 静的フィールド**

`color`

→ **インスタンス変数**

### 試験で重要

> 「生成された全オブジェクトで共有される」

→ **クラス変数（static）**

---

## 3. インスタンス変数

**インスタンスごとに別々に持つ変数。**

```java
class User {
    String name;
}
```

```java
User a = new User();
User b = new User();

a.name = "田中";
b.name = "佐藤";
```

```text
Userクラス
   ↓
 ┌────────┐
 │ a      │
 │田中    │
 └────────┘

 ┌────────┐
 │ b      │
 │佐藤    │
 └────────┘
```

### 試験で重要

> 「オブジェクトごとに異なる値を保持」

→ **インスタンス変数**

---

## 4. 静的メンバー（static member）

`static` が付いた、

* クラス変数
* クラスメソッド

などをまとめて**静的メンバー**という。

```java
class MathUtil {

    static int count;

    static int add(int a, int b) {
        return a + b;
    }
}
```

インスタンスを作らなくても、

```java
MathUtil.add(1, 2);
```

のように利用できる。

### 覚え方

```text
static
 ↓
インスタンスではなく
「クラスそのもの」に属する
```

---

## 5. スーパークラス・サブクラス

**継承関係**を表す。

```java
class Animal {
    void eat() {}
}

class Dog extends Animal {
    void bark() {}
}
```

関係は、

```text
       Animal
    スーパークラス
         ↑
       継承
         │
        Dog
     サブクラス
```

### スーパークラス

親となるクラス。

共通する機能を定義する。

### サブクラス

スーパークラスを**継承する子クラス**。

親の機能を引き継ぎながら、独自機能を追加できる。

---

## 6. オーバーライド

サブクラス側で、**親クラスのメソッドを再定義すること。**

```java
class Animal {
    void speak() {
        System.out.println("鳴く");
    }
}

class Dog extends Animal {
    void speak() {
        System.out.println("ワン");
    }
}
```

Dogでは、

```text
speak()
 ↓
「鳴く」ではなく「ワン」
```

となる。

### 試験キーワード

> 継承したメソッドをサブクラスで再定義

→ **オーバーライド**

---

## 7. オーバーロードとの違い

混同注意。

### オーバーライド

**親クラスのメソッドを子クラスで再定義**

```java
Animal.speak()
   ↓
Dog.speak()
```

### オーバーロード

**同じ名前で引数が異なるメソッドを複数定義**

```java
print(String text)

print(int number)

print(String text, int number)
```

### 覚え方

| 用語      | 意味              |
| ------- | --------------- |
| オーバーライド | 親の処理を**上書き**    |
| オーバーロード | 同名メソッドを**複数用意** |

---

## 8. ポリモーフィズム（多態性）

応用情報では重要。

**同じメソッド呼出しでも、実際のオブジェクトによって処理が変わる。**

```java
Animal dog = new Dog();
Animal cat = new Cat();

dog.speak(); // ワン
cat.speak(); // ニャー
```

```text
        Animal
       speak()
       /     \
      /       \
    Dog       Cat
   ワン      ニャー
```

呼び出す側は、

```java
animal.speak();
```

と同じ書き方でよい。

→ **実際のインスタンスによって処理が変わる**

---

## 9. カプセル化

**データと処理をクラスにまとめ、内部を直接操作させない考え方。**

```java
class Account {

    private int balance;

    public void deposit(int money) {
        balance += money;
    }
}
```

外部から、

```java
balance = -100000;
```

のような勝手な変更を防ぐ。

### 試験キーワード

> 内部データを隠蔽する

> 外部からの不正な変更を防ぐ

→ **カプセル化 / 情報隠蔽**

---

## 10. クラスライブラリ

**よく使うクラスを再利用できるようにまとめたもの。**

例えばJavaでは、

```java
String
ArrayList
HashMap
Math
```

など、多数のクラスがあらかじめ用意されている。

```text
クラスライブラリ
   │
   ├─ String
   ├─ ArrayList
   ├─ HashMap
   └─ Math
```

### メリット

* 再利用できる
* 開発効率向上
* 品質を一定にしやすい

---

# 試験で特に重要な切り分け

| 問題文のキーワード     | 答え              |
| ------------- | --------------- |
| クラスから生成された実体  | インスタンス          |
| 各オブジェクトが個別に持つ | インスタンス変数        |
| 全インスタンスで共有    | クラス変数 / 静的フィールド |
| クラスそのものに属する   | static / 静的メンバー |
| 親クラス          | スーパークラス         |
| 子クラス          | サブクラス           |
| 親の機能を引き継ぐ     | 継承              |
| 親のメソッドを子で再定義  | オーバーライド         |
| 同名・引数違いのメソッド  | オーバーロード         |
| 同じ呼出しで異なる動作   | ポリモーフィズム（多態性）   |
| データを外部から隠す    | カプセル化 / 情報隠蔽    |
| 再利用可能なクラス群    | クラスライブラリ        |

---

# 最低限これを覚える

```text
クラス
  ↓ 生成
インスタンス

staticあり
  ↓
クラス全体で共有

staticなし
  ↓
インスタンスごとに持つ


スーパークラス（親）
       ↓ 継承
サブクラス（子）
       ↓
オーバーライド
「親の処理を上書き」


同じ命令
  ↓
オブジェクトによって動作が変わる
  ↓
ポリモーフィズム
```

## 応用情報で特に狙われやすい部分

**① クラス変数 vs インスタンス変数**
→ 「共有か、個別か」

**② スーパークラス vs サブクラス**
→ 「親か、子か」

**③ オーバーライド vs オーバーロード**
→ 「上書きか、同名別引数か」

**④ ポリモーフィズム**
→ 「同じ呼出しで異なる動作」

**⑤ カプセル化**
→ 「内部データを隠す」

この5つはセットで切り分けられるようにしておく。
