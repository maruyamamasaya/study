## 正規化とは

**正規化**とは、データの重複や更新時の矛盾を減らすために、表（テーブル）を適切に分割・整理すること。

基本的には次の順番で正規化する。

```text
非正規形
  ↓ 繰り返し属性をなくす
第1正規形
  ↓ 主キーの一部への依存をなくす
第2正規形
  ↓ 主キー以外への依存をなくす
第3正規形
```

---

# 用語

## 主キー

レコードを一意に識別するための属性。

例：

| 社員ID | 氏名 |
| ---- | -- |
| 001  | 田中 |
| 002  | 佐藤 |

この場合、

```text
主キー：社員ID
```

社員IDが分かれば、氏名を特定できる。

```text
社員ID → 氏名
```

この関係を**関数従属**という。

---

## 関数従属

ある属性Aの値が決まると、属性Bの値が一意に決まる関係。

```text
A → B
```

と表す。

例えば、

```text
社員ID → 社員名
商品ID → 商品名
部署ID → 部署名
```

など。

---

## 非キー属性

**主キーを構成していない属性**。

例えば、

```text
主キー：注文ID

注文ID
商品名
金額
顧客名
```

なら、

```text
非キー属性：
商品名
金額
顧客名
```

となる。

---

## 主キーの真部分集合

複合主キーの**一部分**のこと。

例えば主キーが、

```text
{注文ID, 商品ID}
```

なら、

```text
{注文ID}
{商品ID}
```

は主キーの真部分集合。

主キー全部ではなく、**一部だけ**という意味。

---

# 第1正規形

## 条件

**繰り返し属性・複数の値を持つ属性をなくす。**

1つのセルには、基本的に1つの値だけを入れる。

### 第1正規形ではない例

| 顧客ID | 顧客名 | 電話番号               |
| ---- | --- | ------------------ |
| 001  | 田中  | 090-1111, 080-2222 |
| 002  | 佐藤  | 090-3333           |

1つの項目に電話番号が複数入っている。

```text
電話番号
↓
090-1111
080-2222
```

これは**繰り返し属性**と考えられる。

### 第1正規形

| 顧客ID | 顧客名 | 電話番号     |
| ---- | --- | -------- |
| 001  | 田中  | 090-1111 |
| 001  | 田中  | 080-2222 |
| 002  | 佐藤  | 090-3333 |

または電話番号を別テーブルに分割する。

### 覚え方

> **第1正規形 = 繰り返しをなくす**

```text
1セル1データ
```

---

# 第2正規形

## 条件

第1正規形を満たしたうえで、

**非キー属性が、主キーの真部分集合に関数従属していないこと。**

簡単にいうと、

> **複合主キーの一部分だけで決まる項目をなくす。**

---

## 例

次のテーブルを考える。

| 注文ID | 商品ID | 商品名 | 数量 |
| ---- | ---- | --- | -- |
| 001  | A01  | ペン  | 2  |
| 001  | A02  | ノート | 1  |
| 002  | A01  | ペン  | 5  |

主キーは、

```text
{注文ID, 商品ID}
```

の複合主キー。

ところが、

```text
商品ID → 商品名
```

となっている。

つまり商品名は、

```text
{注文ID, 商品ID}
```

全部がなくても、

```text
商品ID
```

だけで決まる。

商品IDは主キーの**真部分集合**。

したがって、

```text
商品ID → 商品名
```

という**部分関数従属**が存在する。

---

## 第2正規形にする

### 注文明細

| 注文ID | 商品ID | 数量 |
| ---- | ---- | -- |
| 001  | A01  | 2  |
| 001  | A02  | 1  |

### 商品

| 商品ID | 商品名 |
| ---- | --- |
| A01  | ペン  |
| A02  | ノート |

これで商品名は商品テーブルに分離される。

### 覚え方

> **第2正規形 = 主キーの一部への依存をなくす**

```text
複合主キー
   ↓
主キーの一部 → 非キー属性

これを禁止
```

---

# 第3正規形

## 条件

第2正規形を満たしたうえで、

**非キー属性が、他の非キー属性に関数従属していないこと。**

簡単にいうと、

> **主キーではない項目を経由して決まる項目をなくす。**

これを**推移的関数従属**という。

---

## 例

| 社員ID | 社員名 | 部署ID | 部署名 |
| ---- | --- | ---- | --- |
| 001  | 田中  | D01  | 営業部 |
| 002  | 佐藤  | D02  | 開発部 |

主キー：

```text
社員ID
```

関数従属を見ると、

```text
社員ID → 部署ID
```

さらに、

```text
部署ID → 部署名
```

となる。

つまり、

```text
社員ID
 ↓
部署ID
 ↓
部署名
```

となっている。

部署IDは**非キー属性**。

部署名が非キー属性である部署IDに依存している。

これが**推移的関数従属**。

---

## 第3正規形にする

### 社員

| 社員ID | 社員名 | 部署ID |
| ---- | --- | ---- |
| 001  | 田中  | D01  |
| 002  | 佐藤  | D02  |

### 部署

| 部署ID | 部署名 |
| ---- | --- |
| D01  | 営業部 |
| D02  | 開発部 |

これで、

```text
部署ID → 部署名
```

を別テーブルとして管理できる。

### 覚え方

> **第3正規形 = 非キー属性への依存をなくす**

```text
主キー → 非キー属性 → 非キー属性

という依存をなくす
```

---

# 第1〜第3正規形まとめ

| 正規形   | なくすもの   | ポイント            |
| ----- | ------- | --------------- |
| 第1正規形 | 繰り返し属性  | 1セル1値           |
| 第2正規形 | 部分関数従属  | 主キーの一部だけに依存させない |
| 第3正規形 | 推移的関数従属 | 非キー属性に依存させない    |

---

# 試験用の覚え方

```text
第1正規形
→ 繰り返しをなくす

第2正規形
→ 主キーの「一部」への依存をなくす

第3正規形
→ 主キー「以外」への依存をなくす
```

さらに短くすると、

```text
1：繰り返し
2：一部依存
3：非キー依存
```

---

# 関数従属で見る

### 第2正規形でNG

主キーが

```text
{A, B}
```

なのに、

```text
A → C
```

となっている。

Cは主キー全部ではなく、主キーの真部分集合 `A` だけに依存している。

```text
{A, B} → C   ○

しかし

A → C         ← これが問題
```

---

### 第3正規形でNG

```text
A → B
B → C
```

Aが主キーで、BとCが非キー属性の場合、

```text
A → B → C
```

となる。

Cが主キーではなくBに依存しているため、第3正規形ではない。

---

# 応用情報での見分け方

問題で次の言葉が出たら対応させる。

```text
繰り返し属性
→ 第1正規形

主キーの真部分集合に関数従属
→ 第2正規形に違反

部分関数従属
→ 第2正規形に違反

非キー属性に関数従属
→ 第3正規形に違反

推移的関数従属
→ 第3正規形に違反
```

## 最重要

```text
第1正規形：繰り返さない

第2正規形：
主キーが {A,B} なら
Aだけ、Bだけで非キー属性が決まらない

第3正規形：
主キー → 非キー → 非キー
という関係を作らない
```
