# アローダイアグラム

## 概要

**プロジェクトの作業順序と所要時間を矢印で表した図。**

主に以下を求めるために使う。

- 作業の順序
- プロジェクト全体の所要時間
- クリティカルパス
- 各作業の余裕時間

---

## 基本

- **矢印（→）**：作業
- **○（ノード）**：作業の開始・終了地点
- **数字**：作業に必要な時間

例：

① ──A:3日──→ ② ──B:4日──→ ③

AとBを順番に行うため、

3日 + 4日 = 7日

全体で **7日** 必要。

---

## クリティカルパス

**開始から終了までで、最も所要時間が長い経路。**

例：

ルート①：A → B → D = 3 + 4 + 2 = 9日  
ルート②：A → C → D = 3 + 2 + 2 = 7日

→ クリティカルパスは **ルート①（9日）**

### ポイント

クリティカルパス上の作業が遅れると、

**プロジェクト全体の完了も遅れる。**

---

## 重要用語

| 用語 | 意味 |
|---|---|
| クリティカルパス | 最も時間がかかる経路 |
| 最早結合点時刻 | 最も早くその地点に到達できる時刻 |
| 最遅結合点時刻 | 全体を遅らせずに到達できる最も遅い時刻 |
| 余裕時間 | 遅れても全体に影響しない時間 |
| ダミー作業 | 所要時間0。作業の依存関係だけを表す |

---

## 応用情報でのポイント

問題では主に、

1. 各ルートの時間を足す
2. **最も長いルートを探す**
3. そのルートが **クリティカルパス**
4. プロジェクト全体の最短所要時間を求める

という流れ。

> **「一番長い経路 = クリティカルパス」**

と覚えておけばOK。
