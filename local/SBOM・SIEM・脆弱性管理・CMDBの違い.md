## まず結論

| 用語        | 何を管理・確認する？    | 試験キーワード         |
| --------- | ------------- | --------------- |
| **SBOM**  | ソフトウェアの**部品** | OSS・ライブラリ・依存関係  |
| **SIEM**  | システムの**ログ**   | ログ収集・相関分析・攻撃検知  |
| **脆弱性管理** | システムの**弱点**   | CVE・パッチ・脆弱性診断   |
| **CMDB**  | IT資産の**構成情報** | サーバ・NW・関係性・構成管理 |

---

# 1. SBOM

**Software Bill of Materials（ソフトウェア部品表）**

ソフトウェアが「何で作られているか」を一覧化するもの。

例えば、

```text
自社Webアプリ
├── React
├── Next.js
├── axios
└── OpenSSL
```

のように、使用しているOSS・ライブラリ・バージョンなどを管理する。

### なぜ必要？

あるライブラリに脆弱性が発見されたとき、

> 「うちのシステム、そのライブラリ使ってる？」

をすぐ確認できる。

### 試験キーワード

* OSS
* ライブラリ
* ソフトウェア部品
* 依存関係
* サプライチェーン
* 使用コンポーネントの把握

→ **SBOM**

---

# 2. SIEM

**Security Information and Event Management**

複数のシステムから**ログを集めて分析し、セキュリティ上の異常を検知する仕組み**。

```text
サーバ ──┐
FW ─────┤
端末 ────┼→ SIEM → 相関分析 → 不審な動きを検知
クラウド ─┘
```

例えば、

```text
深夜に大量のログイン失敗
        +
海外IPからログイン成功
        ↓
不正アクセスの可能性
```

のように、複数ログを組み合わせて分析する。

### 試験キーワード

* ログ
* イベント
* 一元管理
* 相関分析
* リアルタイム監視
* 不正アクセス検知

→ **SIEM**

---

# 3. 脆弱性管理

システムに存在する**セキュリティ上の弱点を継続的に発見・評価・対応する活動**。

基本的な流れは、

```text
脆弱性を発見
   ↓
影響・リスクを評価
   ↓
優先順位を決定
   ↓
パッチ適用・設定変更
   ↓
再確認
```

例えば、

> 「OpenSSLに重大な脆弱性がある」
>
> → 自社への影響を確認
> → パッチ適用
> → 修正されたか確認

### 試験キーワード

* CVE
* CVSS
* 脆弱性診断
* セキュリティパッチ
* リスク評価
* 修正・対応

→ **脆弱性管理**

---

# 4. CMDB

**Configuration Management Database（構成管理データベース）**

会社のITシステムを構成する**IT資産と、その関係性を管理するDB**。

例えば、

```text
Webサーバ
 │
 ├─ OS：Red Hat
 ├─ IP：10.0.1.10
 └─ 接続先
      ↓
   DBサーバ
      ↓
   ストレージ
```

などを管理する。

対象になるものは、

* サーバ
* OS
* ネットワーク機器
* DB
* アプリケーション
* クラウドリソース
* 各構成要素の関係

など。

### 試験キーワード

* 構成アイテム（CI）
* IT資産
* サーバ
* ネットワーク
* 構成情報
* システム間の依存関係
* ITサービス管理

→ **CMDB**

---

# SBOMとCMDBの違い【重要】

似ているが、見る範囲が違う。

```text
CMDB
└─ Webサーバ
    └─ Webアプリ
        └─ SBOM
            ├─ React
            ├─ axios
            └─ OpenSSL
```

### CMDB

**システム全体の構成を見る**

> 「どんなサーバやシステムが存在している？」

### SBOM

**ソフトウェア内部の部品を見る**

> 「このアプリはどんなライブラリで作られている？」

---

# SBOMと脆弱性管理の違い【重要】

### SBOM

```text
「何を使っている？」
```

を把握する。

### 脆弱性管理

```text
「何が危険？」
「どう対応する？」
```

を管理する。

例えば、

```text
SBOM
↓
OpenSSL 3.xを使用していることが判明

脆弱性情報
↓
OpenSSL 3.xに脆弱性発見

脆弱性管理
↓
影響確認 → 優先順位付け → パッチ適用
```

つまり、**SBOMは脆弱性管理にも活用できる**。

---

# SIEMと脆弱性管理の違い

### SIEM

**起きている・起きた攻撃をログから見つける**

```text
不審なログ
↓
攻撃かもしれない！
```

### 脆弱性管理

**攻撃される可能性のある弱点を見つけて直す**

```text
脆弱性発見
↓
攻撃される前に直そう！
```

# 試験での見分け方

問題文のキーワードを見る。

```text
「OSS・ライブラリ・依存関係」
        ↓
       SBOM

「ログ・相関分析・異常検知」
        ↓
       SIEM

「CVE・CVSS・パッチ・弱点」
        ↓
     脆弱性管理

「サーバ・NW・IT資産・構成情報」
        ↓
       CMDB
```
