## 1. OS・プロセス・スレッド

| 用語             | 意味                   | 試験での見分け方           |
| -------------- | -------------------- | ------------------ |
| **OS**         | ハードウェアやアプリを管理する基本ソフト | CPU・メモリ・ファイル・入出力管理 |
| **カーネル**       | OSの中核部分              | CPU・メモリ・デバイスを直接管理  |
| **プロセス**       | 実行中のプログラム            | **独立したメモリ空間**      |
| **スレッド**       | プロセス内の実行単位           | 同じプロセス内で**メモリを共有** |
| **マルチタスク**     | 複数処理を並行して実行          | CPU時間を切り替える        |
| **コンテキストスイッチ** | CPUが実行対象を切り替える       | 切替えにはオーバーヘッドがある    |
| **スケジューリング**   | CPUをどの処理に割り当てるか決定    | CPU割当て問題           |
| **ラウンドロビン**    | 一定時間ずつCPUを割り当てる      | **タイムクォンタム**がキーワード |

### プロセスとスレッド

```text
プロセス
├─ メモリ
├─ スレッドA
├─ スレッドB
└─ スレッドC
```

* **プロセス** → 独立性が高い
* **スレッド** → プロセス内のメモリ・資源を共有

## 2. 排他制御・デッドロック

| 用語         | 意味                | 試験ポイント         |
| ---------- | ----------------- | -------------- |
| **排他制御**   | 同時アクセスによる競合を防ぐ    | 共有資源へのアクセス     |
| **セマフォ**   | 資源を利用できる数を管理      | 排他制御・同期処理      |
| **競合状態**   | 実行タイミングによって結果が変わる | Race Condition |
| **デッドロック** | お互いに資源解放を待ち続ける    | 処理が永久に進まない     |

### デッドロックのイメージ

```text
処理A：資源Xを持っている → 資源Y待ち
                              ↑
                              ↓
処理B：資源Yを持っている → 資源X待ち

→ お互い待ち続ける
→ デッドロック
```

## 3. 仮想記憶・ページング

| 用語           | 意味                   | 試験ポイント        |
| ------------ | -------------------- | ------------- |
| **仮想記憶**     | ディスクを利用して大きなメモリ空間を実現 | RAM不足を補う      |
| **ページング**    | メモリを固定サイズで分割して管理     | 「ページ」がキーワード   |
| **ページフォールト** | 必要なページが主記憶に存在しない     | ディスクから読み込む    |
| **ページ置換**    | 不要なページを追い出す          | LRU・FIFOなど    |
| **LRU**      | 最も長く使われていないページを追い出す  | **最近使ってないもの** |
| **FIFO**     | 最初に入ったページから追い出す      | **一番古いもの**    |
| **スラッシング**   | ページ交換が多発して性能低下       | ページフォールト頻発    |

### 流れで覚える

```text
仮想記憶
  ↓
ページ単位で管理
  ↓
必要なページがRAMにない
  ↓
ページフォールト
  ↓
ディスクから読み込む
  ↓
これが頻発
  ↓
スラッシング
```

## 4. プログラムの実行

| 用語             | 意味                | 試験での見分け方     |
| -------------- | ----------------- | ------------ |
| **コンパイラ**      | プログラム全体を翻訳        | **実行前に一括翻訳** |
| **インタプリタ**     | プログラムを逐次解釈        | **実行しながら翻訳** |
| **リンカ**        | 複数のオブジェクトファイル等を結合 | **結合**       |
| **ローダ**        | プログラムを主記憶へ読み込む    | **メモリへロード**  |
| **JITコンパイラ**   | 実行時に機械語へコンパイル     | Javaなど       |
| **バイトコード**     | VMで実行する中間コード      | JVMなど        |
| **ガベージコレクション** | 不要になったメモリを自動回収    | Javaなど       |

### コンパイラとインタプリタ

```text
コンパイラ
ソースコード
   ↓
一括翻訳
   ↓
実行


インタプリタ
ソースコード
   ↓
1つずつ解釈
   ↓
実行
```

## 5. ソフトウェア・ミドルウェア

| 用語         | 意味                    | 試験ポイント        |
| ---------- | --------------------- | ------------- |
| **API**    | ソフトウェア同士が機能を利用するための窓口 | システム間連携       |
| **ミドルウェア** | OSとアプリの間に位置するソフト      | DBMS・Webサーバなど |
| **OSS**    | ソースコードが公開されているソフトウェア  | ライセンス問題       |
| **GPL**    | OSSライセンスの一種           | コピーレフト        |
| **IDE**    | 統合開発環境                | エディタ・デバッグ等を統合 |
| **デバッガ**   | バグを調査するツール            | ブレークポイントなど    |

# 6. ソフトウェア開発手法

| 用語               | 意味               | 試験での見分け方                       |
| ---------------- | ---------------- | ------------------------------ |
| **ウォーターフォール**    | 工程を順番に進める        | 要件→設計→実装→テスト                   |
| **アジャイル**        | 短期間の開発を繰り返す      | 変化への対応                         |
| **スクラム**         | アジャイルの代表的手法      | スプリント・バックログ                    |
| **スプリント**        | スクラムの短い開発期間      | 反復開発                           |
| **プロダクトバックログ**   | 開発する機能・要求の一覧     | 優先順位付き                         |
| **リファクタリング**     | 外部仕様を変えず内部構造を改善  | **機能は変えない**                    |
| **リバースエンジニアリング** | 既存システムから仕様・設計を解析 | **完成物→設計**                     |
| **リエンジニアリング**    | 既存システムを分析して再構築   | 改善・再構築                         |
| **DevOps**       | 開発と運用が協力する考え方    | Development + Operations       |
| **CI**           | 変更を頻繁に統合・テスト     | Continuous Integration         |
| **CD**           | 継続的にリリース可能にする    | Continuous Delivery/Deployment |

# 7. UML・設計図

| 用語         | 何を見る図？       | キーワード         |
| ---------- | ------------ | ------------- |
| **クラス図**   | クラスの構造・関係    | 属性・メソッド・継承    |
| **シーケンス図** | オブジェクト間のやり取り | **時間の流れ**     |
| **状態遷移図**  | 状態の変化        | 状態・イベント       |
| **DFD**    | データの流れ       | **データフロー**    |
| **ER図**    | データ同士の関係     | **DB・エンティティ** |

### 試験での切り分け

```text
「クラスの関係は？」
→ クラス図

「時間順の処理は？」
→ シーケンス図

「状態がどう変化する？」
→ 状態遷移図

「データがどこへ流れる？」
→ DFD

「DBのテーブル・データ関係は？」
→ ER図
```

# 8. ソフトウェアテスト

| 用語              | 意味              | 試験ポイント       |
| --------------- | --------------- | ------------ |
| **ブラックボックステスト** | 内部構造を意識せずテスト    | 入力と出力        |
| **ホワイトボックステスト** | 内部ロジックを確認       | プログラム内部      |
| **同値分割**        | 同じ結果になる入力をグループ化 | 代表値をテスト      |
| **境界値分析**       | 境界付近を重点的にテスト    | 上限・下限        |
| **命令網羅**        | 全命令を最低1回実行      | C0           |
| **判定条件網羅**      | 判定結果の真・偽を実行     | C1           |
| **回帰テスト**       | 修正による既存機能への影響確認 | **修正後の再テスト** |

### ブラックボックス

```text
中身は見ない

入力
 ↓
[ プログラム ]
 ↓
出力

→ 入力と出力から確認
```

### ホワイトボックス

```text
プログラム内部を見る

if
for
while
条件分岐
処理経路

→ 内部ロジックを確認
```

# 9. 結合テスト

| 用語            | 意味           |
| ------------- | ------------ |
| **トップダウンテスト** | 上位モジュールからテスト |
| **ボトムアップテスト** | 下位モジュールからテスト |
| **スタブ**       | 下位モジュールの代用品  |
| **ドライバ**      | 上位モジュールの代用品  |

### 超重要な組み合わせ

```text
トップダウン
    ↓
上からテスト
    ↓
下がまだない
    ↓
スタブで代用


ボトムアップ
    ↓
下からテスト
    ↓
上がまだない
    ↓
ドライバで代用
```

**覚え方**

* トップダウン → **スタブ**
* ボトムアップ → **ドライバ**
