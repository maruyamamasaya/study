## 全体像

| 用語  | 意味                              | 一言で                |
| --- | ------------------------------- | ------------------ |
| SOA | Service Oriented Architecture   | **システムをサービス単位で構成** |
| SLA | Service Level Agreement         | **サービス品質の合意**      |
| ERP | Enterprise Resource Planning    | **経営資源を統合管理**      |
| BPR | Business Process Re-engineering | **業務プロセスを抜本的に改革**  |

---

# 1. SOA

**SOA（Service Oriented Architecture）**
＝ サービス指向アーキテクチャ

システムの機能を、独立した**サービス**として構築し、それらを組み合わせてシステムを実現する考え方。

## 例

ECサイトに、

```text
・顧客認証
・在庫確認
・決済
・配送
・メール通知
```

という機能がある場合、それぞれを独立したサービスとして構築する。

```text
ECサイト
   │
   ├→ 認証サービス
   ├→ 在庫サービス
   ├→ 決済サービス
   └→ 配送サービス
```

必要に応じてサービスを組み合わせたり、他のシステムから再利用したりできる。

### 特徴

* 機能をサービス単位に分割
* サービスを組み合わせて利用
* 再利用しやすい
* システム変更に柔軟に対応しやすい

> **SOA = システムを「サービスという部品」に分ける**

---

# 2. SLA

**SLA（Service Level Agreement）**
＝ サービスレベル合意

サービス提供者と利用者の間で、**サービス品質の水準について合意すること**。

例えばクラウドサービスなら、

```text
稼働率：99.9%以上
障害対応：30分以内に開始
問い合わせ：24時間以内に回答
```

などを定める。

## SLAで定める例

* 稼働率
* 応答時間
* 障害復旧時間
* サポート時間
* 問い合わせへの対応時間

> **SLA = 「このくらいの品質でサービスを提供します」という約束**

---

# 3. ERP

**ERP（Enterprise Resource Planning）**
＝ 企業資源計画

企業の持つ、

```text
ヒト
モノ
カネ
情報
```

などの**経営資源を企業全体で統合的に管理する考え方**。

また、それを実現する統合業務システムをERPシステム（ERPパッケージ）と呼ぶ。

## 例

従来、

```text
販売部 → 販売システム

経理部 → 会計システム

人事部 → 人事システム

倉庫   → 在庫システム
```

とバラバラだったものを、

```text
        ERP
         │
 ┌───────┼───────┐
 ↓       ↓       ↓
販売    会計    人事
 ↓
在庫・購買
```

のように統合する。

### メリット

* データを一元管理できる
* 部門間で情報を共有できる
* 経営情報を把握しやすくなる
* 業務の標準化・効率化につながる

> **ERP = 会社全体の情報・経営資源をまとめて管理**

---

# 4. BPR

**BPR（Business Process Re-engineering）**
＝ ビジネスプロセス・リエンジニアリング

既存の業務プロセスを前提に少し改善するのではなく、**業務そのものを抜本的に見直して再設計すること**。

## 例

現在、

```text
申請
 ↓
紙に記入
 ↓
上司が押印
 ↓
総務が確認
 ↓
システムへ入力
```

という業務がある。

単に、

```text
紙 → Excel
```

にするだけではなく、

```text
Webから申請
 ↓
自動承認・電子承認
 ↓
データ自動登録
```

のように、**業務の流れそのものを作り直す**。

### ポイント

* 既存業務を前提としない
* 業務プロセスを抜本的に見直す
* コスト・品質・スピードなどを大幅に改善する

> **BPR = 業務を根本から作り直す**

---

# ERPとBPRの関係

ERP導入とBPRは関連して登場することがある。

例えば、

```text
現在の業務
    ↓
BPR
「そもそも、この業務必要？」
「もっと効率化できない？」
    ↓
業務を再設計
    ↓
ERP導入
    ↓
販売・会計・在庫などを統合
```

という流れ。

重要なのは、

```text
BPR
→ 業務を変える

ERP
→ 経営資源・業務情報を統合管理する
```

という違い。

---

# SOAとSLAの違い

名前は似ているが、内容は全く異なる。

```text
SOA
→ Architecture
→ システムをどう作るか

SLA
→ Agreement
→ サービス品質をどう約束するか
```

|       | SOA            | SLA      |
| ----- | -------------- | -------- |
| 分野    | システム設計         | ITサービス管理 |
| 目的    | サービス単位でシステムを構成 | 品質水準を合意  |
| キーワード | 再利用・サービス       | 稼働率・応答時間 |

---

# 4つの違い

```text
SOA
→ システムの「作り方」

SLA
→ サービス品質の「約束」

ERP
→ 会社の情報・資源の「統合」

BPR
→ 仕事のやり方の「改革」
```

## 具体例で考える

ある会社がシステムを刷新するとする。

### BPR

```text
「今の業務自体を見直そう」
```

→ 業務改革

### ERP

```text
「販売・在庫・会計を統合しよう」
```

→ 統合管理

### SOA

```text
「認証・決済などを
サービスとして分けて作ろう」
```

→ システム設計

### SLA

```text
「システムの稼働率は
99.9%以上にしよう」
```

→ サービス品質

| **ERP** | 経営資源・統合管理    | 販売・会計・在庫を統合   |

# 問題文での見分け方

```text
「機能をサービスとして部品化・再利用」
→ SOA

「稼働率・応答時間などを合意」
→ SLA

「ヒト・モノ・カネ・情報」
「基幹業務を統合」
→ ERP

「業務プロセスを抜本的に見直す」
→ BPR
```

# 超短縮版

**SOA = サービスで作る
SLA = 品質を約束する
ERP = 会社全体を統合する
BPR = 業務を根本から変える**
