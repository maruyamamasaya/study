## 全体イメージ

CPUは非常に高速だが、主記憶（メインメモリ）はCPUより遅い。

その速度差を埋めるために、さまざまな仕組みが使われる。

```text
CPU
 ↓
キャッシュメモリ
 ↓
主記憶
 ↓
補助記憶装置
```

上に行くほど、

* 高速
* 容量が小さい
* 高価

下に行くほど、

* 低速
* 容量が大きい
* 安価

---

# キャッシュメモリ

## 概要

**CPUと主記憶の間に置かれる高速なメモリ。**

よく使うデータを一時的に保存しておき、
CPUが主記憶までアクセスする回数を減らす。

```text
CPU
 ↓
キャッシュ
 ↓
主記憶
```

## ポイント

* 主記憶より高速
* CPUに近い
* 容量は小さい
* よく使うデータを保存する

### 覚え方

> **キャッシュ = よく使うデータを近くに置く**

---

# メモリインターリーブ

## 概要

主記憶を複数の**メモリバンク**に分割し、
並行してアクセスすることで高速化する方式。

例えば、

```text
メモリバンク0
メモリバンク1
メモリバンク2
メモリバンク3
```

にデータを分散して配置する。

```text
アドレス0 → バンク0
アドレス1 → バンク1
アドレス2 → バンク2
アドレス3 → バンク3
アドレス4 → バンク0
```

複数のバンクへ順番にアクセスすることで、
次のデータを効率よく読み出せる。

### 覚え方

> **メモリインターリーブ = 主記憶を複数バンクに分けて並行アクセス**

---

# キャッシュメモリとの違い

| 項目  | キャッシュメモリ        | メモリインターリーブ    |
| --- | --------------- | ------------- |
| 目的  | CPUと主記憶の速度差を埋める | 主記憶へのアクセスを高速化 |
| 方法  | 高速な別メモリを使う      | 主記憶を複数バンクに分割  |
| データ | よく使うデータを保存      | データを複数バンクに分散  |
| 場所  | CPUと主記憶の間       | 主記憶内部         |

```text
キャッシュ
→ 高速メモリを間に置く

インターリーブ
→ 主記憶そのものを複数に分ける
```

---

# キャッシュの局所性

キャッシュメモリは、プログラムの**局所性**を利用する。

## 時間的局所性

一度使ったデータは、
**近いうちにもう一度使われる可能性が高い**。

例：

```text
ループ処理で同じ変数を何度も使う
```

## 空間的局所性

あるデータを使ったら、
**その近くのデータも使われる可能性が高い**。

例：

```text
配列を先頭から順番に読む
```

### 覚え方

```text
時間的局所性
→ また使う

空間的局所性
→ 近くも使う
```

---

# キャッシュヒット・キャッシュミス

## キャッシュヒット

必要なデータがキャッシュに存在する。

```text
CPU
 ↓
キャッシュにある！
 ↓
高速に取得
```

## キャッシュミス

必要なデータがキャッシュに存在しない。

```text
CPU
 ↓
キャッシュにない
 ↓
主記憶まで取りに行く
```

キャッシュヒット率が高いほど、
平均アクセス時間は短くなる。

---

# ライトスルー方式

CPUがデータを書き込むとき、

**キャッシュと主記憶の両方に同時に書き込む。**

```text
CPU
 ├→ キャッシュ
 └→ 主記憶
```

## 特徴

* キャッシュと主記憶の内容が常に一致しやすい
* データ管理が簡単
* 主記憶にも毎回書くので遅くなりやすい

### 覚え方

> **ライトスルー = キャッシュを通り抜けて主記憶まで書く**

---

# ライトバック方式

まずキャッシュだけに書き込み、
後からまとめて主記憶へ反映する方式。

```text
CPU
 ↓
キャッシュ
 ↓
後で主記憶
```

## 特徴

* 高速
* 主記憶への書込み回数を減らせる
* キャッシュと主記憶の内容が一時的に異なる

### 覚え方

> **ライトバック = 後で主記憶へ戻す**

---

# ライトスルーとライトバック

| 方式     | 主記憶への書込み | 特徴        |
| ------ | -------- | --------- |
| ライトスルー | 毎回       | 安全・単純だが遅め |
| ライトバック | 後で       | 高速だが管理が複雑 |

---

# 仮想記憶

## 概要

主記憶が足りない場合に、
補助記憶装置の一部を主記憶のように利用する仕組み。

```text
主記憶
+
SSD / HDD
↓
仮想的に大きなメモリとして扱う
```

### 覚え方

> **仮想記憶 = ディスクを使って主記憶を広く見せる**

---

# ページング方式

仮想記憶を実現する代表的な方式。

メモリを一定サイズの**ページ**に分割する。

```text
仮想記憶
↓
ページ1
ページ2
ページ3
ページ4
```

主記憶側では対応する領域を**ページフレーム**という。

---

# ページフォールト

必要なページが主記憶に存在しない状態。

```text
CPUがページを要求
 ↓
主記憶にない
 ↓
ページフォールト
 ↓
ディスクから主記憶へ読み込む
```

ディスクアクセスが発生するため、
処理速度が大きく低下する。

---

# スラッシング

ページフォールトが大量に発生し、
ページの入替えばかり行っている状態。

```text
ページ読込み
 ↓
追い出す
 ↓
また必要になる
 ↓
再び読込み
```

結果として、
CPUが本来の処理をほとんどできなくなる。

### 覚え方

> **スラッシング = ページ交換しすぎて性能低下**

---

# TLB

**TLB（Translation Lookaside Buffer）**

仮想アドレスから物理アドレスへの変換情報を
高速に参照するためのキャッシュ。

```text
仮想アドレス
 ↓
TLB
 ↓
物理アドレス
```

### 覚え方

> **TLB = アドレス変換用のキャッシュ**

---

# 試験用まとめ

| 用語         | 内容                 |
| ---------- | ------------------ |
| キャッシュメモリ   | CPUと主記憶の間の高速メモリ    |
| メモリインターリーブ | 主記憶を複数バンクに分割して高速化  |
| 時間的局所性     | 同じデータを再び使う         |
| 空間的局所性     | 近くのデータを使う          |
| キャッシュヒット   | キャッシュに目的データがある     |
| キャッシュミス    | キャッシュに目的データがない     |
| ライトスルー     | キャッシュと主記憶へ同時書込み    |
| ライトバック     | キャッシュに書いて後から主記憶へ反映 |
| 仮想記憶       | ディスクを使って主記憶を広く見せる  |
| ページフォールト   | 必要なページが主記憶にない      |
| スラッシング     | ページ交換が頻発して性能低下     |
| TLB        | アドレス変換情報のキャッシュ     |

---

# 最低限覚える

```text
キャッシュ
→ よく使うデータをCPUの近くに置く

メモリインターリーブ
→ 主記憶を複数バンクに分けて並行アクセス

ライトスルー
→ 毎回主記憶まで書く

ライトバック
→ 後で主記憶に書く

ページフォールト
→ 必要なページが主記憶にない

スラッシング
→ ページ交換しすぎ

TLB
→ 仮想→物理アドレス変換のキャッシュ
```
