## EAとは

**EA（Enterprise Architecture）**とは、組織全体の業務と情報システムを整理し、全体最適の観点から改善していくための考え方・設計手法。

企業内で、

```text id="7u0ejc"
業務
 ↓
データ
 ↓
アプリケーション
 ↓
技術・インフラ
```

をバラバラに考えるのではなく、**企業全体を一つの構造として整理する**。

> **EA = 企業全体の業務・システムの設計図**

---

# EAを構成する4つの体系

EAでは主に次の4つに分けて整理する。

| 体系 | 名称              | 何を見る？    |
| -- | --------------- | -------- |
| BA | ビジネスアーキテクチャ     | 業務       |
| DA | データアーキテクチャ      | データ      |
| AA | アプリケーションアーキテクチャ | システム・アプリ |
| TA | テクノロジアーキテクチャ    | 技術・インフラ  |

```text id="nkjpnx"
BA → 業務
DA → データ
AA → アプリ
TA → 技術
```

---

# 1. BA：ビジネスアーキテクチャ

**Business Architecture**

企業の**業務内容・業務プロセス**を整理する。

## 例えば

ECサイトを運営する会社なら、

```text id="n5l6q5"
商品登録
  ↓
注文受付
  ↓
決済
  ↓
出荷
  ↓
売上管理
```

といった業務の流れを整理する。

## 主な対象

* 業務プロセス
* 業務機能
* 組織
* 業務の流れ

> **BA = 仕事をどう進めているか**

---

# 2. DA：データアーキテクチャ

**Data Architecture**

企業で扱う**データの構造や関係**を整理する。

## 例えば

ECサイトなら、

```text id="twj8jl"
顧客
 │
 ├── 注文
 │     │
 │     └── 商品
 │
 └── 支払情報
```

など、どのようなデータが存在し、どのような関係になっているか整理する。

## 主な対象

* 顧客データ
* 商品データ
* 売上データ
* データ間の関係
* データ構造

> **DA = どんなデータを使っているか**

---

# 3. AA：アプリケーションアーキテクチャ

**Application Architecture**

業務を実現するために、**どのようなアプリケーション・システムが必要か**を整理する。

## 例えば

```text id="l2svt3"
ECシステム
     ↓
在庫管理システム
     ↓
会計システム
     ↓
顧客管理システム
```

どのシステムがどの業務を担当し、システム同士がどう連携するかを整理する。

## 主な対象

* 業務システム
* アプリケーション
* システム間連携
* アプリケーション機能

> **AA = どのシステムを使うか**

---

# 4. TA：テクノロジアーキテクチャ

**Technology Architecture**

システムを動かすための**技術・インフラ基盤**を整理する。

## 例えば

```text id="6tt4lg"
アプリケーション
      ↓
Linux
      ↓
仮想化・クラウド
      ↓
サーバ
      ↓
ネットワーク
```

## 主な対象

* OS
* サーバ
* ネットワーク
* データベース製品
* ミドルウェア
* クラウド
* ハードウェア

> **TA = どんな技術で動かすか**

---

# 4体系の関係

例えば「商品の注文」という業務なら、

```text id="f5vxg8"
BA
「商品を注文する」
      ↓
DA
「顧客・商品・注文データ」
      ↓
AA
「ECシステム・在庫管理システム」
      ↓
TA
「サーバ・OS・DB・ネットワーク」
```

という形で考えられる。

## 覚え方

```text id="5kkf3p"
BA → 仕事

DA → 情報

AA → システム

TA → インフラ
```

---

# EAの参照モデル

EAでは、それぞれの領域を整理・標準化するために**参照モデル（Reference Model）**を利用する。

参照モデルとは、

> **EAを整理するときに利用する共通の分類・基準・お手本**

のようなもの。

代表的なものとして次のモデルがある。

| 参照モデル | 対応する領域 | 内容         |
| ----- | ------ | ---------- |
| BRM   | BA     | 業務         |
| DRM   | DA     | データ        |
| SRM   | AA     | サービス・アプリ機能 |
| TRM   | TA     | 技術         |

---

# BRM

**Business Reference Model**

業務を分類・整理するための参照モデル。

```text id="slgh7v"
BRM
↓
業務を整理
```

例えば、

* 顧客管理
* 販売管理
* 契約管理
* 会計
* 人事

など、組織の業務・機能を整理する。

> **BRM = 業務のお手本**

---

# DRM

**Data Reference Model**

データを分類・整理するための参照モデル。

```text id="t19sdz"
DRM
↓
データを整理
```

例えば、

```text id="ej9bpf"
顧客
商品
注文
契約
売上
```

などのデータについて、意味・構造・関係などを整理する。

> **DRM = データのお手本**

---

# SRM

**Service Component Reference Model**
（サービスコンポーネント参照モデル）

システムが提供する**サービスや機能を分類・整理するための参照モデル**。

例えば、

```text id="eqixg5"
認証
検索
決済
通知
帳票
```

など、アプリケーションが提供する機能・サービスを整理する。

> **SRM = システム機能・サービスのお手本**

---

# TRM

**Technical Reference Model**

システムで利用する**技術やIT基盤を分類・整理するための参照モデル**。

例えば、

```text id="4hqykb"
OS
DBMS
ネットワーク
ミドルウェア
通信技術
```

などを整理する。

> **TRM = 技術のお手本**

---

# 4体系と参照モデルの対応

ここが試験では重要。

| EAの体系 | 意味       | 参照モデル   |
| ----- | -------- | ------- |
| BA    | 業務       | **BRM** |
| DA    | データ      | **DRM** |
| AA    | アプリ・サービス | **SRM** |
| TA    | 技術       | **TRM** |

```text id="x7bkag"
BA ─→ BRM
│      Business
│
DA ─→ DRM
│      Data
│
AA ─→ SRM
│      Service
│
TA ─→ TRM
       Technical
```

---

# 現状と理想像

EAでは、現在の状態と将来あるべき状態を比較して改善していく。

## As-Is

**現在の状態**

```text id="wxshsn"
現在
↓
システムがバラバラ
データが重複
業務が複雑
```

## To-Be

**将来あるべき状態**

```text id="w9tvrg"
理想
↓
システム統合
データ統一
業務効率化
```

そして、

```text id="8t3nvm"
As-Is
 現状
  ↓
ギャップ分析
  ↓
改善・移行
  ↓
To-Be
 あるべき姿
```

という形で全体最適を目指す。

## EAとは

```text id="f2m1bz"
EA
＝ 企業全体の
「業務＋データ＋システム＋技術」
を整理して全体最適を目指す
```

## 4体系

```text id="m22nj6"
BA → Business
   → 業務

DA → Data
   → データ

AA → Application
   → アプリケーション

TA → Technology
   → 技術・インフラ
```

## 参照モデル

```text id="2pd6mw"
BRM → Business
    → 業務

DRM → Data
    → データ

SRM → Service
    → サービス・システム機能

TRM → Technical
    → 技術
```

---

# 最重要の対応関係

```text id="c3e76z"
【EAの4体系】       【参照モデル】

BA（業務）     ←→ BRM（業務）

DA（データ）   ←→ DRM（データ）

AA（アプリ）   ←→ SRM（サービス）

TA（技術）     ←→ TRM（技術）
```

## 一言で覚える

**BA = 何の仕事をする？
DA = 何のデータを使う？
AA = 何のシステムで実現する？
TA = 何の技術で動かす？**

そして、

**BRM・DRM・SRM・TRM = それぞれを整理するための共通的な参照モデル**

と理解すると分かりやすい。
