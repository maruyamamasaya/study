## CPUの基本

CPUは、プログラムの命令を読み込んで実行する装置。

基本的に、

```text id="yxdltr"
命令フェッチ
  ↓
命令解読（デコード）
  ↓
命令実行
```

を繰り返す。

---

# クロック周波数

CPUが動作するタイミングの基準。

単位は **Hz（ヘルツ）**。

```text id="1f3h50"
3GHz
= 1秒間に約30億クロック
```

基本的にはクロック周波数が高いほど、多くの処理を行える。

ただし、CPU性能はクロック周波数だけでは決まらない。

---

# CPI

**CPI（Cycles Per Instruction）**

1命令を実行するために必要な平均クロック数。

```text id="c5xd9g"
CPIが小さい
→ 少ないクロックで命令を処理
→ 高速
```

CPU実行時間の計算問題にも登場する。

---

# パイプライン

複数の命令を**流れ作業のように並行して処理する**方式。

```text id="8o5o0e"
命令A：取得 → 解読 → 実行
命令B：      取得 → 解読 → 実行
命令C：            取得 → 解読 → 実行
```

1つの命令が終わるのを待たず、次の命令の処理を開始する。

> **パイプライン = 命令処理を流れ作業化**

---

# 分岐予測

if文などの条件分岐で、

**次にどちらの命令を実行するかをCPUが予測する仕組み。**

```text id="ys1fvu"
        条件
       /    \
    処理A   処理B

CPU「たぶんAだろう」
```

予測が当たれば、待ち時間を減らせる。

> **分岐予測 = 次にどこへ進むか予測**

---

# 投機実行

分岐予測などの結果を使って、

**結果が確定する前に、予測した命令を先に実行する。**

```text id="d2oc4w"
分岐予測
  ↓
「Aだろう」
  ↓
Aを先に実行
  ↓
正解 → そのまま利用
失敗 → 結果を破棄
```

> **投機実行 = 予測した処理を先にやっておく**

---

# スーパースカラ

CPU内部に複数の実行ユニットを用意して、

**複数の命令を同時に実行する方式。**

```text id="dthp1q"
命令A → 演算器1
命令B → 演算器2
命令C → 演算器3
```

> **スーパースカラ = 複数命令を同時実行**

---

# マルチコア

1つのCPUの中に複数の**CPUコア**を搭載する。

```text id="1b5ejb"
CPU
├─ Core 1
├─ Core 2
├─ Core 3
└─ Core 4
```

複数の処理を並列に実行できる。

> **マルチコア = CPUそのものを複数搭載するイメージ**

---

# SIMD

**Single Instruction Multiple Data**

1つの命令で、複数のデータをまとめて処理する。

```text id="wqthdt"
        同じ命令
           ↓
    ┌──────┼──────┐
    ↓      ↓      ↓
データA データB データC
```

画像処理や数値計算などに向いている。

> **SIMD = 1命令で複数データ**

---

# RISC

**Reduced Instruction Set Computer**

単純な命令を中心に構成するCPU設計。

* 命令が比較的単純
* 命令形式を単純化
* パイプライン処理に向いている

> **RISC = 少数・単純な命令**

---

# CISC

**Complex Instruction Set Computer**

複雑で高機能な命令を持つCPU設計。

> **CISC = 複雑な命令を持つ**

### RISCとの比較

```text id="7m2eww"
RISC
→ 単純な命令

CISC
→ 複雑な命令
```

---

# VLIW

**Very Long Instruction Word**

複数の命令を1つの長い命令としてまとめ、
複数の演算器で並列実行する方式。

```text id="v5jiyb"
長い命令
├→ 演算1
├→ 演算2
└→ 演算3
```

コンパイラ側で、並列実行できる命令を判断する。

> **VLIW = 複数命令を長い1命令にまとめる**

---

# キャッシュメモリ

CPUと主記憶の速度差を埋めるための**高速なメモリ**。

```text id="a20zdg"
CPU
 ↓
L1キャッシュ
 ↓
L2キャッシュ
 ↓
L3キャッシュ
 ↓
主記憶
```

一般的にCPUに近いほど、

**高速・小容量**。

> **キャッシュ = よく使うデータをCPUの近くに置く**

---

# レジスタ

CPU内部にある**非常に高速な記憶領域**。

演算途中の値や命令などを保持する。

```text id="xcy7k8"
CPU
├─ レジスタ
├─ 演算器
└─ 制御装置
```

キャッシュよりさらにCPU内部の処理に直接使われる。

---

# メモリインターリーブ

主記憶を複数のメモリバンクに分割し、
並行してアクセスすることで高速化する。

```text id="m92khu"
主記憶
├→ Bank 0
├→ Bank 1
├→ Bank 2
└→ Bank 3
```

> **メモリインターリーブ = 主記憶を複数に分けて高速化**

---

# DMA

**DMA（Direct Memory Access）**

CPUを介さずに、入出力装置と主記憶の間で直接データを転送する仕組み。

```text id="9ryhmk"
通常

I/O → CPU → メモリ


DMA

I/O ─────→ メモリ
     直接
```

CPUの負担を減らせる。

> **DMA = CPUを介さず直接メモリ転送**

---

# GPU

**GPU（Graphics Processing Unit）**

大量の単純な計算を並列処理することが得意なプロセッサ。

画像処理だけでなく、

* AI
* 機械学習
* 科学技術計算

などにも利用される。

```text id="q8w63u"
CPU
→ 複雑な処理を幅広く処理

GPU
→ 大量の計算を並列処理
```

# 特に混同しやすいもの

```text id="i4mmyr"
パイプライン
→ 命令処理を流れ作業にする

スーパースカラ
→ 複数の命令を同時に実行する

マルチコア
→ CPUコア自体を複数搭載する
```

```text id="cq0awx"
分岐予測
→ どちらへ進むか予測する

投機実行
→ 予測した方を先に実行する
```

## 超短縮版

```text id="1b7nka"
パイプライン → 流れ作業
スーパースカラ → 同時実行
マルチコア → コア複数
投機実行 → 先回り
分岐予測 → 行き先予測
RISC → 単純命令
CISC → 複雑命令
SIMD → 1命令・複数データ
DMA → CPUを通さない
キャッシュ → CPUの近くに保存
```
