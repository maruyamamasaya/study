## ブロードキャストストーム

**ブロードキャストフレームがネットワーク内で大量に流れ続け、通信できなくなる現象。**

特に、スイッチ間にループがある場合に発生しやすい。

```text id="wph7us"
      ┌── Switch A ──┐
      │              │
      └── Switch B ──┘
            ↑
          ループ
```

ブロードキャストはスイッチによって転送されるため、

```text id="ogt3gn"
ブロードキャスト
   ↓
Switch A
   ↓
Switch B
   ↓
Switch A
   ↓
Switch B
   ↓
・・・
```

のようにループすると、大量のフレームがネットワークを占有する。

### 主な原因

* スイッチ間のループ
* ネットワーク構成ミス
* STPが正しく動作していない

### 対策

**STP（Spanning Tree Protocol）**などを利用して、ループする経路を論理的に遮断する。

> **ブロードキャストストーム = ブロードキャストが大量増殖**

---

# 輻輳（ふくそう）

ネットワークに処理能力を超える通信が集中し、**混雑している状態**。

英語では **Congestion（コンジェスション）**。

```text id="3sxt5j"
通信
通信
通信
通信
通信
 ↓↓↓↓↓

[ルータ]

処理しきれない
 ↓
遅延・パケット損失
```

### 発生すると

* 通信速度が低下する
* 遅延が増加する
* パケットが破棄される
* 再送が増える
* さらにネットワークが混雑する場合がある

> **輻輳 = 通信量が多すぎて道路渋滞**

---

# ブロードキャストストームと輻輳の違い

| 項目   | ブロードキャストストーム    | 輻輳           |
| ---- | --------------- | ------------ |
| 状態   | ブロードキャストが大量に流れる | 通信が集中して混雑    |
| 主な原因 | L2ループなど         | 通信量が処理能力を超える |
| 主な対象 | LAN・スイッチ        | ネットワーク全般     |
| 結果   | ネットワークを圧迫       | 遅延・パケット損失    |
| 関連技術 | STP             | 輻輳制御         |

---

# 関係性

ブロードキャストストームが発生すると大量の通信が発生するため、**結果としてネットワークの輻輳を引き起こすこともある**。

```text id="ggdmr6"
L2ループ
   ↓
ブロードキャストが増殖
   ↓
ブロードキャストストーム
   ↓
帯域を大量消費
   ↓
輻輳・通信障害
```

つまり、

> **ブロードキャストストームは「原因・現象が具体的」**
>
> **輻輳は「ネットワークが混雑している状態」**

と考えると分かりやすい。

---

# STP

**STP（Spanning Tree Protocol）**は、スイッチ間のループを防止するプロトコル。

冗長な経路が存在する場合、一部の経路を論理的にブロックする。

```text id="y9kck3"
Switch A
  │  ＼
  │    ＼
  │      × ← ブロック
  │        ＼
Switch B ── Switch C
```

障害が発生した場合は、ブロックしていた経路を利用できる。

### 覚え方

> **STP = L2ループを防ぐ**

---

# 試験用まとめ

```text id="kkmjy6"
ブロードキャストストーム
→ ブロードキャストが大量増殖
→ L2ループが代表的な原因
→ STPでループ防止

輻輳
→ 通信量が処理能力を超える
→ ネットワークの「渋滞」
→ 遅延・パケット損失が発生
```

## 一言で覚える

**ブロードキャストストーム
＝ 同じチラシがLAN内を大量に回り続ける**

**輻輳
＝ 道路に車が集まりすぎて渋滞する**
