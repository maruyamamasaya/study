Web開発では、まず以下のセキュリティ用語を理解しておくことが重要です。

|用語|一言でいうと|何を守る？|
|---|---|---|
|**XSS**|悪意あるJavaScriptをページ上で実行させる攻撃|ブラウザ・Cookie・画面|
|**CSRF**|ログイン中のユーザーに勝手な操作をさせる攻撃|更新・送信処理|
|**CORS**|どのサイトからAPIを呼んでよいかをブラウザで制御する仕組み|APIへのブラウザ経由アクセス|
|**Cookie**|ブラウザに保存され、サーバーへ送られる小さなデータ|ログイン状態など|
|**認証**|「あなたは誰？」を確認する仕組み|本人確認|
|**認可**|「あなたは何をしてよい？」を確認する仕組み|権限制御|
|**HTTPS**|ブラウザとサーバー間の通信を暗号化する仕組み|通信内容|

## それぞれのイメージ

```text
HTTPS
→ 通信を盗み見されにくくする

認証
→ 田中さん本人ですか？

認可
→ 田中さんは管理画面を使えますか？

Cookie
→ 田中さんがログイン済みだと覚えておく

XSS
→ Webページに悪いJavaScriptを仕込まれる

CSRF
→ ログイン状態を悪用して勝手に操作される

CORS
→ 別のWebサイトからAPIを呼べるか制御する
```

## Webアプリ全体で見ると

```text
ユーザー
   │
   │ HTTPS
   ▼
ブラウザ
   │
   ├── XSS対策
   ├── Cookie
   └── CORS
   │
   ▼
API / サーバー
   │
   ├── 認証
   │   └── 誰なのか？
   │
   ├── 認可
   │   └── 何をしてよいのか？
   │
   └── CSRF対策
   │
   ▼
データベース
```

## 特に覚えておきたいポイント

### XSS

**悪意あるJavaScriptをWebページ上で実行させる攻撃。**

```text
攻撃者
↓
悪意あるJavaScriptを仕込む
↓
ユーザーのブラウザで実行
↓
Cookieなどを狙われる可能性
```

---

### CSRF

**ログイン済みの状態を悪用して、ユーザーが意図していない操作を実行させる攻撃。**

```text
ユーザー
↓
サービスにログイン済み
↓
悪意あるサイトを開く
↓
勝手にリクエスト
↓
変更・購入などが実行される
```

---

### CORS

**どのWebサイトからAPIへアクセスしてよいかを、ブラウザ側で制御する仕組み。**

```text
my-site.com
↓
API
↓
許可


evil-site.com
↓
API
↓
ブラウザがブロック
```

> CORSは認証・認可の代わりにはならない。

---

### Cookie

**ブラウザに保存され、必要に応じてサーバーへ送られる小さなデータ。**

主に、

```text
ログイン状態

Session ID

ユーザー設定
```

などの管理に利用されます。

---

### 認証

**「あなたは誰ですか？」を確認する仕組み。**

```text
メールアドレス
+
パスワード
↓
本人確認
↓
ログイン
```

---

### 認可

**「あなたは何をしてよいですか？」を確認する仕組み。**

```text
一般ユーザー
↓
自分の情報だけ閲覧可能

管理者
↓
全ユーザーを管理可能
```

つまり、

```text
認証
→ 誰なのか？

認可
→ 何をしてよいのか？
```

という違いです。

---

### HTTPS

**ブラウザとサーバーの通信を暗号化する仕組み。**

```text
ブラウザ

   ↓

HTTPS
🔒 暗号化

   ↓

サーバー
```

ログイン情報や個人情報などを、通信途中で盗み見・改ざんされにくくします。

---

# まとめ

```text
HTTPS
→ 通信を守る

Cookie
→ ログイン状態などを保持する

認証
→ 誰なのか確認する

認可
→ 何をしてよいか確認する

XSS
→ 悪いJavaScriptを実行させる攻撃

CSRF
→ ログイン状態を悪用する攻撃

CORS
→ 別サイトからのAPIアクセスをブラウザで制御する
```

Webセキュリティでは、これらを単独ではなく、

```text
HTTPS
   ↓
安全に通信

認証
   ↓
本人確認

Cookie / Session
   ↓
ログイン状態を維持

認可
   ↓
権限を確認

XSS / CSRF対策
   ↓
攻撃を防ぐ

CORS
   ↓
ブラウザからのAPIアクセスを制御
```

というように、**複数の仕組みを組み合わせてWebアプリを守る**ことが重要です。
