React系では Component / Props / State / Hooks、設計系ではアンチパターンや Prop Drilling、Web全般では CSR / SSR / SSG などが繰り返し登場しています。

まずはこのあたりがおすすめです。

| 用語                                    | 超ざっくり意味                    | よく出る場面                  |
| ------------------------------------- | -------------------------- | ----------------------- |
| [[用語解説/アンチパターン（Anti-pattern）とは？\|アンチパターン]] | やりがちだけど避けたい設計・実装           | 設計・レビュー                 |
| コンポーネント                               | UIを部品に分けたもの                | React / Vue             |
| Props                                 | 親→子へ渡すデータ                  | React                   |
| State                                 | 画面が持っている「状態」               | React / Vue             |
| Hooks                                 | Reactの便利な機能群               | React                   |
| [[用語解説/副作用]]                               | 描画以外の処理。API通信など            | `useEffect`             |
| レンダリング                                | 画面を作って表示すること               | React / Next.js         |
| 再レンダリング                               | State変更などで画面を再計算すること       | React                   |
| DOM                                   | JavaScriptから操作できるWebページの構造 | JavaScript              |
| SPA                                   | ページ全体を読み直さず画面遷移するWebアプリ    | React / Vue             |
| CSR                                   | ブラウザ側で画面を生成                | React / SPA             |
| SSR                                   | サーバー側でHTMLを生成              | Next.js                 |
| SSG                                   | ビルド時にHTMLを生成               | Next.js                 |
| ルーティング                                | URLと画面を対応させる仕組み            | React Router / Next.js  |
| 状態管理                                  | アプリ内のデータ・状態を管理すること         | Redux / Pinia / Zustand |
| Prop Drilling                         | Propsを何階層もバケツリレーする状態       | React設計                 |
| グローバルState                            | アプリ全体で共有するState            | Redux / Context等        |
| ライフサイクル                               | 生成→表示→更新→破棄という流れ           | React / Vue             |
| マウント                                  | コンポーネントが画面に登場すること          | React                   |
| アンマウント                                | コンポーネントが画面から消えること          | React                   |
| イベントハンドラ                              | クリックなどが起きた時の処理             | JavaScript / React      |

| バンドル                                  | JSなど複数ファイルをまとめる処理          | Vite / webpack          |
| ビルド                                   | ソースコードを本番用に変換              | npm / Next.js           |
| Lint                                  | コードの問題を自動チェック              | ESLint                  |

| 技術的負債                                 | 後回しにした問題が将来のコストになること       | 設計・保守                   |
| 密結合                                   | 部品同士が依存しすぎている状態            | 設計                      |
| 疎結合                                   | 部品同士の依存を小さくした状態            | 設計                      |
| 責務                                    | 「この部品は何を担当するか」             | 設計                      |
| **関心の分離**                             | 役割ごとにコードを分離する考え方           | 設計                      |

特にReactの記事では、**Component → Props → State → Hooks → 再レンダリング → useEffect → 状態管理**あたりが一つのセットです。Qiitaでも `useState` は状態管理、`useEffect` はAPI通信などの副作用を扱うものとして頻繁に説明されています。

そしてNext.jsまで行くと、

**SPA → CSR → SSR → SSG → ISR → Server Component → Client Component**

という用語が増えてきます。CSR/SSR/SSGはフロントエンドのレンダリング方式を理解する基本用語として扱われています。
