## Linuxとは

Linuxは、WindowsやmacOSと同じ**OS（オペレーティングシステム）**の一つです。

OSは、コンピュータのハードウェアとアプリケーションの間に入り、コンピュータ全体を管理する役割を持っています。

代表的なOSには、次のようなものがあります。

- Windows
    
- macOS
    
- Linux
    

普段使用するパソコンではWindowsやmacOSを目にすることが多いですが、**Webサーバーやクラウド環境ではLinuxが非常によく利用されています。**

---

## なぜインフラエンジニアにLinuxが必要なのか

インフラエンジニアは、サーバーの構築や設定、監視、障害対応などを行います。

そのサーバーのOSとしてLinuxが使われていることが多いため、Linuxの基本的な操作や仕組みを理解することが重要になります。

例えば、Webサービスで問題が発生した場合には、

- サーバーが正常に動いているか
    
- アプリケーションが起動しているか
    
- CPUやメモリを使いすぎていないか
    
- ディスク容量が不足していないか
    
- エラーログが出ていないか
    
- ネットワーク通信が正常か
    

といったことをLinux上で確認します。

そのためLinuxは、**サーバーの状態を確認し、設定し、問題を調査するための基本技術**といえます。

---

## Linuxはコマンドで操作する

Linuxサーバーでは、WindowsやmacOSのようにマウスで画面を操作するのではなく、**コマンドを入力して操作することが多い**です。

例えば、現在のディレクトリにあるファイルを確認する場合は、次のように入力します。

```bash
ls
```

ディレクトリを移動する場合は、

```bash
cd /var/log
```

ファイルの内容を確認する場合は、

```bash
cat example.log
```

といったコマンドを使用します。

最初は難しく感じますが、実際の業務で頻繁に使うコマンドはある程度決まっています。

---

## Linuxで重要な考え方

Linuxを勉強するときは、コマンドを暗記するだけではなく、Linuxがどのような仕組みで動いているのかを理解することが重要です。

特に次のような領域があります。

### 1. ファイル・ディレクトリ

Linuxでは、設定ファイル、ログ、アプリケーションなど、多くのものがファイルとして管理されています。

そのため、

- ファイルを見る
- ファイルを作る
- ファイルをコピーする
- ファイルを移動する
- ファイルを削除する    
- ディレクトリを移動する


といった基本操作が重要になります。

代表的なコマンドには次のようなものがあります。

```text
ls
cd
pwd
cp
mv
rm
cat
```

---

### 2. ユーザーと権限

Linuxでは、

「誰がこのファイルを操作できるのか」

という権限管理が重要です。

例えば、

```text
一般ユーザー → 閲覧のみ可能
管理者       → 編集可能
```

といった制御ができます。

代表的なものとして、

```text
root
sudo
chmod
chown
```

などがあります。

サーバーを安全に運用するために重要な仕組みです。

---

### 3. プロセス

Linux上で動いているプログラムのことを**プロセス**と呼びます。

例えば、

```text
Linux
├── nginx
├── Node.js
├── MySQL
└── SSH
```

のように、Linux上では複数のプログラムが同時に動いています。

「Webサイトにつながらない」

という問題が発生した場合、

「nginxのプロセスは動いているか？」

といった確認を行います。

代表的なコマンドには、

```text
ps
top
kill
```

などがあります。

---

### 4. サービス

Webサーバーやデータベースなど、サーバー上で継続的に動かすプログラムは**サービス**として管理されることがあります。

例えばnginxを起動する場合、

```bash
sudo systemctl start nginx
```

状態を確認する場合、

```bash
sudo systemctl status nginx
```

といった操作を行います。

---

### 5. ログ

サーバーで何か問題が発生したときに非常に重要なのが**ログ**です。

ログには、

- いつアクセスされたか
    
- どのような処理が行われたか
    
- どのようなエラーが発生したか
    

などの情報が記録されています。

例えばWebサイトでエラーが発生した場合、

```text
ユーザー
   ↓
Webサイトでエラー
   ↓
サーバーにログイン
   ↓
ログを確認
   ↓
エラー原因を調査
```

という流れで調査します。

インフラエンジニアにとって、ログを確認して原因を調べる能力は非常に重要です。

---

### 6. CPU・メモリ・ディスク

サーバーもコンピュータなので、

- CPU
    
- メモリ
    
- ディスク
    

といったリソースがあります。

例えばディスク容量が100%になると、ログやデータを書き込めなくなり、システムに問題が発生することがあります。

そのため、

```bash
df -h
```

でディスク容量を確認したり、

```bash
top
```

でCPUやメモリの利用状況を確認したりします。

---

### 7. ネットワーク

Linuxサーバーは、他のサーバーやインターネットと通信します。

そのため、

- IPアドレス
    
- ポート
    
- DNS
    
- HTTP / HTTPS
    
- TCP/IP
    

といったネットワークの知識も必要になります。

例えば、

```text
ブラウザ
   ↓
HTTPS（443番ポート）
   ↓
Linuxサーバー
   ↓
nginx
   ↓
アプリケーション
```

というように通信が行われます。

Linuxとネットワークは非常に関係が深いため、セットで勉強すると理解しやすくなります。

---

### 8. SSH

実際のサーバーは、自分の目の前にあるとは限りません。

例えばAWS上にLinuxサーバーがある場合、自分のパソコンからネットワーク経由で接続します。

そこで使われる代表的な仕組みが**SSH**です。

```text
自分のPC
   ↓
  SSH
   ↓
インターネット
   ↓
Linuxサーバー
```

SSHで接続すると、自分のPCからLinuxサーバーにコマンドを入力できるようになります。

---

## Linuxにはいくつか種類がある

Linuxには「ディストリビューション」と呼ばれるいくつかの種類があります。

代表的なものには、

- Ubuntu
    
- Debian
    
- Red Hat Enterprise Linux
    
- Rocky Linux
    
- Amazon Linux
    

などがあります。

種類によってパッケージ管理などに違いがありますが、ファイル、プロセス、ユーザー、権限などの基本的な考え方は共通しています。

そのため、最初からすべて覚える必要はありません。

まずはUbuntuやAmazon Linuxなど、一つのLinux環境を実際に触ってみることが重要です。

---

## インフラエンジニアとしてLinuxで覚えたいこと

最初は次の順番で勉強すると理解しやすいです。

```text
Linuxとは何か
    ↓
ファイル・ディレクトリ
    ↓
ユーザー・権限
    ↓
プロセス・サービス
    ↓
CPU・メモリ・ディスク
    ↓
ログ
    ↓
SSH
    ↓
ネットワーク
```

すべてのLinuxコマンドを覚える必要はありません。

重要なのは、

**「サーバーで何か問題が起きたとき、どこを確認すればいいのか」**

を理解することです。

---

## まとめ

Linuxは、Webサーバーやクラウド環境で広く利用されているOSです。

インフラエンジニアはLinuxを使って、

- サーバーを操作する
    
- ファイルを管理する
    
- ユーザーや権限を管理する
    
- プロセスやサービスを管理する
    
- CPUやメモリを確認する
    
- ログから障害原因を調査する
    
- ネットワークの状態を確認する
    

といった作業を行います。

そのためLinuxは、インフラエンジニアにとって**すべてを暗記するものではなく、「サーバーの中で何が起きているのかを理解するための基礎」**として身につけることが重要です。
