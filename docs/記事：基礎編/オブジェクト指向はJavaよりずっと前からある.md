Javaがオブジェクト指向を作ったわけではなく、**既にあったオブジェクト指向という考え方を採用した言語の一つ**です。

### 時系列で見ると

```
1960年代
│
├─ Simula
│   └─ クラス・オブジェクト・継承などが登場
│
↓
1970年代
│
├─ Smalltalk
│   └─ オブジェクト指向を本格的に発展
│
↓
1980年代
│
├─ C++
│   └─ C言語 + オブジェクト指向
│
↓
1990年代
│
├─ Java（1995年）
│   └─ オブジェクト指向を強く採用
│
↓
2000年代〜
│
├─ C#
├─ Ruby
├─ Python
├─ JavaScript
└─ など
```

特に重要なのが **Simula と Smalltalk** です。

Simulaは1960年代に登場し、現在のオブジェクト指向につながる「クラス」「オブジェクト」「継承」といった仕組みを持っていました。

Smalltalkは1970年代に、

> 「プログラムをオブジェクト同士のやり取りとして考える」

という考え方をかなり強く押し進めました。

### Javaは何をしたのか？

Javaは1995年登場なので、かなり後です。

Javaは、

```
それまでのオブジェクト指向
        ↓
class
object
継承
カプセル化
ポリモーフィズム
        ↓
Javaとして扱いやすく整理
```

という位置づけで考えるといいです。

つまり、

**オブジェクト指向 = 設計・プログラミングの考え方**

**Java = オブジェクト指向を実現できるプログラミング言語**

です。

### だからJava以外でも使う

例えばC++でも、

```
class User {
};
```

Pythonでも、

```
class User:
    pass
```

TypeScriptでも、

```
class User {
}
```

と書けます。

言語は違いますが、

```
User
├─ name
├─ age
│
├─ login()
└─ logout()
```

のように、**データと処理を「User」というオブジェクトとして考える思想は共通**しています。

そして面白いところが、Reactなどの最近の開発では「何でもクラス・継承にする」という昔ながらのオブジェクト指向から少し離れて、**関数型プログラミングやコンポジション（組み合わせ）**もかなり使われます。

なので歴史的には、

**手続き型 → オブジェクト指向 → 関数型・コンポジションも組み合わせる現代的な設計**

という流れまで見ると、Java・React・TypeScriptの違いも理解しやすくなります。
