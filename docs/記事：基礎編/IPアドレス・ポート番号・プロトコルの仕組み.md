1. 全体像

ネットワーク通信を理解するときは、まず次の3つを分けて考えると分かりやすい。

IPアドレス

    ↓

「どのコンピュータ？」

  

ポート番号

    ↓

「そのコンピュータのどのサービス？」

  

プロトコル

    ↓

「どんなルールで通信する？」

たとえるなら、

IPアドレス ＝ 建物の住所

ポート番号 ＝ 部屋・受付窓口

プロトコル ＝ 会話するときのルール

というイメージ。

  

2. IPアドレスとは

IPアドレスは、ネットワーク上で

「どのコンピュータに通信するのか」

を指定するための住所。

例えば、

203.0.113.10

というIPアドレスのサーバーがあったとする。

ただし、1台のサーバーではWebだけでなく、SSH・データベース・APIなど、複数のサービスを動かすことができる。

そこで必要になるのがポート番号。

  

3. ポート番号とは

ポート番号は、

「そのコンピュータのどのサービスに接続するのか」

を指定する番号。

例えば1台のサーバーで、

203.0.113.10

  

├─ :22    → SSH

├─ :80    → HTTP

├─ :443   → HTTPS

├─ :3000  → Next.js

├─ :3306  → MySQL

└─ :5432  → PostgreSQL

という構成にできる。

つまり、

203.0.113.10:443

と

203.0.113.10:22

は、

同じコンピュータに接続しているが、接続先のサービスが違う。

  

4. よく使われるポート番号

代表的なものは次のとおり。

|   |   |   |
|---|---|---|
|ポート|プロトコル・サービス|主な用途|
|22|SSH|サーバーへのリモート接続|
|80|HTTP|Webサイト|
|443|HTTPS|暗号化されたWebサイト|
|3000|HTTPなど|Next.jsなどの開発サーバー|
|3306|MySQL|MySQLデータベース|
|5432|PostgreSQL|PostgreSQLデータベース|
|587|SMTP|メール送信|
|993|IMAP|メール受信|

  

5. ブラウザでWebサイトを見る場合

例えば、

https://example.com

にアクセスした場合、

example.com

    ↓

DNSでIPアドレスを調べる

    ↓

203.0.113.10

    ↓

203.0.113.10:443

という流れになる。

https:// の標準ポートが443番なので、通常はポート番号を書く必要がない。

つまり、

https://example.com

は基本的に、

https://example.com:443

という意味。

HTTPの場合も、

http://example.com

は基本的に、

http://example.com:80

となる。

  

6. ポート番号は自分で指定できる

Webサーバーだから必ず80・443を使わなければならないわけではない。

例えばNext.jsでは、

http://localhost:3000

がよく使われる。

これは、

localhost

    ↓

自分のPC

  

:3000

    ↓

3000番ポートで動いているNext.js

という意味。

ブラウザから、

http://203.0.113.10:3000

と指定することもできる。

この場合ブラウザは、

「203.0.113.10の3000番ポートにHTTPで接続する」

という動きをする。

  

7. 同じサーバーで全く違うアプリも動かせる

1台のサーバーで複数のアプリケーションを同時に動かすこともできる。

例えば、

サーバー

203.0.113.10

  

├─ :3000 → Next.js 予約サイト

├─ :3001 → 管理画面

├─ :5000 → Python Flask API

├─ :8080 → Javaアプリ

├─ :3306 → MySQL

└─ :22   → SSH

という構成も可能。

言語が違っていても問題ない。

Next.js / Node.js

Python / Flask

Java / Spring Boot

PHP / Laravel

MySQL

などを同じサーバー上で動かすこともできる。

  

8. 同じポートを2つのアプリで使える？

基本的には使えない。

例えば、

Next.js → :3000

Flask   → :5000

なら問題ない。

一方、

Next.js → :3000

Flask   → :3000

のように、

同じIPアドレスの同じポートを2つのアプリが同時に待ち受けることは基本的にできない。

後から起動しようとすると、

Port 3000 is already in use

などのエラーになる。

  

9. ブラウザから22番ポートにアクセスしたら？

例えば、

http://203.0.113.10:22

とブラウザに入力したとする。

22番ポートは通常SSHが使っている。

この場合、

ブラウザ

   │

   │ HTTPで通信しようとする

   ↓

203.0.113.10:22

   ↓

SSHサーバー

となる。

ブラウザはHTTPで話そうとしているのに、相手はSSH。

つまり、

ブラウザ

「HTTPで話そう！」

  

SSH

「ここはSSHなんだけど……」

という状態。

そのため、正常なWebページは表示されない。

また、ブラウザによっては安全上の理由から特定ポートへのアクセス自体を禁止している場合もある。

  

10. プロトコルも重要

通信では、

IPアドレス + ポート番号

だけでなく、

プロトコル

も重要。

例えば、

203.0.113.10:22

に接続するなら、

SSHクライアント

    │

    │ SSH

    ↓

203.0.113.10:22

    ↓

SSHサーバー

となる。

Webなら、

ブラウザ

    │

    │ HTTPS

    ↓

203.0.113.10:443

    ↓

Webサーバー

となる。

つまり、

ポートが合っていても、プロトコルが合っていなければ正常に通信できない。

  

11. メールも同じ仕組み

メールも基本的には、

IPアドレス

+

ポート番号

+

プロトコル

で通信する。

例えば、

SMTP :587

    ↓

メール送信

  

IMAP :993

    ↓

メール受信

という使い分けがある。

  

12. ブラウザでGmailを見る場合は？

ここは少し重要。

ブラウザでWebメールを見る場合は、

ブラウザ

   │

   │ HTTPS :443

   ↓

Webメール

なので、普通のWebサイトと同じ443番を利用する。

一方、メールアプリなどがメールサーバーと通信する場合は、

メールアプリ

   │

   ├─ SMTP :587 → メール送信

   │

   └─ IMAP :993 → メール受信

などになる。

つまり、

「メールだから587や993」ではない。

どのようにメールサービスを利用しているかによって違う。

  

13. 本番Webサイトでは443にまとめることが多い

実際のWebシステムでは、

https://example.com:3000

のようなURLをユーザーに使わせることはあまりない。

通常は、

https://example.com

だけでアクセスできるようにする。

そのために、nginxやロードバランサーなどを利用する。

例えば、

ブラウザ

   │

   │ HTTPS :443

   ↓

┌──────────────┐

│ nginx / ALB   │

└──────┬───────┘

       │

       │ HTTP :3000

       ↓

┌──────────────┐

│ Next.js      │

│ :3000        │

└──────────────┘

外部ユーザーは、

https://example.com

にアクセスしている。

しかし内部では、

443

 ↓

nginx / ALB

 ↓

3000

 ↓

Next.js

と通信している。

このような仕組みをリバースプロキシと呼ぶ。

  

14. 複数のアプリをURLで振り分けることもできる

例えば、

https://shop.example.com

        ↓

Next.js :3000

  

https://admin.example.com

        ↓

管理画面 :3001

  

https://api.example.com

        ↓

Flask :5000

という構成もできる。

外部から見るとすべて、

HTTPS :443

だが、

サーバー内部では、

:3000

:3001

:5000

などに振り分けられている。

  

15. WebサーバーからDBサーバーへの通信も同じ

例えばWebシステムなら、

ユーザー

   ↓

ブラウザ

   ↓ HTTPS :443

Webサーバー

   ↓ MySQL :3306

DBサーバー

という通信になることがある。

AWSなら例えば、

インターネット

      ↓

HTTPS :443

      ↓

     ALB

      ↓

HTTP :3000

      ↓

     EC2

   Next.js

      ↓

MySQL :3306

      ↓

     RDS

という構成が考えられる。

つまり、ポートはブラウザからWebサイトにアクセスするときだけ使われるものではない。

サーバー同士の通信でも使われる。

  

16. 「入口は同じ？」という考え方

ネットワーク的な基本の考え方はかなり共通している。

接続先IP

    ↓

どのコンピュータ？

  

ポート

    ↓

どのサービス？

  

プロトコル

    ↓

どうやって会話する？

例えば、

203.0.113.10:443

→ HTTPS

  

203.0.113.10:22

→ SSH

  

203.0.113.10:3306

→ MySQL

というように、同じサーバーでも入口が違う。

  

17. ポート番号を「部屋番号」と考える

初心者のうちは、次のイメージが分かりやすい。

サーバーという建物

IP: 203.0.113.10

  

┌────────────────────────┐

│                        │

│  22号室   → SSH        │

│                        │

│  80号室   → HTTP       │

│                        │

│  443号室  → HTTPS      │

│                        │

│  3000号室 → Next.js    │

│                        │

│  3306号室 → MySQL      │

│                        │

└────────────────────────┘

IPアドレスで建物まで行き、

ポート番号で目的の部屋を指定する。

さらに、その部屋のサービスが理解できるプロトコルで通信する。

  

18. まとめ

覚えておきたいポイントは次のとおり。

|   |   |
|---|---|
|用語|意味|
|IPアドレス|どのコンピュータか|
|ポート番号|そのコンピュータのどのサービスか|
|プロトコル|どのようなルールで通信するか|
|HTTP|Web通信|
|HTTPS|暗号化されたWeb通信|
|SSH|サーバーへのリモート接続|
|SMTP|メール送信|
|IMAP|メール受信|
|リバースプロキシ|受け取った通信を内部の別サービスへ転送する仕組み|

特に重要なのは、

IPアドレス

「どのサーバー？」

  

        ＋

  

ポート番号

「どのサービス？」

  

        ＋

  

プロトコル

「どうやって話す？」

という関係。

Webシステムでは、例えば、

ブラウザ

   ↓

HTTPS :443

   ↓

ALB / nginx

   ↓

HTTP :3000

   ↓

Next.js

   ↓

MySQL :3306

   ↓

データベース

のように、1回のWebアクセスの裏側でも複数のポート・プロトコルが使われている。

この考え方が分かると、Webサーバー・DBサーバー・AWS・ファイアウォール・セキュリティグループなどの理解にもつながってくる。
