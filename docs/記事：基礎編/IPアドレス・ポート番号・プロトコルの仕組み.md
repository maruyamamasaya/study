## 1. 全体像

ネットワーク通信を理解するときは、まず次の3つを分けて考えると分かりやすいです。

```text
IPアドレス
    ↓
「どのコンピュータ？」

ポート番号
    ↓
「そのコンピュータのどのサービス？」

プロトコル
    ↓
「どんなルールで通信する？」
```

たとえるなら、

```text
IPアドレス ＝ 建物の住所
ポート番号 ＝ 部屋・受付窓口
プロトコル ＝ 会話するときのルール
```

というイメージです。

---

## 2. IPアドレスとは

IPアドレスは、ネットワーク上で

> **「どのコンピュータに通信するのか」**

を指定するための住所です。

例えば、

```text
203.0.113.10
```

というIPアドレスのサーバーがあったとします。

ただし、1台のサーバーではWebだけでなく、SSH・データベース・APIなど、複数のサービスを動かすことができます。

そこで必要になるのが**ポート番号**です。

---

## 3. ポート番号とは

ポート番号は、

> **「そのコンピュータのどのサービスに接続するのか」**

を指定する番号です。

例えば1台のサーバーで、

```text
203.0.113.10

├─ :22    → SSH
├─ :80    → HTTP
├─ :443   → HTTPS
├─ :3000  → Next.js
├─ :3306  → MySQL
└─ :5432  → PostgreSQL
```

という構成にできます。

つまり、

```text
203.0.113.10:443
```

と、

```text
203.0.113.10:22
```

は、同じコンピュータに接続していますが、**接続先のサービスが違う**ということです。

---

## 4. よく使われるポート番号

代表的なものは次のとおりです。

|ポート|プロトコル・サービス|主な用途|
|---|---|---|
|22|SSH|サーバーへのリモート接続|
|80|HTTP|Webサイト|
|443|HTTPS|暗号化されたWebサイト|
|3000|HTTPなど|Next.jsなどの開発サーバー|
|3306|MySQL|MySQLデータベース|
|5432|PostgreSQL|PostgreSQLデータベース|
|587|SMTP|メール送信|
|993|IMAP|メール受信|

---

## 5. ブラウザでWebサイトを見る場合

例えば、

```text
https://example.com
```

にアクセスした場合、

```text
example.com
    ↓
DNSでIPアドレスを調べる
    ↓
203.0.113.10
    ↓
203.0.113.10:443
```

という流れになります。

HTTPSの標準ポートは443番なので、通常はポート番号を書く必要がありません。

つまり、

```text
https://example.com
```

は基本的に、

```text
https://example.com:443
```

という意味です。

HTTPの場合も、

```text
http://example.com
```

は基本的に、

```text
http://example.com:80
```

となります。

---

## 6. ポート番号は自分で指定できる

Webサーバーだから必ず80番・443番を使わなければならないわけではありません。

例えばNext.jsでは、

```text
http://localhost:3000
```

がよく使われます。

これは、

```text
localhost
    ↓
自分のPC

:3000
    ↓
3000番ポートで動いているNext.js
```

という意味です。

ブラウザから、

```text
http://203.0.113.10:3000
```

と指定することもできます。

この場合ブラウザは、

> **「203.0.113.10の3000番ポートにHTTPで接続する」**

という動きをします。

---

## 7. 同じサーバーで全く違うアプリも動かせる

1台のサーバーで複数のアプリケーションを同時に動かすこともできます。

例えば、

```text
サーバー
203.0.113.10

├─ :3000 → Next.js 予約サイト
├─ :3001 → 管理画面
├─ :5000 → Python Flask API
├─ :8080 → Javaアプリ
├─ :3306 → MySQL
└─ :22   → SSH
```

という構成も可能です。

使っている言語が違っていても問題ありません。

例えば、

- Next.js / Node.js
    
- Python / Flask
    
- Java / Spring Boot
    
- PHP / Laravel
    
- MySQL
    

などを同じサーバー上で動かすこともできます。

---

## 8. 同じポートを2つのアプリで使える？

基本的には使えません。

例えば、

```text
Next.js → :3000
Flask   → :5000
```

なら問題ありません。

一方、

```text
Next.js → :3000
Flask   → :3000
```

のように、同じIPアドレス・同じポート番号で、2つのアプリが同時に待ち受けることは基本的にできません。

後から起動しようとすると、

```text
Port 3000 is already in use
```

などのエラーになります。

---

## 9. ブラウザから22番ポートにアクセスしたら？

例えば、

```text
http://203.0.113.10:22
```

とブラウザに入力したとします。

22番ポートは通常SSHが使っています。

この場合、

```text
ブラウザ
   │
   │ HTTPで通信しようとする
   ▼
203.0.113.10:22
   │
   ▼
SSHサーバー
```

となります。

ブラウザはHTTPで話そうとしているのに、相手はSSHです。

イメージとしては、

```text
ブラウザ
「HTTPで話そう！」

SSH
「ここはSSHなんだけど……」
```

という状態です。

そのため、正常なWebページは表示されません。

また、ブラウザによっては安全上の理由から、特定ポートへのアクセス自体を禁止している場合もあります。

---

## 10. プロトコルも重要

通信では、

```text
IPアドレス
+
ポート番号
```

だけでなく、**プロトコル**も重要です。

例えば、

```text
203.0.113.10:22
```

に接続するなら、

```text
SSHクライアント
    │
    │ SSH
    ▼
203.0.113.10:22
    │
    ▼
SSHサーバー
```

となります。

Webなら、

```text
ブラウザ
    │
    │ HTTPS
    ▼
203.0.113.10:443
    │
    ▼
Webサーバー
```

となります。

つまり、

> **ポート番号が合っていても、プロトコルが合っていなければ正常に通信できない**

ということです。

---

## 11. メールも同じ仕組み

メールも基本的には、

```text
IPアドレス
+
ポート番号
+
プロトコル
```

で通信します。

例えば、

```text
SMTP :587
    ↓
メール送信
```

```text
IMAP :993
    ↓
メール受信
```

という使い分けがあります。

---

## 12. ブラウザでGmailを見る場合は？

ブラウザでWebメールを見る場合は、

```text
ブラウザ
   │
   │ HTTPS :443
   ▼
Webメール
```

となるため、普通のWebサイトと同じ443番を利用します。

一方、メールアプリなどがメールサーバーと通信する場合は、

```text
メールアプリ
   │
   ├─ SMTP :587 → メール送信
   │
   └─ IMAP :993 → メール受信
```

などになります。

つまり、

> **「メールだから587番や993番を使う」とは限らない**

ということです。

どのような方法でメールサービスを利用しているかによって変わります。

---

## 13. 本番Webサイトでは443にまとめることが多い

実際のWebシステムでは、

```text
https://example.com:3000
```

のようなURLを一般ユーザーに使わせることはあまりありません。

通常は、

```text
https://example.com
```

だけでアクセスできるようにします。

そのために、nginxやロードバランサーなどを利用します。

例えば、

```text
ブラウザ
   │
   │ HTTPS :443
   ▼
┌──────────────┐
│ nginx / ALB  │
└──────┬───────┘
       │
       │ HTTP :3000
       ▼
┌──────────────┐
│ Next.js      │
│ :3000        │
└──────────────┘
```

外部ユーザーは、

```text
https://example.com
```

にアクセスしています。

しかし内部では、

```text
443
 ↓
nginx / ALB
 ↓
3000
 ↓
Next.js
```

と通信しています。

このように、外部から受け取った通信を内部の別サービスへ転送する仕組みを、**リバースプロキシ**と呼びます。

---

## 14. 複数のアプリをURLで振り分けることもできる

例えば、

```text
https://shop.example.com
        ↓
Next.js :3000
```

```text
https://admin.example.com
        ↓
管理画面 :3001
```

```text
https://api.example.com
        ↓
Flask :5000
```

という構成もできます。

外部から見るとすべて、

```text
HTTPS :443
```

ですが、内部では、

```text
:3000
:3001
:5000
```

などに振り分けられています。

---

## 15. WebサーバーからDBサーバーへの通信も同じ

例えばWebシステムなら、

```text
ユーザー
   ↓
ブラウザ
   ↓ HTTPS :443
Webサーバー
   ↓ MySQL :3306
DBサーバー
```

という通信になることがあります。

AWSなら例えば、

```text
Internet
    ↓
HTTPS :443
    ↓
   ALB
    ↓
HTTP :3000
    ↓
   EC2
 Next.js
    ↓
MySQL :3306
    ↓
   RDS
```

という構成が考えられます。

つまり、ポート番号はブラウザからWebサイトにアクセスするときだけ使われるものではありません。

**サーバー同士の通信でもポート番号が使われます。**

---

## 16. 「入口は同じ？」という考え方

ネットワーク通信の基本的な考え方は共通しています。

```text
接続先IP
    ↓
どのコンピュータ？

ポート
    ↓
どのサービス？

プロトコル
    ↓
どうやって会話する？
```

例えば、

```text
203.0.113.10:443
→ HTTPS

203.0.113.10:22
→ SSH

203.0.113.10:3306
→ MySQL
```

というように、同じサーバーでも入口が違います。

---

## 17. ポート番号を「部屋番号」と考える

初心者のうちは、次のイメージが分かりやすいです。

```text
サーバーという建物

IP: 203.0.113.10

┌────────────────────────┐
│                        │
│  22号室   → SSH        │
│                        │
│  80号室   → HTTP       │
│                        │
│  443号室  → HTTPS      │
│                        │
│  3000号室 → Next.js    │
│                        │
│  3306号室 → MySQL      │
│                        │
└────────────────────────┘
```

IPアドレスで建物まで行き、

ポート番号で目的の部屋を指定します。

さらに、その部屋のサービスが理解できる**プロトコル**で通信します。

---

## 18. まとめ

覚えておきたいポイントは次のとおりです。

|用語|意味|
|---|---|
|IPアドレス|どのコンピュータか|
|ポート番号|そのコンピュータのどのサービスか|
|プロトコル|どのようなルールで通信するか|
|HTTP|Web通信|
|HTTPS|暗号化されたWeb通信|
|SSH|サーバーへのリモート接続|
|SMTP|メール送信|
|IMAP|メール受信|
|リバースプロキシ|受け取った通信を内部の別サービスへ転送する仕組み|

特に重要なのは、

```text
IPアドレス
「どのサーバー？」
        ＋
ポート番号
「どのサービス？」
        ＋
プロトコル
「どうやって話す？」
```

という関係です。

Webシステムでは、例えば、

```text
ブラウザ
   ↓
HTTPS :443
   ↓
ALB / nginx
   ↓
HTTP :3000
   ↓
Next.js
   ↓
MySQL :3306
   ↓
データベース
```

のように、1回のWebアクセスの裏側でも複数のポート・プロトコルが使われています。

この考え方が分かると、Webサーバー・DBサーバー・AWS・Firewall・Security Groupなどの理解にもつながります。
