## 1. ネットワーク全体のイメージ

オンプレ環境では、PCやサーバーをスイッチ・ルーター・Firewallなどで接続してネットワークを構成します。

```text
PC / Server
     │
     ▼
┌─────────────┐
│ L2スイッチ   │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ L3スイッチ   │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Firewall    │
└──────┬──────┘
       │
       ▼
    Router
       │
       ▼
   Internet
```

それぞれ役割が異なります。

|機器・機能|主な役割|
|---|---|
|L2スイッチ|同じネットワーク内の通信|
|L3スイッチ|異なるネットワーク間の通信|
|Router|別ネットワークへの経路を決める|
|Firewall|通信を許可・拒否する|
|NAT|IPアドレスを変換する|

---

## 2. L2スイッチとは

L2スイッチは、主に**同じネットワーク内の機器を接続する装置**です。

例えば、

```text
PC-A
192.168.1.10
     │
     ▼
┌─────────────┐
│ L2スイッチ   │
└──────┬──────┘
       │
       ▼
PC-B
192.168.1.20
```

両方とも、

```text
192.168.1.0/24
```

という同じネットワークに所属しています。

L2スイッチは主に**MACアドレス**を見て通信を転送します。

イメージとしては、

```text
「このMACアドレスのPCは3番ポートにいる」
        ↓
「3番ポートへデータを送ろう」
```

という動きをします。

### L2スイッチのポイント

**同じネットワーク内の通信を担当する。**

---

## 3. L3スイッチとは

L3スイッチは、**異なるネットワーク同士を接続する装置**です。

例えば、

```text
192.168.1.0/24
      │
      ▼
  L2スイッチ
      │
      ▼
  L3スイッチ
      │
      ▼
  L2スイッチ
      │
      ▼
192.168.2.0/24
```

`192.168.1.0/24` と `192.168.2.0/24` は別ネットワークです。

L2スイッチだけでは、この2つのネットワーク間をルーティングできません。

そこでL3スイッチが、

```text
192.168.1.x
      ↓
192.168.2.x に行きたい
      ↓
192.168.2.0/24 側へ転送
```

という判断をします。

L3では主に**IPアドレス**を使います。

### L3スイッチのポイント

**異なるネットワーク間の通信を担当する。**

---

## 4. VLAN

実際の社内ネットワークでは、VLANを使ってネットワークを**論理的に分割**することがあります。

例えば、

```text
VLAN 10
社員PC
192.168.10.0/24

VLAN 20
サーバー
192.168.20.0/24

VLAN 30
管理端末
192.168.30.0/24
```

という構成です。

```text
              L2スイッチ
        ┌────────────────┐
PC ─────┤ VLAN 10        │
PC ─────┤ VLAN 10        │
Server ─┤ VLAN 20        │
Server ─┤ VLAN 20        │
管理PC ─┤ VLAN 30        │
        └───────┬────────┘
                │
                ▼
            L3スイッチ
```

L2スイッチがVLAN内の通信を担当し、L3スイッチが、

```text
VLAN 10
   ↓
VLAN 20
```

のような**VLAN間通信（Inter-VLAN Routing）**を担当します。

---

## 5. ルーティングとは

ルーティングは、

> **「この通信をどこへ送るか」を決める仕組み**

です。

例えばサーバーが、

```text
IPアドレス
192.168.1.100

サブネットマスク
255.255.255.0

デフォルトゲートウェイ
192.168.1.1
```

だったとします。

同じネットワークの、

```text
192.168.1.50
```

へ通信する場合は、同一ネットワーク内なので直接通信できます。

一方、

```text
8.8.8.8
```

のような外部IPへ通信する場合、

```text
8.8.8.8
   ↓
192.168.1.x ではない
   ↓
自分とは別ネットワーク
   ↓
デフォルトゲートウェイへ送る
   ↓
192.168.1.1
```

となります。

---

## 6. デフォルトルート

ルーターなどでは、

```text
0.0.0.0/0
```

というルートがよく登場します。

これは、

> **「個別のルートが見つからなかった通信はこちらへ送る」**

という意味です。

例えば、

```text
192.168.10.0/24 → 社内ネットワーク
192.168.20.0/24 → サーバーネットワーク
0.0.0.0/0       → Internet側
```

というルーティングテーブルなら、`8.8.8.8` への通信は、

```text
8.8.8.8
   ↓
0.0.0.0/0
   ↓
Internet側
```

へ送られます。

---

## 7. ルーティングとFirewallは別物

ここは非常に重要です。

### ルーティング

```text
どこへ送る？
```

を決めます。

### Firewall

```text
その通信を通していい？
```

を判断します。

つまり、

```text
Routing
   ↓
通信経路を決める

Firewall
   ↓
通信を許可・拒否する
```

という違いがあります。

例えば、

```text
Server
  │
  ▼
Router
  │
  ▼
Firewall
  │
  ▼
Internet
```

という経路が存在していても、Firewallが、

```text
Server → Internet
DENY
```

としていれば通信できません。

---

## 8. Firewallではポート単位でも制御できる

Firewallでは、次のような情報を使って通信を制御できます。

- 送信元IP
    
- 送信先IP
    
- プロトコル
    
- ポート番号
    

例えば、

```text
HTTPS  TCP 443 → 許可
HTTP   TCP 80  → 許可
SSH    TCP 22  → 拒否
```

といった設定ができます。

---

## 9. SSHとは

SSHは、Linuxサーバーなどを**遠隔操作するためによく使われる仕組み**です。

一般的には、

```text
TCP 22
```

を使用します。

例えば、

```text
管理PC
  │
  │ SSH : 22
  ▼
Linux Server
```

という通信です。

SSH接続すると、管理者が遠隔からサーバーのコマンドを実行できます。

そのため非常に便利ですが、同時に**重要な管理用の入口**でもあります。

---

## 10. SSHの22番ポートは基本的に世界中へ公開しない

Webサーバーの場合、

```text
443 HTTPS
```

は一般ユーザーがアクセスする必要があります。

そのため、

```text
Internet
   │
   │ TCP 443
   ▼
Web Server
```

のように公開します。

しかし、SSHは一般ユーザーが利用する必要がありません。

そのため、

```text
443 → Internetから許可
22  → Internet全体からは許可しない
```

という考え方が基本になります。

```text
Internet
   │
   ├── TCP 443 ──→ OK
   │
   └── TCP 22  ──→ NG
```

---

## 11. SSHを使う場合は接続元を限定する

管理者がSSHを使う必要がある場合、

```text
203.0.113.10
```

という管理拠点のグローバルIPだけ許可する、といった設定ができます。

```text
管理者
203.0.113.10
     │
     │ SSH : 22
     ▼
┌────────────────┐
│    Firewall    │
│                │
│ 管理者IP → OK  │
│ その他   → NG  │
└───────┬────────┘
        │
        ▼
    Linux Server
```

例えば、

```text
203.0.113.10 → TCP 22 → ALLOW
その他       → TCP 22 → DENY
```

とします。

これなら、世界中からSSHログインを試されるリスクを大幅に減らせます。

---

## 12. SSH自体にもセキュリティ対策をする

ネットワーク側だけでなく、SSH側でも対策します。

代表的な対策は次のとおりです。

- パスワード認証ではなく公開鍵認証を使用する
    
- rootでの直接ログインを禁止する
    
- 接続元IPを限定する
    
- 不要ならSSHを外部公開しない
    
- OpenSSHやOSをアップデートする
    
- SSHログを監視する
    
- 必要に応じてVPNや踏み台サーバーを使用する
    

特に、

```text
Internet
   │
   │ SSH : 22
   ▼
Server
```

と直接公開するより、

```text
管理PC
   │
   │ VPN
   ▼
VPN Gateway
   │
   ▼
社内ネットワーク
   │
   │ SSH
   ▼
Server
```

とする方が安全です。

SSHそのものをInternetへ直接公開しなくて済むためです。

## 13. AWSとの対応

オンプレの考え方は、AWSにもかなりそのまま当てはまります。

|オンプレ|AWSで近いもの|
|---|---|
|社内ネットワーク|VPC|
|VLAN / サブネット|Subnet|
|ルーティングテーブル|Route Table|
|Internet接続|Internet Gateway|
|NAT|NAT Gateway|
|Firewall|Security Group / NACL|
|物理・仮想サーバー|EC2|

例えばAWSなら、

```text
Internet
    │
    │ HTTPS : 443
    ▼
   ALB
    │
    ▼
   EC2
```

としつつ、

```text
Internet → EC2 : 22
拒否
```

という設計にできます。

EC2を管理する場合も、SSHをInternetへ公開するのではなく、**AWS Systems Manager Session Manager**などを利用する方法があります。

## 14. オンプレとAWSを並べて考える

### オンプレ

```text
PC / Server
     │
     ▼
L2 Switch
     │
     ▼
L3 Switch
     │
     ▼
Firewall
     │
     ▼
Router
     │
     ▼
Internet
```

### AWS

```text
EC2
 │
 ▼
Subnet
 │
 ▼
Route Table
 │
 ▼
NAT Gateway / Internet Gateway
 │
 ▼
Internet
```

AWSでは、オンプレで物理機器として存在していたネットワーク機能の多くが、クラウド上のサービスとして提供されています。

## 15. 最重要ポイント

まずは次の違いを理解しておくと、ネットワーク全体がかなり分かりやすくなります。

### L2

```text
MACアドレスを見る
        ↓
同じネットワーク内をつなぐ
```

### L3

```text
IPアドレスを見る
        ↓
異なるネットワークをつなぐ
```

### Routing

```text
どこへ送るか決める
```

### Firewall

```text
その通信を通していいか決める
```

### NAT

```text
IPアドレスを変換する
```

そして外部公開については、

```text
Web
TCP 443
   ↓
一般ユーザーが必要
   ↓
Internetへ公開
```

一方で、

```text
SSH
TCP 22
   ↓
管理者しか必要ない
   ↓
基本的にInternet全体へは公開しない
```

と考えると分かりやすいです。

# まとめ

ネットワークでは、

> **「通信経路が存在すること」と「通信が許可されていること」は別**

という点が重要です。

例えばSSHの場合、

```text
Internet
   │
   │ TCP 22
   ▼
Firewall
   │
   × ← ここで拒否
   │
Server
```

とすれば、サーバーまでSSH通信は到達しません。

一方、Webアクセスなら、

```text
Internet
   │
   │ TCP 443
   ▼
Firewall
   │
   ○
   ▼
Web Server
```

と許可します。

したがって、ネットワークを考えるときは、

```text
① L2 / L3でネットワークを構成する
        ↓
② ルーティングで通信経路を決める
        ↓
③ Firewallで通信を許可・拒否する
        ↓
④ SSHなど各サービス側でも認証・セキュリティ対策を行う
```

という順番で考えると理解しやすくなります。
