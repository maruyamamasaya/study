1. ネットワーク全体のイメージ

オンプレ環境では、PCやサーバーをスイッチ・ルーター・Firewallなどで接続してネットワークを構成します。

PC / Server

     │

     ▼

┌─────────────┐

│ L2スイッチ   │

└──────┬──────┘

       │

       ▼

┌─────────────┐

│ L3スイッチ   │

└──────┬──────┘

       │

       ▼

┌─────────────┐

│ Firewall     │

└──────┬──────┘

       │

       ▼

    Router

       │

       ▼

   Internet

それぞれ役割が異なります。

|   |   |
|---|---|
|機器・機能|主な役割|
|L2スイッチ|同じネットワーク内の通信|
|L3スイッチ|異なるネットワーク間の通信|
|Router|別ネットワークへの経路を決める|
|Firewall|通信を許可・拒否する|
|NAT|IPアドレスを変換する|

  

2. L2スイッチとは

L2スイッチは、主に同じネットワーク内の機器を接続する装置です。

例えば、

PC-A

192.168.1.10

     │

     ▼

┌─────────────┐

│ L2スイッチ   │

└──────┬──────┘

       │

       ▼

PC-B

192.168.1.20

両方とも、

192.168.1.0/24

という同じネットワークに所属しています。

L2スイッチは主にMACアドレスを見て通信を転送します。

イメージとしては、

「このMACアドレスのPCは3番ポートにいる」

  

        ↓

  

「3番ポートへデータを送ろう」

という動きをします。

L2スイッチのポイント

同じネットワーク内の通信を担当する。

  

3. L3スイッチとは

L3スイッチは、異なるネットワーク同士を接続する装置です。

例えば、

192.168.1.0/24

      │

      ▼

  L2スイッチ

      │

      ▼

  L3スイッチ

      │

      ▼

  L2スイッチ

      │

      ▼

192.168.2.0/24

192.168.1.0/24 と 192.168.2.0/24 は別ネットワークです。

L2スイッチだけでは、この2つのネットワーク間をルーティングできません。

そこでL3スイッチが、

192.168.1.x

      ↓

192.168.2.x に行きたい

      ↓

192.168.2.0/24 側へ転送

という判断をします。

L3では主にIPアドレスを使います。

L3スイッチのポイント

異なるネットワーク間の通信を担当する。

  

4. VLAN

実際の社内ネットワークでは、VLANを使ってネットワークを論理的に分割することがあります。

例えば、

VLAN 10

社員PC

192.168.10.0/24

  

VLAN 20

サーバー

192.168.20.0/24

  

VLAN 30

管理端末

192.168.30.0/24

という構成です。

              L2スイッチ

        ┌────────────────┐

PC ─────┤ VLAN 10        │

PC ─────┤ VLAN 10        │

Server ─┤ VLAN 20        │

Server ─┤ VLAN 20        │

管理PC ─┤ VLAN 30        │

        └───────┬────────┘

                │

                ▼

            L3スイッチ

L2スイッチがVLAN内の通信を担当し、

L3スイッチが、

VLAN 10

   ↓

VLAN 20

のような**VLAN間通信（Inter-VLAN Routing）**を担当します。

  

5. ルーティングとは

ルーティングは、

「この通信をどこへ送るか」を決める仕組み

です。

例えばサーバーが、

IPアドレス

192.168.1.100

  

サブネットマスク

255.255.255.0

  

デフォルトゲートウェイ

192.168.1.1

だったとします。

同じネットワークの、

192.168.1.50

へ通信する場合は、同一ネットワーク内なので直接通信できます。

一方、

8.8.8.8

のような外部IPへ通信する場合、

8.8.8.8

   ↓

  

192.168.1.x ではない

  

   ↓

  

自分とは別ネットワーク

  

   ↓

  

デフォルトゲートウェイへ送る

  

   ↓

  

192.168.1.1

となります。

  

6. デフォルトルート

ルーターなどでは、

0.0.0.0/0

というルートがよく登場します。

これは、

「個別のルートが見つからなかった通信は、こちらへ送る」

という意味です。

例えば、

192.168.10.0/24 → 社内ネットワーク

192.168.20.0/24 → サーバーネットワーク

0.0.0.0/0       → Internet側

というルーティングテーブルなら、

8.8.8.8

への通信は、

0.0.0.0/0

    ↓

Internet側

へ送られます。

  

7. ルーティングとFirewallは別物

ここは非常に重要です。

ルーティングは、

どこへ送る？

を決めます。

Firewallは、

その通信を通していい？

を判断します。

つまり、

ルーティング

↓

通信経路を決める

  

Firewall

↓

通信を許可・拒否する

という違いがあります。

例えば、

Server

  │

  ▼

Router

  │

  ▼

Firewall

  │

  ▼

Internet

という経路が存在していても、

Firewallが、

Server → Internet

  

DENY

としていれば通信できません。

  

8. Firewallではポート単位でも制御できる

Firewallでは、

送信元IP

送信先IP

プロトコル

ポート番号

などを使って通信を制御できます。

例えば、

HTTPS  TCP 443 → 許可

  

HTTP   TCP 80  → 許可

  

SSH    TCP 22  → 拒否

といった設定ができます。

  

9. SSHとは

SSHは、Linuxサーバーなどを遠隔操作するためによく使われる仕組みです。

一般的には、

TCP 22

を使用します。

例えば、

管理PC

  │

  │ SSH : 22

  ▼

Linux Server

という通信です。

SSH接続すると、管理者が遠隔からサーバーのコマンドを実行できます。

そのため、非常に便利ですが、同時に重要な管理用の入口でもあります。

  

10. SSHの22番ポートは基本的に世界中へ公開しない

Webサーバーの場合、

443 HTTPS

は一般ユーザーがアクセスする必要があります。

そのため、

Internet

   │

   │ 443

   ▼

Web Server

のように公開します。

しかしSSHは一般ユーザーが利用する必要がありません。

そのため、

443 → Internetから許可

  

22 → Internet全体からは許可しない

という考え方が基本になります。

例えば、

Internet

   │

   ├── TCP 443 ──→ OK

   │

   └── TCP 22 ───→ NG

です。

  

11. SSHを使う場合は接続元を限定する

管理者がSSHを使う必要がある場合、

203.0.113.10

という管理拠点のグローバルIPだけ許可する、といった設定ができます。

管理者

203.0.113.10

     │

     │ SSH : 22

     ▼

┌───────────────┐

│   Firewall    │

│               │

│ 管理者IP → OK │

│ その他   → NG │

└───────┬───────┘

        │

        ▼

    Linux Server

例えば、

203.0.113.10 → TCP 22 → ALLOW

  

その他        → TCP 22 → DENY

とします。

これなら、世界中からSSHログインを試されるリスクを大幅に減らせます。

  

12. SSH自体にもセキュリティ対策をする

ネットワーク側だけでなくSSH側でも対策します。

代表的なのは、

- パスワード認証ではなく公開鍵認証を使用する
- rootでの直接ログインを禁止する
- 接続元IPを限定する
- 不要ならSSHを外部公開しない
- OpenSSHやOSをアップデートする
- SSHログを監視する
- 必要に応じてVPNや踏み台サーバーを使用する

といった方法です。

特に、

Internet

   │

   │ SSH 22

   ▼

Server

と直接公開するより、

管理PC

   │

   │ VPN

   ▼

VPN Gateway

   │

   ▼

社内ネットワーク

   │

   │ SSH

   ▼

Server

とする方が安全です。

SSHそのものをInternetへ公開しないからです。

  

13. AWSとの対応

オンプレの考え方はAWSにもかなりそのまま当てはまります。

|   |   |
|---|---|
|オンプレ|AWSで近いもの|
|社内ネットワーク|VPC|
|VLAN / サブネット|Subnet|
|ルーティングテーブル|Route Table|
|Internet接続|Internet Gateway|
|NAT|NAT Gateway|
|Firewall|Security Group / NACL|
|物理・仮想サーバー|EC2|

例えばAWSなら、

Internet

    │

    │ HTTPS : 443

    ▼

   ALB

    │

    ▼

   EC2

としつつ、

Internet → EC2 : 22

  

拒否

という設計にできます。

EC2を管理する場合も、SSHをInternetへ公開するのではなく、Systems Manager Session Managerなどを利用する方法があります。

15. 最重要ポイント

まずは次の違いを理解しておくと、ネットワーク全体がかなり分かりやすくなります。

L2

↓

MACアドレスを見る

↓

同じネットワーク内をつなぐ

  

  

L3

↓

IPアドレスを見る

↓

異なるネットワークをつなぐ

  

  

Routing

↓

どこへ送るか決める

  

  

Firewall

↓

その通信を通していいか決める

  

  

NAT

↓

IPアドレスを変換する

そして外部公開については、

Web

TCP 443

↓

一般ユーザーが必要

↓

Internetへ公開

  

  

SSH

TCP 22

↓

管理者しか必要ない

↓

基本的にInternet全体へは公開しない

と考えると分かりやすいです。

まとめ

ネットワークでは、

「通信経路が存在すること」と「通信が許可されていること」は別です。

例えばSSHの場合、

Internet

   │

   │ TCP 22

   ▼

Firewall

   │

   × ← ここで拒否

   │

Server

とすれば、サーバーまでSSH通信は到達しません。

一方Webアクセスなら、

Internet

   │

   │ TCP 443

   ▼

Firewall

   │

   ○

   ▼

Web Server

と許可します。

したがって、ネットワークを考えるときは、

① L2/L3でネットワークを構成する

↓

② ルーティングで通信経路を決める

↓

③ Firewallで通信を許可・拒否する

↓

④ SSHなど各サービス側でも認証・セキュリティ対策を行う

という順番で考えると理解しやすくなります。
