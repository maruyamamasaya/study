**構築**とは、

> **設計した内容をもとに、実際にシステムや環境を作る作業**です。

簡単に言うと、

**設計が「作り方を決めること」、構築が「実際に作ること」**です。

---

## 具体例

たとえば、AWSでWebシステムを作る場合です。

### 設計で決めること

- EC2を何台使うか
- データベースはRDSにするか
- 通信はHTTPSにするか
- バックアップをどうするか

### 構築で行うこと

- EC2を作成する
- [[用語解説/RDS]]を作成する
- セキュリティグループを設定する
- [[用語解説/nginx]]をインストールする
- アプリを配置する
- ドメインやSSL証明書を設定する

---

## 構築の対象

|分野|構築内容|
|---|---|
|サーバー|OS、Webサーバー、ミドルウェアの設定|
|ネットワーク|IP、DNS、ルーター、Firewallの設定|
|クラウド|AWS、Azure、GCP上の環境作成|
|データベース|DB作成、テーブル作成、権限設定|
|アプリ|プログラムの配置、ビルド、起動|
|CI/CD|GitHub Actionsなどの自動化設定|

---

## 開発の流れ

```
要件定義
「何が必要か」
    ↓
設計
「どう作るか」
    ↓
構築
「実際に環境や仕組みを作る」
    ↓
テスト
「正しく動くか確認する」
    ↓
運用
「継続して管理する」
```

## 実務でよく使われる例

### サーバー構築

- Linuxをインストールする
- ユーザーや権限を設定する
- nginxやApacheを設定する

### ネットワーク構築

- IPアドレスを設定する
- 通信経路を作る
- Firewallを設定する

### データベース構築

```
CREATE DATABASE reservation_system;
```

```
CREATE TABLE users (
  id INT PRIMARY KEY,
  name VARCHAR(100)
);
```

### CI/CD構築

- [[記事：基礎編/GitHub Actions]]の[[用語解説/YAML]]を作る
- [[用語解説/Push]]時にテストを実行する
- mainへのマージ時に自動デプロイする

## 設計・構築・実装の違い

|用語|意味|
|---|---|
|**設計**|何をどのように作るか決める|
|**構築**|サーバーや環境、仕組みを実際に作る|
|**実装**|プログラムのコードを書く|

ただし、実務では「システムを構築する」のように、実装も含めて広い意味で使われる場合があります。

---

## 一言でいうと

**構築 = 「設計書や要件に沿って、実際に使えるシステムや環境を作ること」**です。

特にインフラ分野では、**サーバー・ネットワーク・クラウド・データベースなどを設定し、動く状態にする作業**を「構築」と呼ぶことが多いです。
