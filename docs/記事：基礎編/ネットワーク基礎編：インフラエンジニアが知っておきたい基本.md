## ネットワークとは

ネットワークとは、**複数のコンピュータや機器同士をつないで、データをやり取りする仕組み**です。

例えば、普段Webサイトを見るときも、

```text
自分のPC
   ↓
インターネット
   ↓
Webサーバー
```

という形で、ネットワークを通じて通信しています。

インフラエンジニアは、サーバーを用意するだけではなく、

- どのサーバーと通信できるか
    
- どのポートを開けるか
    
- どの通信を許可するか
    
- インターネットからアクセスできるか
    

といったネットワーク部分も考える必要があります。

---

## なぜネットワークの知識が必要なのか

サーバーが正常に動いていても、ネットワークに問題があると利用者はアクセスできません。

例えば、

```text
Webサイトにつながらない
```

という問題が発生した場合でも、原因はさまざまです。

```text
DNSがおかしい
↓
IPアドレスが間違っている
↓
ポートが閉じている
↓
Firewallで遮断されている
↓
Webサーバーが起動していない
```

そのためインフラエンジニアは、

**「通信がどこまで届いていて、どこで止まっているのか」**

を考えながら原因を切り分けます。

---

## IPアドレス

IPアドレスは、ネットワーク上に存在する機器を識別するための番号です。

簡単にいうと、

**ネットワーク上の住所**

です。

例えば、

```text
192.168.1.10
```

のような数字で表します。

通信するときは、

```text
送信元IP
   ↓
ネットワーク
   ↓
送信先IP
```

というように、どこからどこへデータを送るのかを指定します。

---

## グローバルIPとプライベートIP

IPアドレスには、大きく分けて2種類あります。

### グローバルIPアドレス

インターネット上で利用するIPアドレスです。

```text
インターネット
     ↓
203.xxx.xxx.xxx
     ↓
サーバー
```

インターネット上で機器を識別するために使われます。

### プライベートIPアドレス

会社や家庭、クラウド内部など、限定されたネットワーク内で使用するIPアドレスです。

例えば、

```text
192.168.1.10
10.0.0.5
```

などがあります。

AWSでも、VPC内部のEC2にはプライベートIPが割り当てられます。

---

## ポート

IPアドレスだけでは、

「どのコンピュータに接続するか」

までは分かります。

しかし、そのコンピュータの中では複数のサービスが動いています。

例えば、

```text
Linuxサーバー

├── SSH
├── Webサーバー
├── データベース
└── その他のアプリ
```

そこで使うのが**ポート番号**です。

IPアドレスが建物の住所だとすると、

**ポート番号は部屋番号**

のようなものです。

---

## よく使われるポート番号

代表的なポートには次のようなものがあります。

|ポート番号|用途|
|--:|---|
|22|SSH|
|80|HTTP|
|443|HTTPS|
|3306|MySQL|
|5432|PostgreSQL|

例えば、

```text
203.0.113.10:443
```

なら、

```text
203.0.113.10
      ↓
サーバーのIPアドレス

443
 ↓
HTTPS
```

という意味になります。

---

## TCPとUDP

ネットワーク通信では、主に**TCP**と**UDP**という通信方式があります。

### TCP

TCPは、データが正しく相手に届いたかを確認しながら通信します。

特徴としては、

- 信頼性が高い
    
- データの順番を保証する
    
- 届かなかった場合は再送する
    

といったものがあります。

Web通信やSSHなどでよく利用されます。

```text
送信
 ↓
受信
 ↓
届いたことを確認
```

---

### UDP

UDPは、相手に届いたかを細かく確認せずにデータを送ります。

そのためTCPより高速ですが、データが失われる可能性があります。

主に、

- 動画配信
    
- 音声通信
    
- DNS
    

など、速度が重要な通信で利用されます。

---

## DNS

DNSは、

**ドメイン名をIPアドレスに変換する仕組み**

です。

例えば人間は、

```text
example.com
```

の方が覚えやすいですが、実際の通信ではIPアドレスが必要です。

そこでDNSが、

```text
example.com
     ↓
DNS
     ↓
203.0.113.10
```

という変換を行います。

DNSはよく、

**インターネット上の電話帳**

のようなものと説明されます。

---

## HTTPとHTTPS

Webサイトを見るときには、HTTPという通信ルールが利用されます。

例えばブラウザが、

```text
このページをください
```

とWebサーバーへリクエストします。

するとWebサーバーが、

```text
HTML
画像
JSON
```

などのデータを返します。

この通信ルールがHTTPです。

---

## HTTPSとは

HTTPSは、HTTP通信を暗号化したものです。

```text
HTTP

ブラウザ
   ↓
通信内容
   ↓
サーバー
```

に対して、

```text
HTTPS

ブラウザ
   ↓
暗号化
   ↓
サーバー
```

となります。

現在のWebサービスでは、基本的にHTTPSが利用されています。

HTTPSでは主に443番ポートが使用されます。

---

## ルーター

ルーターは、

**異なるネットワーク同士をつなぐ機器**

です。

例えば自宅では、

```text
PC
スマートフォン
テレビ
   ↓
Wi-Fiルーター
   ↓
インターネット
```

という構成になっています。

ルーターは、

「このデータはどこへ送ればいいのか」

を判断して、適切なネットワークへデータを送ります。

---

## ルーティング

ルーティングとは、

**通信データをどの経路へ送るか決める仕組み**

です。

例えば、

```text
PC
 ↓
ルーターA
 ↓
ルーターB
 ↓
Webサーバー
```

というように、インターネットでは複数の機器を経由して目的地まで通信します。

AWSでも、

**ルートテーブル**

という設定を使って、

```text
この通信はインターネットへ
この通信は社内ネットワークへ
```

といった経路を設定します。

---

## Firewall

Firewallは、

**通信を許可するか、拒否するかを判断する仕組み**

です。

例えばWebサーバーなら、

```text
22番  → 管理者のみ許可
80番  → 許可
443番 → 許可
3306番 → 外部から禁止
```

といった設定を行います。

すべてのポートをインターネットへ公開すると、セキュリティ上のリスクが高くなります。

そのため、

**必要な通信だけを許可する**

という考え方が重要です。

AWSでは、似た役割を持つものとして**Security Group**があります。

---

## サブネット

サブネットとは、

**大きなネットワークを小さく分割したもの**

です。

例えば、

```text
会社ネットワーク
    │
    ├── 開発用ネットワーク
    ├── 本番用ネットワーク
    └── 管理用ネットワーク
```

というように分けることができます。

AWSでは、VPCの中に複数のサブネットを作ります。

```text
VPC
│
├── Public Subnet
│
│      └── Webサーバー
│
└── Private Subnet
       └── DBサーバー
```

といった構成がよく使われます。

---

## Public SubnetとPrivate Subnet

AWSを勉強するとよく登場する考え方です。

### Public Subnet

インターネットと直接通信できるネットワークです。

例えば、

```text
インターネット
     ↓
Public Subnet
     ↓
Webサーバー
```

のように使います。

### Private Subnet

基本的にインターネットから直接アクセスさせないネットワークです。

例えばデータベースを、

```text
Webサーバー
    ↓
Private Subnet
    ↓
データベース
```

のように配置します。

データベースを直接インターネットへ公開しないことで、安全性を高めることができます。

---

## ネットワーク障害の考え方

例えばWebサイトにつながらない場合、次のような順番で確認できます。

```text
① DNSは正しいか
      ↓
② IPアドレスは正しいか
      ↓
③ サーバーまで通信できるか
      ↓
④ ポートは開いているか
      ↓
⑤ Firewallで許可されているか
      ↓
⑥ Webサーバーは動いているか
```

重要なのは、

**最初から原因を決めつけず、通信経路を一つずつ確認すること**

です。

---

## Linuxでネットワークを確認する

Linuxでは、ネットワークの確認にいくつかのコマンドを使用します。

例えば、

```bash
ip addr
```

でIPアドレスを確認できます。

通信できるか簡単に確認するときは、

```bash
ping 8.8.8.8
```

などを使います。

DNSを確認する場合は、

```bash
nslookup example.com
```

や、

```bash
dig example.com
```

などがあります。

HTTP通信を確認する場合は、

```bash
curl https://example.com
```

を使うこともできます。

ポートの状態を見る場合は、

```bash
ss -tuln
```

などを利用します。

---

## ネットワークを理解するとAWSが分かりやすくなる

AWSには、

- VPC
    
- Subnet
    
- Route Table
    
- Internet Gateway
    
- Security Group
    
- Load Balancer
    
- Route 53
    

など、多くのネットワーク関連サービスがあります。

最初は難しそうに見えますが、基本はこれまで説明した内容です。

```text
IPアドレス
     ↓
サブネット
     ↓
ルーティング
     ↓
Firewall
     ↓
DNS
     ↓
HTTP / HTTPS
```

これらをAWS上で設定できるようにしたもの、と考えると理解しやすくなります。

---

## インフラエンジニアとして覚えたいネットワークの順番

最初は次の順番で理解すると分かりやすいです。

```text
ネットワークとは
      ↓
IPアドレス
      ↓
ポート
      ↓
TCP / UDP
      ↓
DNS
      ↓
HTTP / HTTPS
      ↓
ルーター・ルーティング
      ↓
Firewall
      ↓
サブネット
      ↓
AWS VPC
```

特に、

**IPアドレス・ポート・DNS・HTTP/HTTPS**

の4つは、Webやクラウドを理解するうえで非常に重要です。

---

## まとめ

ネットワークとは、コンピュータ同士がデータをやり取りするための仕組みです。

インフラエンジニアは、

- IPアドレスで通信相手を特定する
    
- ポートでサービスを特定する
    
- DNSでドメイン名をIPへ変換する
    
- HTTP / HTTPSでWeb通信を行う
    
- ルーティングで通信経路を決める
    
- Firewallで通信を制御する
    
- サブネットでネットワークを分割する
    

といった仕組みを理解する必要があります。

ネットワークを学ぶうえで一番大切なのは、

**「データがどこから、どこを通って、どこへ届くのか」**

をイメージできるようになることです。

この考え方が身につくと、Linux、AWS、Docker、Webサーバー、セキュリティといった他のインフラ技術も理解しやすくなります。
