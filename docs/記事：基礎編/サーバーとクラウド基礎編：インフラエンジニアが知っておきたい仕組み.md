## サーバーとは

サーバーとは、**他のコンピュータからの要求に対して、データや機能を提供するコンピュータ**です。

例えばWebサイトを見る場合、

```text
自分のPC
   ↓
「このページを見たい」
   ↓
Webサーバー
   ↓
「HTMLや画像を返す」
```

というやり取りが行われます。

つまりサーバーは、

**「利用者からのリクエストを受け取り、必要な処理やデータを返す側」**

と考えると分かりやすいです。

---

## サーバーは特別な機械なのか

サーバーというと、大きな専用機をイメージしがちですが、基本的には普通のコンピュータと同じです。

違いは、主に

- 長時間動き続ける
    
- 多くの利用者からアクセスされる
    
- ネットワーク越しにサービスを提供する
    
- 安定性や安全性が求められる
    

といった役割を持っていることです。

例えば、

```text
CPU
メモリ
ディスク
OS
ネットワーク
```

といった基本構成は、普段使っているPCと同じです。

---

# サーバーの主な種類

サーバーには、役割によっていくつか種類があります。

## Webサーバー

Webサイトへのアクセスを受け付けます。

代表的なものは、

- nginx
    
- Apache
    

です。

例えば、

```text
ブラウザ
   ↓
HTTPS
   ↓
nginx
   ↓
Webアプリ
```

という流れになります。

---

## アプリケーションサーバー

実際の業務処理やWebアプリケーションを動かすサーバーです。

例えば、

```text
ユーザー
   ↓
Webサーバー
   ↓
Node.js
Java
Python
PHP
```

などのアプリケーションが処理を行います。

---

## データベースサーバー

データを保存・検索するためのサーバーです。

代表的なものには、

- MySQL
    
- PostgreSQL
    
- Oracle Database
    

などがあります。

例えば、

```text
Webアプリ
   ↓
DBサーバー
   ↓
ユーザー情報
予約情報
商品情報
```

といったデータを管理します。

---

## ファイルサーバー

ファイルを保存し、複数のユーザーやシステムから利用できるようにします。

例えば、

- 画像
    
- PDF
    
- 動画
    
- バックアップデータ
    

などを保存します。

---

# サーバーでは何を管理するのか

インフラエンジニアは、サーバー上でさまざまなものを管理します。

例えば、

```text
OS
├── CPU
├── メモリ
├── ディスク
├── ユーザー
├── 権限
├── プロセス
├── ネットワーク
├── ログ
└── アプリケーション
```

です。

Linuxの知識が重要なのは、このサーバーの中身を操作するためです。

---

# Webサイトへアクセスするときの流れ

ここまでのLinuxやネットワークの知識も合わせると、

```text
ユーザー
   ↓
DNS
   ↓
IPアドレス
   ↓
HTTPS :443
   ↓
Webサーバー
   ↓
アプリケーション
   ↓
データベース
```

という流れになります。

インフラエンジニアは、この通信が正常に動くように環境を構築します。

---

# オンプレミスとは

以前は、企業が自社でサーバーを購入し、自社内やデータセンターに設置することが一般的でした。

このような形を、

**オンプレミス**

と呼びます。

```text
会社
  ↓
サーバールーム
  ↓
物理サーバー
```

自分たちで、

- サーバー購入
    
- 設置
    
- ネットワーク配線
    
- 電源管理
    
- 故障対応
    
- OS設定
    

などを行います。

---

# クラウドとは

クラウドとは、

**インターネット経由でサーバーやデータベースなどのITインフラを利用できる仕組み**

です。

代表的なクラウドサービスには、

- AWS
    
- Microsoft Azure
    
- Google Cloud
    

があります。

クラウドを使うと、物理サーバーを購入しなくても、

```text
管理画面
   ↓
サーバー作成
   ↓
数分後
   ↓
利用開始
```

といったことができます。

---

# オンプレミスとクラウドの違い

## オンプレミス

```text
サーバーを購入
      ↓
設置
      ↓
ネットワーク設定
      ↓
OSインストール
      ↓
利用開始
```

準備に時間がかかります。

また、将来必要になるスペックを予測して購入する必要があります。

---

## クラウド

```text
クラウド管理画面
      ↓
必要なスペックを指定
      ↓
サーバー作成
      ↓
利用開始
```

必要に応じてスペックを変更したり、台数を増やしたりできます。

---

# クラウドのメリット

クラウドには、主に次のようなメリットがあります。

- サーバーを購入しなくてもよい
    
- 短時間で環境を作れる
    
- 必要に応じて性能を変更できる
    
- サーバーを増やしやすい
    
- 世界中の拠点を利用できる
    
- 利用した分だけ料金を支払えるサービスが多い
    

そのため、現在では多くのWebサービスでクラウドが利用されています。

---

# AWSとは

AWSは、

**Amazon Web Services**

の略です。

Amazonが提供しているクラウドサービスです。

AWSには非常に多くのサービスがありますが、最初から全部覚える必要はありません。

まずは代表的なものを理解すると分かりやすいです。

---

# EC2

EC2は、

**クラウド上の仮想サーバー**

です。

イメージとしては、

```text
AWS
 └── EC2
      └── Linux
           └── Webアプリ
```

です。

オンプレミスで物理サーバーを購入する代わりに、AWS上でサーバーを作ることができます。

---

# RDS

RDSは、

**AWSが提供するデータベースサービス**

です。

例えば、

- MySQL
    
- PostgreSQL
    

などを利用できます。

```text
EC2
 ↓
RDS
 ↓
データ
```

という構成ができます。

OSレベルの管理などの一部をAWSに任せられるため、データベースを運用しやすくなります。

---

# S3

S3は、

**ファイルを保存するためのサービス**

です。

例えば、

- 画像
    
- 動画
    
- PDF
    
- バックアップ
    

などを保存できます。

```text
Webアプリ
    ↓
S3
    ↓
画像・ファイル
```

という使い方ができます。

---

# VPC

VPCは、

**AWS上に自分専用のネットワークを作る仕組み**

です。

例えば、

```text
AWS
│
└── VPC
    │
    ├── Public Subnet
    │     └── Webサーバー
    │
    └── Private Subnet
          └── DBサーバー
```

といったネットワーク構成を作ることができます。

ここで、

- IPアドレス
    
- サブネット
    
- ルーティング
    
- Firewall
    

といったネットワークの知識が必要になります。

---

# Route 53

Route 53は、

**AWSのDNSサービス**

です。

例えば、

```text
example.com
    ↓
Route 53
    ↓
AWS上のサーバー
```

という形でドメインとサーバーをつなぐことができます。

---

# ALB

ALBは、

**Application Load Balancer**

の略です。

複数のサーバーへアクセスを振り分ける役割があります。

例えば、

```text
ユーザー
   ↓
ALB
   ↓
┌─────────┐
EC2-1   EC2-2
```

というようにアクセスを分散できます。

これによって、1台のサーバーに負荷が集中することを防ぎます。

---

# IAM

IAMは、

**AWS内のユーザーや権限を管理する仕組み**

です。

例えば、

```text
開発者A
→ EC2操作可能

開発者B
→ S3のみ操作可能
```

といった権限管理ができます。

クラウドでは、

**誰が何を操作できるか**

を適切に管理することが非常に重要です。

---

# クラウドだからサーバーの知識が不要になるわけではない

クラウドを使うと、物理サーバーを購入したり設置したりする必要は減ります。

しかし、

- Linux
    
- ネットワーク
    
- IPアドレス
    
- ポート
    
- DNS
    
- Webサーバー
    
- セキュリティ
    
- データベース
    

などの知識が不要になるわけではありません。

むしろAWSのサービスは、

**これまで存在していたインフラ技術を、クラウド上で簡単に利用できるようにしたもの**

と考えると理解しやすいです。

---

# 例えばAWSでWebサービスを作ると

簡単な構成なら、

```text
ユーザー
   ↓
Route 53
   ↓
ALB
   ↓
EC2
   ↓
Webアプリ
   ↓
RDS
```

となります。

画像などは、

```text
Webアプリ
   ↓
S3
```

へ保存することもできます。

さらに、

```text
GitHub
   ↓
CI/CD
   ↓
Docker
   ↓
AWS
```

と組み合わせることで、デプロイも自動化できます。

---

# サーバーとDockerの関係

Dockerも、最終的にはどこかのサーバー上で動きます。

例えば、

```text
AWS
 ↓
EC2
 ↓
Linux
 ↓
Docker
 ↓
Webアプリ
```

という構成です。

DockerがあるからといってLinuxやサーバーがなくなるわけではありません。

Dockerは、

**サーバー上でアプリを動かしやすくする仕組み**

と考えると分かりやすいです。

---

# サーバーとクラウドで重要な考え方

インフラエンジニアとしては、サービス名を暗記するだけではなく、

```text
ユーザー
   ↓
ネットワーク
   ↓
サーバー
   ↓
アプリケーション
   ↓
データベース
```

という全体像を理解することが重要です。

AWSを使っている場合でも、

```text
DNS
 ↓
Route 53

ネットワーク
 ↓
VPC

サーバー
 ↓
EC2

データベース
 ↓
RDS

ファイル
 ↓
S3
```

というように、既存のインフラ技術と対応させると理解しやすくなります。

---

# インフラエンジニアとして最初に覚えたいこと

最初は、

```text
サーバーとは何か
    ↓
Linux
    ↓
Webサーバー
    ↓
ネットワーク
    ↓
仮想サーバー
    ↓
クラウド
    ↓
EC2
    ↓
VPC
    ↓
RDS・S3
    ↓
ALB・Route 53
```

という順番で学習すると分かりやすいです。

---

# まとめ

サーバーとは、

**利用者や他のシステムからのリクエストを受け取り、データや機能を提供するコンピュータ**

です。

クラウドとは、

**そのサーバーやネットワーク、データベースなどをインターネット経由で利用できる仕組み**

です。

つまり、

```text
サーバー
＝ コンピュータそのもの・役割

クラウド
＝ サーバーなどのインフラを利用する方法
```

と考えると分かりやすくなります。

インフラエンジニアにとって重要なのは、

**「AWSの操作方法を覚えること」だけではなく、その裏側でLinux・ネットワーク・サーバーがどのように動いているのか理解すること**

です。

この基礎があると、Docker、CI/CD、監視、セキュリティ、IaCなど、より高度なインフラ技術も理解しやすくなります。
