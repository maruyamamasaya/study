1. 全体像

Webシステムでは、大きく分けると次のような構成になります。

ユーザー

   ↓ HTTPS

Web / APIサーバー

   ↓

DBサーバー

それぞれの役割は、

- Webサーバー：ユーザーからのリクエストを受けて、プログラムを実行する
- DBサーバー：データを保存・検索・更新する

という違いがあります。

  

⸻

  

2. Webサーバーとは

Webサーバーは、ブラウザなどから送られてきたリクエストを処理するサーバーです。

例えば、

ユーザー

「予約一覧を見たい」

      ↓

Webサーバー

      ↓

プログラムを実行

      ↓

DBから予約情報を取得

      ↓

ユーザーへ返す

といった処理を行います。

代表的なWebサーバー・アプリケーションとして、

- nginx
- Apache
- Node.js
- Next.js
- Java / Spring
- PHP / Laravel

などがあります。

  

⸻

  

3. DBサーバーとは

DBサーバー（データベースサーバー）は、

大量のデータを安全に保存し、高速に検索・更新するためのサーバー

です。

代表的なデータベースには、

- MySQL
- PostgreSQL
- Oracle Database
- SQL Server
- Amazon Aurora
- Amazon DynamoDB

などがあります。

例えば、

DB

├── users

│   └── ユーザー情報

│

├── reservations

│   └── 予約情報

│

├── products

│   └── 商品情報

│

└── payments

    └── 決済情報

のようなデータを管理します。

  

⸻

  

4. WebサーバーからDBへアクセスする仕組み

基本的な流れは、

ブラウザ

   ↓ HTTP / HTTPS

Webサーバー

   ↓ DB接続

DBサーバー

   ↓

検索結果

   ↓

Webサーバー

   ↓

ブラウザ

となります。

重要なのは、

ブラウザ → DB

ではなく、

ブラウザ

   ↓

Web / APIサーバー

   ↓

DB

とすることです。

Web/APIサーバー側で、

- 認証
- 権限チェック
- 入力チェック
- ビジネスロジック

などを行ってからDBへアクセスします。

  

⸻

  

5. DBへのアクセスはSQL？API？

DBの種類によって異なります。

RDBの場合

MySQLやPostgreSQLなどでは、基本的にSQLを使います。

SELECT *

FROM users

WHERE id = 123;

流れとしては、

Webアプリ

   ↓

SQL

   ↓

MySQL / PostgreSQL

です。

ただし、実際のプログラムではORMを使うこともあります。

例えばPrismaなら、

const user = await prisma.user.findUnique({

  where: {

    id: 123

  }

});

のように書けます。

内部的には、

SELECT *

FROM users

WHERE id = 123;

のようなSQLが実行されます。

代表的なORMには、

- Prisma
- Sequelize
- TypeORM
- Hibernate
- Entity Framework

などがあります。

  

⸻

  

6. API経由でDBへアクセスする場合

別システムが所有しているDBにアクセスしたい場合は、DBへ直接接続するのではなくAPIを使うことがあります。

システムA

   ↓ HTTP API

システムB

   ↓ SQL

DB

例えば、

予約システム

   ↓

GET /api/users/123

   ↓

会員システム

   ↓

会員DB

という構成です。

この場合、予約システムは会員DBへ直接SQLを実行しません。

  

⸻

  

7. WebサーバーとDBサーバーは別のマシン？

必ずしも別である必要はありません。

開発環境や小規模システムなら、

1台のサーバー

  

├── nginx

├── Next.js

└── MySQL

という構成も可能です。

この場合、

Next.js

   ↓

localhost

   ↓

MySQL

のようにアクセスできます。

  

⸻

  

8. 本番環境では分けることが多い

本番環境では、

Webサーバー

     ↓

DBサーバー

と分離する構成が一般的です。

例えばAWSなら、

インターネット

      ↓

     ALB

      ↓

     EC2

 Web/APIサーバー

      ↓

     RDS

 DBサーバー

といった構成になります。

分けることで、

- Webサーバーだけ増やせる
- DBだけ高性能にできる
- 障害の影響を分離できる
- セキュリティを強化できる
- DBだけバックアップできる

などのメリットがあります。

  

⸻

  

9. WebサーバーとDBサーバーの物理性能

WebサーバーとDBサーバーは、物理的には同じ性能でも問題ありません。

例えば、

Webサーバー

  

CPU     4コア

メモリ  16GB

SSD     500GB

DBサーバー

  

CPU     4コア

メモリ  16GB

SSD     500GB

でも動作します。

「Webサーバー専用CPU」「DB専用CPU」があるわけではありません。

違うのは、

ハードウェアそのものより、担当する仕事

です。

  

⸻

  

10. Webサーバーで重要な性能

Webサーバーでは、

HTTPリクエスト

      ↓

プログラム実行

      ↓

計算・処理

      ↓

DB問い合わせ

      ↓

レスポンス

という処理が大量に発生します。

そのため、

- CPU
- メモリ
- ネットワーク性能

などが重要になります。

また、Webサーバーは比較的台数を増やしやすい特徴があります。

             ┌→ Webサーバー1

ユーザー → ALB

             ├→ Webサーバー2

             └→ Webサーバー3

これをスケールアウトと呼びます。

  

⸻

  

11. DBサーバーで重要な性能

DBサーバーでは特に、

- メモリ
- ストレージ速度
- ストレージ容量
- IOPS
- CPU
- データの信頼性

が重要です。

特に、

メモリとストレージ性能

が重要になります。

  

⸻

  

12. DBではなぜメモリが重要なのか

DBは毎回SSDからデータを読み込むと遅いため、よく使用するデータをメモリに保持します。

SSD

 ↓

メモリ

 ↓

DB処理

 ↓

Webサーバー

メモリはSSDより高速なので、

よく使うデータ

      ↓

メモリにキャッシュ

      ↓

高速に検索

できます。

そのためDBサーバーでは、大容量メモリを搭載する構成がよくあります。

  

⸻

  

13. DBではストレージも重要

DBでは常に、

SELECT

↓

読み込み

INSERT

↓

書き込み

UPDATE

↓

読み込み + 書き込み

DELETE

↓

書き込み

といった処理が発生します。

そのため、

- SSDの速度
- IOPS
- 容量
- 耐久性

などが重要になります。

IOPSとは

IOPSは、

1秒間にストレージへ何回読み書きできるか

を表す指標です。

DBでは大量の読み書きが発生するため、重要な性能指標になります。

  

⸻

  

14. DBは高速検索が得意

例えば100万件のユーザーデータから、

SELECT *

FROM users

WHERE email = 'test@example.com';

のように特定データを検索します。

さらに、

100万件

   ↓

インデックス

   ↓

必要なデータ

という仕組みを使うことで高速化できます。

この仕組みを**インデックス（Index）**と呼びます。

  

⸻

  

15. DBではデータを壊さないことが重要

DBでは単純な速度だけでなく、

データが正しい状態を維持すること

が非常に重要です。

例えば銀行で、

Aさん

100万円

  

↓ 10万円送金

  

Bさん

50万円

という処理をするとします。

正常なら、

Aさん

90万円

  

Bさん

60万円

になります。

しかし途中でサーバーが停止して、

Aさん

90万円

  

Bさん

50万円

になってしまうと問題です。

そこでDBには、

- トランザクション
- COMMIT
- ROLLBACK
- ロック
- 排他制御
- ACID特性

などの仕組みがあります。

  

⸻

  

16. バックアップも非常に重要

Webサーバーが壊れた場合、

Webサーバー故障

      ↓

新しいサーバー作成

      ↓

GitHubからコード取得

      ↓

再デプロイ

という方法で復旧できることがあります。

しかしDBには、

顧客情報

予約情報

注文履歴

売上情報

決済情報

など、再作成できないデータがあります。

そのため、

DB

├── 自動バックアップ

├── スナップショット

├── レプリケーション

└── 障害復旧

などが重要になります。

  

⸻

  

17. DBはインターネットへ直接公開しない

基本的な構成は、

インターネット

      ↓

     ALB

      ↓

Web/APIサーバー

      ↓

DBサーバー

です。

DBを、

インターネット

      ↓

DB

と直接公開する構成は基本的に避けます。

18. AWSの場合

AWSでは例えば、

VPC

  

├── ALB

│

├── EC2

│   └── Next.js

│

└── RDS

    └── PostgreSQL

という構成にできます。

通信は、

ユーザー

   ↓ HTTPS

ALB

   ↓

EC2

   ↓ SQL

RDS

となります。

RDSはインターネットへ直接公開せず、EC2からのみ接続できるようにすることが一般的です。

例えばPostgreSQLなら、

EC2

 ↓ TCP 5432

RDS

MySQLなら、

EC2

 ↓ TCP 3306

RDS

という通信になります。

  

⸻

  

19. RDSとは

Amazon RDSは、AWSが提供しているマネージド型のRDBサービスです。

例えば、

Amazon RDS

├── MySQL

├── PostgreSQL

├── MariaDB

├── Oracle

└── SQL Server

などを利用できます。

自分でDBサーバーを一から構築するよりも、

- バックアップ
- 障害対応
- バージョン管理
- 監視
- 冗長化

などをAWS側の機能で管理しやすくなっています。

  

⸻

  

20. DynamoDBの場合

DynamoDBはRDSとは少し違います。

RDSなら、

Next.js

   ↓

SQL

   ↓

RDS

ですが、DynamoDBでは、

Next.js

   ↓

AWS SDK

   ↓

DynamoDB API

   ↓

DynamoDB

という形になります。

例えば、

const result = await dynamoDb.send(

  new GetCommand({

    TableName: "Users",

    Key: {

      userId: "user-123"

    }

  })

);

のようにアクセスします。

つまり、

RDS

→ SQLで操作する

  

DynamoDB

→ AWS SDK / APIで操作する

という違いがあります。

  

⸻

  

21. WebサーバーとDBサーバーの比較

|   |   |   |
|---|---|---|
|項目|Webサーバー|DBサーバー|
|主な仕事|リクエスト処理|データ管理|
|データ保存|基本的に主目的ではない|非常に重要|
|CPU|重要|重要|
|メモリ|重要|特に重要|
|ストレージ|そこそこ|非常に重要|
|IOPS|比較的重要度低め|重要|
|バックアップ|コードなら再配置可能|非常に重要|
|外部公開|する場合がある|基本的にしない|
|台数追加|比較的簡単|Webより複雑|
|AWS例|EC2 / ECS / Lambda|RDS / Aurora / DynamoDB|

まとめ

WebサーバーとDBサーバーは、物理的にまったく別種類のコンピューターというわけではありません。

Webサーバー

「処理担当」

  

DBサーバー

「データ担当」

という役割の違いです。

特にDBサーバーでは、

DBサーバーで重要なもの

  

├── メモリ

├── ストレージ性能

├── IOPS

├── 高速検索

├── インデックス

├── トランザクション

├── データの整合性

├── バックアップ

├── 冗長化

└── セキュリティ

が重要になります。

Webシステム全体としては、

ユーザー

   ↓

Web / APIサーバー

   ↓

DBサーバー

という3段階をまず理解しておくと、AWS、Next.js、API、SQL、RDSなどの関係がかなり理解しやすくなります。
