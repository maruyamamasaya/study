> **対象**：AWS初心者～インフラ初心者  
> **目標**：「リージョンとは何か」「AZとの違い」「実務でどう使われるか」を理解する

---

# 1. リージョンとは？

AWSのリージョン（Region）は、

**AWSのデータセンターが集まっている地域**のことです。

簡単にいうと、

> **「AWSのサービスを動かす場所（地域）」**

です。

例えば

- 東京
- 大阪
- シンガポール
- バージニア（アメリカ）
- フランクフルト（ドイツ）

などがあります。

---

# 2. イメージ

```
世界

├─東京リージョン
├─大阪リージョン
├─シンガポールリージョン
├─ソウルリージョン
├─シドニーリージョン
├─バージニアリージョン
└─ロンドンリージョン
```

世界中にAWSのリージョンがあります。

---

# 3. 東京リージョンとは？

例えば

```
ap-northeast-1
```

これは

**東京リージョン**

を意味します。

AWSでは

地域ごとにコードがあります。

|リージョン|コード|
|---|---|
|東京|ap-northeast-1|
|大阪|ap-northeast-3|
|ソウル|ap-northeast-2|
|シンガポール|ap-southeast-1|
|バージニア北部|us-east-1|
|オレゴン|us-west-2|
|ロンドン|eu-west-2|

---

# 4. なぜリージョンがあるの？

例えば

日本の会社なら

```
利用者

↓

東京
```

の方が速いです。

もし

```
利用者

↓

アメリカ
```

まで通信すると

遅くなります。

そのため

近いリージョンを選びます。

---

# 5. リージョンごとに独立している

東京と大阪は

別の環境です。

```
東京

EC2

S3

RDS
```

とは別に

```
大阪

EC2

S3

RDS
```

があります。

自動では共有されません。

---

# 6. リージョンをまたぐことはできる？

できます。

例えば

```
東京

↓

S3コピー

↓

大阪
```

や

```
東京

↓

RDSレプリカ

↓

大阪
```

などです。

災害対策（DR：Disaster Recovery）でよく利用されます。

---

# 7. Availability Zone（AZ）とは？

初心者が混同しやすい部分です。

リージョンの中には

**複数のAZ（Availability Zone）**

があります。

例えば

```
東京リージョン

├─AZ-a
├─AZ-c
├─AZ-d
```

など。

---

# 8. リージョンとAZの違い

```
東京リージョン

├─AZ1
├─AZ2
└─AZ3
```

つまり

**リージョン**

↓

大きな地域

**AZ**

↓

その中のデータセンター

です。

---

# 9. 実務ではAZを分ける

例えば

```
EC2①

↓

AZ1
```

```
EC2②

↓

AZ2
```

に置きます。

もし

AZ1が停電しても

AZ2が動きます。

---

# 10. 実際の構成

```
東京リージョン

┌───────────────┐
│ AZ-a          │
│ EC2           │
└───────────────┘

┌───────────────┐
│ AZ-c          │
│ EC2           │
└───────────────┘

ALB
```

ALBが

両方へ振り分けます。

---

# 11. リージョンは変更できる？

できます。

AWSコンソール右上に

```
東京
```

などがあります。

変更すると

表示されるEC2も変わります。

---

# 12. 「EC2が消えた！」はよくある勘違い

実は

```
東京

↓

EC2あり
```

なのに

```
大阪
```

へ切り替えると

何もありません。

初心者あるあるです。

---

# 13. リージョンごとに料金が違う

例えば

東京

↓

少し高い

アメリカ

↓

少し安い

ことがあります。

そのため

海外企業は

アメリカリージョンを使うこともあります。

---

# 14. よく使うAWSサービス

リージョン単位

- EC2
- RDS
- Lambda
- DynamoDB
- VPC
- ECS

ほとんどはリージョンごとのサービスです。

---

# 15. グローバルサービスもある

一方で

世界共通のサービスもあります。

例えば

- IAM
- Route 53
- CloudFront

これらは

**グローバルサービス**

です。

---

# 16. ACMだけ少し特殊

初心者がよく間違えるポイントです。

CloudFrontで使う証明書は

```
us-east-1

（バージニア北部）
```

に作ります。

一方

ALBなら

東京リージョンのALBには

東京リージョンで作った証明書を使います。

---

# 17. 実務での構成

```
東京リージョン

 Route53
     │
CloudFront
     │
    ALB
     │
 ┌───┴────┐
 ▼        ▼
EC2      EC2
AZ-a    AZ-c
     │
 DynamoDB
```

このように

1つのリージョン内で

複数AZを利用します。

---

# 18. 大規模サービスでは

さらに

```
東京リージョン

↓

大阪リージョン

↓

バックアップ
```

を行います。

地震などの災害対策です。

---

# 19. リージョン・AZ・EC2の関係

```
AWS

└── 東京リージョン
     │
     ├── AZ-a
     │     └── EC2
     │
     ├── AZ-c
     │     └── EC2
     │
     └── AZ-d
           └── EC2
```

つまり

**リージョン**

↓

大きな地域

↓

**AZ**

↓

データセンター

↓

**EC2**

↓

サーバー

という構造になります。

---

# 20. まとめ

- **リージョン = AWSのサービスを動かす地域**
- **AZ = リージョン内の独立したデータセンター**
- **EC2やRDSなどはリージョン単位で作成する**
- **高可用性のため、複数AZにシステムを配置するのが一般的**
- **災害対策では複数リージョンを利用することもある**

# あなたが開発している構成で考えると

現在のような構成であれば、

```
利用者
   │
Route 53（グローバル）
   │
CloudFront（グローバル）
   │
東京リージョン
   │
ALB
   │
EC2
   │
├─ S3
├─ DynamoDB
└─ CloudWatch
```

という流れになります。

つまり、**利用者は世界中からアクセスできますが、実際にアプリやデータが動いている場所は「東京リージョン」**ということです。

---

## 一言でまとめると

- **リージョン** = 「どこの地域（国・都市）でシステムを動かすか」
- **AZ** = 「その地域の中の独立したデータセンター」
- **EC2** = 「そのデータセンター内で動く仮想サーバー」

この3つの関係を理解すると、AWSのインフラ構成図がぐっと読みやすくなります。
