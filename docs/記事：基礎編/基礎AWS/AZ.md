AZは、

> **Availability Zone（アベイラビリティ・ゾーン）**

の略です。

簡単にいうと、

> **AWSリージョンの中にある、独立したデータセンターのまとまり**

です。

---

## リージョンとの関係

例えば、東京リージョンの中には複数のAZがあります。

```
AWS

└─ 東京リージョン
    ├─ AZ①
    ├─ AZ②
    └─ AZ③
```

- **リージョン**：東京、大阪、シンガポールなどの大きな地域
- **AZ**：その地域の中にある独立した設備群

という関係です。

---

## なぜ複数のAZがあるの？

1つの設備だけでシステムを動かすと、その場所で停電やネットワーク障害が起きたとき、サービスが止まってしまいます。

```
AZ①
└─ EC2

AZ①で障害
   ↓
EC2も停止
   ↓
サービス停止
```

そこで、別のAZにもサーバーを置きます。

```
東京リージョン

AZ①             AZ②
EC2①            EC2②
```

AZ①に障害が起きても、AZ②のEC2②でサービスを続けられます。

---

## AWSでの構成例

```
              ALB
           ／     ＼
          ▼       ▼

AZ①                    AZ②
EC2①                   EC2②
```

ALBが正常なEC2へアクセスを振り分けます。

片方のAZが止まっても、もう片方で処理できます。

---

## AZ名の例

AWSでは、次のような名前で表示されます。

```
ap-northeast-1a
ap-northeast-1c
ap-northeast-1d
```

`ap-northeast-1` は東京リージョンを表し、最後の `a`、`c`、`d` がAZを表します。

ただし、同じ `1a` という表示でも、AWSアカウントによって実際の設備が異なる場合があります。

---

## AZは建物1つとは限らない

AZは単純に「データセンター1棟」という意味ではありません。

実際には、1つ以上のデータセンターで構成され、電源やネットワークなどが他のAZから独立するよう設計されています。

初心者の段階では、

> **AZ＝独立したデータセンターのエリア**

くらいの理解で問題ありません。

---

## AZとMulti-AZの違い

|用語|意味|
|---|---|
|AZ|リージョン内の独立したデータセンター群|
|Multi-AZ|複数のAZにシステムを配置する構成|
|Single-AZ|1つのAZだけを使う構成|

```
Single-AZ

AZ①
└─ EC2①
```

```
Multi-AZ

AZ①        AZ②
EC2①       EC2②
```

---

## 覚え方

```
世界
 ↓
リージョン
 ↓
AZ
 ↓
EC2などのAWSリソース
```

例えば、

```
東京リージョン
   ↓
AZ①・AZ②
   ↓
EC2・RDSなど
```

という関係です。

---

## 一言でまとめると

> **AZとは、AWSリージョン内にある、障害の影響を分けるための独立したデータセンター群です。**

複数のAZにEC2やデータベースを配置することで、1つのAZに障害が起きてもサービスを継続しやすくなります。
