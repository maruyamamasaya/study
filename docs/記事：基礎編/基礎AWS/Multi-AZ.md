# 1. Multi-AZとは？

Multi-AZ（マルチ・エーゼット）とは、

> **複数のAvailability Zone（AZ）にシステムを配置して、障害に強くする構成**

のことです。

簡単に言えば、

**「別々のデータセンターに予備を置くこと」**です。

---

# 2. まずAZ（Availability Zone）とは？

以前説明したように、

```
東京リージョン

├── AZ-a
├── AZ-c
└── AZ-d
```

AZは

> **リージョン内にある独立したデータセンター**

です。

それぞれ

- 電源
- ネットワーク
- 空調

などができるだけ独立しています。

---

# 3. 1つのAZだけだと？

例えば

```
東京リージョン

AZ-a

└── EC2
```

もしAZ-a全体が障害になると…

```
AZ-a

×

EC2停止
```

サービスも止まります。

---

# 4. Multi-AZなら？

別のAZにも配置します。

```
東京リージョン

AZ-a          AZ-c

EC2①         EC2②
```

AZ-aが停止しても

```
AZ-a ×

AZ-c ○
```

EC2②が動き続けます。

---

# 5. Webシステムでは

ALBと組み合わせます。

```
             ALB
          ／      ＼
         ▼        ▼
AZ-a            AZ-c

EC2①          EC2②
```

ALBは

正常なEC2だけへ通信を送ります。

---

# 6. EC2が故障したら？

例えば

```
EC2①

×

故障
```

すると

```
ALB

↓

EC2②
```

へ通信を切り替えます。

利用者はほとんど気付きません。

---

# 7. AZ全体が止まったら？

例えば

```
AZ-a

停電
```

になっても

```
AZ-c

正常
```

なので

サービスは継続できます。

これがMulti-AZ最大のメリットです。

---

# 8. RDSのMulti-AZ

データベースでは

さらに重要です。

```
AZ-a

Primary DB
```

↓

同期

↓

```
AZ-c

Standby DB
```

常にデータが同期されています。

---

## 障害時

```
Primary DB

×

故障
```

↓

```
Standby

↓

Primaryへ昇格
```

これを

**フェイルオーバー**

といいます。

---

# 9. EC2のMulti-AZとRDSのMulti-AZの違い

### EC2

```
ALB

↓

EC2①

EC2②
```

どちらも利用者のリクエストを処理できます（アクティブ・アクティブ構成が一般的）。

---

### RDS

```
Primary

↓

Standby
```

通常は

Primaryだけ使います。

Standbyは待機です（アクティブ・スタンバイ構成）。

---

# 10. Multi-AZとSingle-AZ

### Single-AZ

```
AZ-a

EC2
```

障害で止まります。

---

### Multi-AZ

```
AZ-a      AZ-c

EC2①      EC2②
```

片方が止まっても動き続けます。

---

# 11. 実際のAWS構成

```
利用者
    │
Route53
    │
CloudFront
    │
ALB
  ┌─┴────┐
  ▼      ▼
AZ-a    AZ-c

EC2①    EC2②
    │
    ▼
RDS Multi-AZ
```

実務では

このような構成が非常に多いです。

---

# 12. Multi-AZとMulti-Regionの違い

よく間違えます。

### Multi-AZ

```
東京リージョン

AZ-a

AZ-c
```

同じリージョン内です。

---

### Multi-Region

```
東京

↓

大阪
```

リージョン自体を分けます。

---

## 比較

|Multi-AZ|Multi-Region|
|---|---|
|同じリージョン|別リージョン|
|AZ障害に強い|リージョン障害に強い|
|レイテンシが低い|災害対策（DR）向き|

---

# 13. メリット

✅ サービスが止まりにくい

✅ AZ障害でも継続できる

✅ フェイルオーバーできる

✅ 高可用性（HA）が実現できる

---

# 14. デメリット

❌ コストが上がる

❌ 構成が少し複雑になる

❌ データ同期が必要になる場合がある

---

```
EC2 1台
```

だけなら

# 16. 関連用語

|用語|意味|
|---|---|
|Region|地域（東京・大阪など）|
|AZ|データセンター|
|Multi-AZ|複数AZへ配置|
|HA|高可用性|
|冗長化|予備を用意する|
|フェイルオーバー|障害時に切り替える|
|ALB|通信を振り分ける|

# 覚え方

```
AWS

└── 東京リージョン
      │
      ├── AZ-a
      │      └── EC2①
      │
      └── AZ-c
             └── EC2②
```

- **リージョン** = 大きな地域
- **AZ** = 独立したデータセンター
- **Multi-AZ** = 複数のデータセンターに分散配置すること

---

# 一言でまとめると

> **Multi-AZとは、「同じリージョン内の複数のデータセンター（AZ）にシステムを配置し、1つのAZが故障してもサービスを継続できるようにする仕組み」です。**

AWSで高可用性（HA）を実現する際の基本となる考え方で、EC2・RDS・ALBなどと組み合わせて利用されます。
