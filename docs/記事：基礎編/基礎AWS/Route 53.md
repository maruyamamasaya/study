実は **Route 53 の「53」は、DNSで使われるポート番号 53** が由来です。

---

## 結論

> **Route 53 = 「DNS（ポート53）でルーティングするサービス」**

つまり名前そのものが、

- **Route** = 通信を目的地へ案内する
- **53** = DNSが利用するポート番号

という意味になっています。

---

# DNSとは？

例えばブラウザで

```
https://example.com
```

へアクセスすると、

コンピューターは

```
example.com
```

では通信できません。

実際には

```
18.64.xxx.xxx
```

のようなIPアドレスへ変換する必要があります。

その変換を行うのが

**DNS（Domain Name System）**

です。

```
example.com

      │

      ▼

DNS

      │

      ▼

18.64.10.20
```

---

# なぜポート53？

ネットワークでは、

通信相手だけでなく「どのサービスに届けるか」を示すために**ポート番号**を使います。

代表的なものは次の通りです。

|ポート番号|サービス|
|---|---|
|20・21|FTP|
|22|SSH|
|25|SMTP（メール送信）|
|53|DNS|
|80|HTTP|
|110|POP3|
|143|IMAP|
|443|HTTPS|
|3306|MySQL|
|5432|PostgreSQL|

DNSは世界共通で**53番ポート**を使います。

---

# なぜ「Route」なの？

DNSは単にIPアドレスを返すだけではありません。

例えば

```
yasukari.com
```

へアクセスすると、

Route 53は

```
yasukari.com

      │

      ▼

ALBへ送る
```

あるいは

```
api.yasukari.com

      │

      ▼

EC2へ送る
```

というように、

**どこへアクセスを振り分けるか（Route）** を決めています。

---

# 実際の流れ

```
ブラウザ

↓

https://yasukari.com

↓

Route 53（DNS）

↓

ALB

↓

EC2

↓

Node.js

↓

DynamoDB
```

この最初の「住所案内」を担当しているのがRoute 53です。

---

# 実は53はAWSが決めた数字ではない

AWSが53という番号を選んだのではなく、

**DNSという技術で昔から53番ポートが標準**として使われていました。

AWSはそれにちなんでサービス名を

> **Route 53**

と名付けています。

---

# 覚え方

```
Route 53

Route
↓
通信の案内人

53
↓
DNSのポート番号
```

つまり、

> **「インターネット上で名前（ドメイン）を目的地へ案内するサービス」**

という意味になります。

---

## AWS全体で見ると

```
https://yasukari.com
        │
        ▼
 Route 53（ドメイン→IPへ変換）
        │
        ▼
 ALB（アクセスを振り分ける）
        │
        ▼
 EC2（Webサーバー）
        │
        ▼
 DynamoDB・S3
```

この流れを理解すると、「Route 53はWebサイトへの入口を担当するサービス」という位置付けがイメージしやすくなります。
