AWSにおける**AZ（Availability Zone：アベイラビリティゾーン）**とは、

> **AWSデータセンターをグループ化した「障害に強い単位」**

です。

簡単に言うと、

> **「1つのリージョンの中にある、独立したデータセンター群」**

です。

---

# イメージ

例えば東京リージョン。

```
東京リージョン (ap-northeast-1)

├── AZ-a
├── AZ-c
├── AZ-d
└── AZ-e
```

※実際のAZ名はアカウントごとに対応が異なるため、「ap-northeast-1a」が必ず同じ物理設備を指すとは限りません。

---

# リージョンとの違い

```
世界
│
├── 東京リージョン
│      ├── AZ1
│      ├── AZ2
│      └── AZ3
│
├── 大阪リージョン
│      ├── AZ1
│      ├── AZ2
│      └── AZ3
│
└── バージニアリージョン
       ├── AZ1
       ├── AZ2
       └── AZ3
```

つまり、

- **リージョン** = 地域（東京・大阪・バージニアなど）
- **AZ** = その地域内の独立したデータセンター群

---

# なぜ分かれているの？

例えば、

```
EC2
│
└── 東京AZ1
```

だけだと、

もしAZ1全体が停電したら

```
EC2
↓
停止
```

になります。

---

そこで、

```
AZ1
EC2

AZ2
EC2
```

のように配置すると、

AZ1が落ちても

```
AZ1
×

AZ2
〇
```

でサービスを継続できます。

これを**高可用性（High Availability）**と呼びます。

---

# 実務ではどう使う？

例えばWebサービスなら、

```
利用者
      │
      ▼
ALB
 ├─────────┐
 ▼         ▼
AZ1       AZ2
EC2       EC2
```

ALB（Application Load Balancer）が、

利用者を

- AZ1のEC2
- AZ2のEC2

へ振り分けます。

AZ1が停止したら

```
ALB

↓

AZ2だけへ転送
```

となります。

---

# RDSも同じ

RDSも

```
AZ1
Primary

AZ2
Standby
```

という構成にできます。

```
Primary

↓

障害

↓

Standbyへ切替
```

これを**Multi-AZ構成**といいます。

---

# S3は？

S3はさらに強力で、

保存した瞬間に

```
AZ1

AZ2

AZ3
```

へ自動で複製されます。

そのため

AZが1つ止まっても

データは失われません。

---

# あなたの予約システムなら

今の構成はおそらく

```
利用者

↓

Route53

↓

ALB

↓

EC2

↓

Next.js

↓

DynamoDB
```

になっています。

ここで

EC2が1台だけなら

```
EC2
(AZ1)
```

です。

もし

```
AZ1
```

が障害になると

サイトも停止します。

---

本番サービスとして可用性を高めるなら、

```
ALB
│
├── EC2（AZ1）
└── EC2（AZ2）
```

のように**複数AZ**へ配置するのが一般的です。

---

# まとめ

|用語|意味|
|---|---|
|リージョン|AWSのサービス提供地域（東京・大阪など）|
|AZ（Availability Zone）|リージョン内の独立したデータセンター群|
|目的|障害が発生してもサービスを継続するため|
|よく使うサービス|EC2、RDS、ALB、EFS など|

## 覚え方

- **リージョン = 都市**
- **AZ = その都市にある複数の大規模データセンター群**

例えば「東京リージョン」は「東京」という地域全体を表し、その中に複数のAZがあり、それぞれが独立した電源・ネットワークを持つことで、一部に障害が起きても他のAZでサービスを継続できるよう設計されています。
