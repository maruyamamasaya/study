
**初心者向け勉強会資料（AWSのリレーショナルデータベースサービス）**

---

# 1. Amazon RDSとは？

Amazon RDS（Relational Database Service）は、

> **AWSがデータベースの運用を代わりに管理してくれるサービス**

です。

通常、データベースを使うには

- サーバーを用意
- DBソフトをインストール
- バックアップ
- 障害対応
- アップデート

など、多くの運用作業が必要です。

RDSなら、それらの多くをAWSが自動化してくれます。

---

# 2. データベースとは？

データベースとは、

> **データを整理して保存する場所**

例えばネットショップなら

|テーブル|保存する内容|
|---|---|
|users|会員情報|
|products|商品情報|
|orders|注文情報|
|payments|支払い情報|

このようなデータを管理します。

# 6. Auroraとは？

Auroraは

> **AWSが独自に開発した高速なRDS**

です。

特徴

- MySQL互換
- PostgreSQL互換
- 高速
- 自動で冗長化
- 高可用性

大規模サービスでよく利用されます。

# 24. RDSとDynamoDBはどう使い分ける？

### RDSが向いているケース

- 会員と予約を関連付けたい
- JOINを多用する
- SQLで複雑な集計をしたい
- 売上レポートを作る
- トランザクションが重要

### DynamoDBが向いているケース

- アクセス数が非常に多い
- シンプルなキー検索が中心
- レスポンス速度を最優先したい
- サーバレス構成を採用したい

---

# まとめ

- **Amazon RDSはAWSのマネージドなリレーショナルデータベースサービス**
- **MySQL・PostgreSQL・Auroraなどを簡単に利用できる**
- **バックアップ・障害対応・パッチ適用などをAWSが管理してくれる**
- **SQLやJOINを活用する業務システムに適している**
- **ECサイト・予約システム・会員管理などで広く利用されている**

# 覚えておきたいキーワード

|用語|一言で説明|
|---|---|
|RDS|AWSのマネージドDBサービス|
|SQL|データベースを操作する言語|
|Table|データを保存する表|
|Row|1件分のデータ|
|Column|データの項目|
|Primary Key|データを一意に識別するキー|
|Foreign Key|他テーブルとの関連を示すキー|
|JOIN|複数のテーブルを結合する|
|Transaction|一連の処理をまとめて成功・失敗させる仕組み|
|Multi-AZ|障害に備えて別AZへ自動待機する構成|
|Read Replica|読み込み負荷を分散する複製DB|
|Snapshot|手動で取得するバックアップ|
|Aurora|AWS独自の高性能リレーショナルDB|
|Parameter Group|DBの設定値を管理する仕組み|
|Security Group|RDSへの通信を制御するファイアウォール|

> **実務のイメージ**  
> 「**Cognitoでログイン → API GatewayでAPI受付 → LambdaやEC2で業務処理 → RDSに予約・会員・注文データを保存**」という構成は、AWS上でWebサービスを開発する際の代表的なアーキテクチャです。RDSはその中で、**重要な業務データを安全かつ確実に保存する役割**を担っています。
