**初心者向け勉強会資料（AWSの認証・ユーザー管理サービス）**

---

# 1. Amazon Cognitoとは？

Amazon Cognitoは、

> **ユーザーのログイン・会員管理・認証を簡単に実現できるAWSのサービス**

です。

例えば、

- Webサイト
- スマホアプリ
- 社内システム
- 会員サイト

などで

- 新規登録
- ログイン
- パスワードリセット
- メール認証
- 多要素認証（MFA）

を簡単に実装できます。

---

# 6. Cognitoの構成

大きく2種類あります。

## User Pool

会員情報を保存する場所

```
名前

メール

パスワード

電話番号
```

などを保存します。

---

## Identity Pool

AWSサービスへアクセスする権限を与えるもの

例えば

```
S3へ画像アップロード
```

などです。

現在は **IAM Identity Center や直接IAMロール連携** を使うケースも増えていますが、Identity Poolは「アプリのユーザーにAWSリソースへの一時的な権限を付与する」用途で今も利用されています。

---


# 18. メリット・デメリット

|メリット|デメリット|
|---|---|
|認証機能を一から作らなくてよい|設定項目が多く、最初は理解に時間がかかる|
|AWSサービスとの連携が簡単|Hosted UIのデザイン変更には制約がある|
|セキュリティ機能が充実|独自の認証フローは工夫が必要な場合がある|
|スケーラブル|仕組み（JWT・OAuthなど）の理解が必要|

# 22. Yasukariでのログインの流れ（具体例）

例えばYasukariのような予約サービスでは、

```
① 会員登録
      │
      ▼
 Amazon Cognito
 （メール認証）
      │
      ▼
② ログイン
      │
      ▼
③ JWTトークン発行
      │
      ▼
④ API Gateway
 （JWTを検証）
      │
      ▼
⑤ Lambda
 （予約処理）
      │
      ▼
⑥ DynamoDB
 （予約情報を保存）
```

つまり、**Cognitoは「本人確認」だけを担当**し、その後の予約・決済・返却などの業務処理はLambdaなどのバックエンドが担当します。

---

# まとめ

- **Amazon CognitoはAWSの認証・ユーザー管理サービス**
- **ログイン・会員登録・メール認証・パスワードリセット・MFAなどを提供する**
- **ログイン後はJWTを発行し、API GatewayがそのJWTを検証する**
- **LambdaやEC2は認証後の業務処理を担当する**
- **AWSでWebサービスやスマホアプリを作る際によく採用される認証基盤**

# 覚えておきたいキーワード

|用語|一言で説明|
|---|---|
|User Pool|ユーザー情報を管理する仕組み|
|Identity Pool|AWSリソースへの一時的な権限を付与する仕組み|
|Hosted UI|Cognitoが提供するログイン画面|
|JWT|ログイン後に発行される認証トークン|
|Access Token|API利用の権限を示すトークン|
|ID Token|ログインしたユーザー情報を含むトークン|
|Refresh Token|Access Tokenの有効期限切れ後に再発行するためのトークン|
|OAuth 2.0|認証・認可の標準プロトコル|
|OpenID Connect (OIDC)|OAuth 2.0を拡張した認証の仕組み|
|MFA|多要素認証（二段階認証）|
|Hosted UI|Cognitoが提供するログイン・サインアップ画面|
|User Attributes|メールアドレス、名前、電話番号などのユーザー属性|
|User Groups|ユーザーをグループ分けして権限管理する機能|
|Federated Identity|GoogleやAppleなど外部認証と連携する仕組み|

> **実務のポイント**  
> AWSでWebアプリを構築する場合は、**「Cognito（認証）→ API Gateway（API入口・認可）→ Lambda/EC2（業務処理）→ DynamoDB/RDS（データ保存）」**という構成が非常によく採用されます。これを理解すると、多くのAWSアプリケーションの全体像が見えやすくなります。
