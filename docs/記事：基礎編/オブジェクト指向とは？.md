もちろんです。「オブジェクト化」が分かったなら、次は **オブジェクト指向** を理解するとJavaがかなり見やすくなります。

## オブジェクト指向とは？

一言でいうと、

> **プログラムを「役割を持ったモノ」の集まりとして設計する考え方**

です。

たとえばECサイトなら、

```text
ECサイト
│
├─ User（ユーザー）
├─ Product（商品）
├─ Cart（カート）
├─ Order（注文）
└─ Payment（決済）
```

というように、「ユーザー」「商品」「注文」などの単位に分けてシステムを作ります。

---

## たとえば「銀行口座」を作る

銀行口座には、

```text
銀行口座
├─ 口座名義
├─ 残高
│
├─ 入金する
└─ 出金する
```

というデータと処理があります。

Javaなら、

```java
class BankAccount {

    String owner;
    int balance;

    void deposit(int amount) {
        balance += amount;
    }

    void withdraw(int amount) {
        balance -= amount;
    }
}
```

そして、

```java
BankAccount account = new BankAccount();

account.owner = "田中";
account.balance = 10000;

account.deposit(5000);
```

すると、

```text
account
│
├─ owner   → "田中"
├─ balance → 15000
│
├─ deposit()
└─ withdraw()
```

という1つのオブジェクトとして扱えます。

これがオブジェクト指向の基本です。

# なぜわざわざオブジェクトに分けるの？

大きなシステムになると、

```text
ユーザー登録
商品検索
料金計算
注文
決済
メール送信
在庫更新
ログイン
```

など、いろいろな処理が出てきます。

全部を1か所に書くと、

```text
巨大なプログラム

ユーザー処理
決済処理
商品処理
メール処理
在庫処理
注文処理
...
```

となって、どんどん分かりにくくなります。

そこで、

```text
User
└─ ユーザーに関する責任

Order
└─ 注文に関する責任

Payment
└─ 決済に関する責任

Product
└─ 商品に関する責任
```

というように、**責任を分担させる**わけです。

これがオブジェクト指向を理解するうえでかなり重要です。

---

# オブジェクト同士が協力する

実際のシステムでは、1つのオブジェクトだけで処理するわけではありません。

たとえば商品購入なら、

```text
User
 │
 │ 商品を購入
 ↓
Order
 │
 │ 決済を依頼
 ↓
Payment
 │
 │ 決済成功
 ↓
Order
 │
 │ 注文完了
 ↓
MailService
    メール送信
```

このように、

> **それぞれのオブジェクトが自分の役割を担当しながら協力する**

のがオブジェクト指向です。

# オブジェクト指向の3大要素

Javaを勉強していると、よく次の3つが出てきます。

### ① カプセル化

**内部のデータを勝手に触らせない**考え方です。

例えばこれは危険です。

```java
account.balance = -1000000;
```

外部から残高を好き勝手に変更できています。

そこで、

```java
class BankAccount {

    private int balance;

    public void deposit(int amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}
```

とします。

外からは、

```java
account.deposit(5000);
```

という正しい入口を通して操作してもらいます。

イメージは、

```text
外部

   deposit(5000)
        ↓
┌────────────────┐
│ BankAccount    │
│                │
│ private balance│ ← 直接触らせない
│                │
└────────────────┘
```

です。

これが**カプセル化**です。

---

### ② 継承

既存のクラスをベースに、新しいクラスを作る仕組みです。

```java
class Animal {

    void eat() {
        System.out.println("食べる");
    }
}
```

これを、

```java
class Dog extends Animal {

    void bark() {
        System.out.println("ワン！");
    }
}
```

とすると、

```text
Animal
  │
  │ 継承
  ↓
 Dog

Dog
├─ eat()  ← Animalから受け継ぐ
└─ bark() ← Dog独自
```

となります。

```java
Dog dog = new Dog();

dog.eat();
dog.bark();
```

の両方が使えます。

---

### ③ ポリモーフィズム（多態性）

名前が難しいですが、

> **同じ命令でも、オブジェクトによって動作を変えられる**

という仕組みです。

例えば、

```java
class Animal {
    void speak() {
    }
}

class Dog extends Animal {
    void speak() {
        System.out.println("ワン！");
    }
}

class Cat extends Animal {
    void speak() {
        System.out.println("ニャー！");
    }
}
```

こうすると、

```java
Animal dog = new Dog();
Animal cat = new Cat();

dog.speak();
cat.speak();
```

結果は、

```text
ワン！
ニャー！
```

です。

同じ、

```java
speak();
```

という命令なのに、

```text
Dog → ワン！

Cat → ニャー！
```

と動作が変わります。

これがポリモーフィズムです。

---

# 「オブジェクト化」と「オブジェクト指向」の違い

ここを区別すると理解しやすいです。

**オブジェクト化**は、

```text
名前
年齢
メール
```

を、

```text
User
├─ name
├─ age
└─ email
```

のように、**1つのモノとしてまとめること**。

一方、**オブジェクト指向**はもっと大きな考え方で、

```text
システム
│
├─ User
│   └─ ユーザーを担当
│
├─ Product
│   └─ 商品を担当
│
├─ Order
│   └─ 注文を担当
│
└─ Payment
    └─ 決済を担当
```

のように、

> **システムを役割ごとのオブジェクトに分けて、それぞれを協力させて作る設計思想**

と考えるといいです。

Javaの場合、この考え方を実現するために、

```text
class
 ↓
object / instance
 ↓
フィールド・メソッド
 ↓
private / public
 ↓
カプセル化
 ↓
継承
 ↓
interface
 ↓
ポリモーフィズム
```

という機能を使っていきます。

特に次の **`interface`（インターフェース）** まで理解すると、「Javaがなぜオブジェクト指向言語なのか」がかなり見えてきます。
