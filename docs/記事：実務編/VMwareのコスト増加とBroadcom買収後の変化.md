
1. VMwareとは

VMwareは、1台の物理サーバー上で複数の仮想サーバー（VM）を動かすための仮想化基盤として広く利用されてきた。

代表的な製品が VMware ESXi / vSphere。

物理サーバー

  ↓

VMware ESXi

  ├─ VM① Windows Server

  ├─ VM② Linux

  ├─ VM③ Webサーバー

  └─ VM④ DBサーバー

物理サーバーをアプリケーションごとに用意する必要がなくなり、ハードウェアを効率的に利用できる。

  

2. 昔のVMwareはどういう料金体系だった？

Broadcomによる買収以前は、

必要なVMware製品を購入し、保守契約を結びながら長期間利用する

という使い方が一般的だった。

永続ライセンスが中心

一度ライセンスを購入すれば、そのライセンス自体は継続して利用できた。

ライセンス購入

    ↓

VMware環境を構築

    ↓

毎年サポート・保守費を支払う

    ↓

数年間利用

    ↓

EOL・ハードウェア更改

    ↓

次期VMware環境へ移行

そのため企業としても、

「VMwareを導入して、5年程度使って、次の更改時期にまた考える」

という計画を立てやすかった。

  

3. CPUソケット単位のライセンス

以前は長く、CPUソケットを基準としたライセンス体系が使われていた。

例えば、

物理サーバー

  

CPU①

CPU②

  

↓

2ソケット

というサーバーなら、基本的にはCPUソケットを基準に必要ライセンスを考える。

その上に、

VM①

VM②

VM③

VM④

VM⑤

...

と複数のVMを構築する。

そのため、単純に

「VMが10台だからVMwareライセンスも10個必要」

という仕組みではなかった。

  

4. BroadcomによるVMware買収

2023年、BroadcomがVMwareを約690億ドルで買収した。

この買収後、VMwareの製品体系・販売方法・ライセンス体系が大きく変更された。

重要なのは、

「VMwareの技術が突然高価になった」

というより、

BroadcomがVMwareのビジネスモデルを大きく変更した

という点。

  

5. VMwareのコストが増加した主な理由

大きく整理すると、

① 永続ライセンス

        ↓

   サブスクリプション

  

② CPUソケット中心

        ↓

   CPUコア数中心

  

③ 必要な製品を個別購入

        ↓

   製品バンドル

  

④ 幅広い顧客への販売

        ↓

   大企業・大規模環境を重視

という変化がある。

  

6. 永続ライセンス → サブスクリプション

昔は、

最初にライセンス購入

        ↓

保守費を支払う

        ↓

長期間利用

という形だった。

現在はサブスクリプション中心になっている。

契約

 ↓

1年間利用

 ↓

更新

 ↓

1年間利用

 ↓

更新

 ↓

...

つまり、

利用し続ける限り継続的にライセンス料金が発生する

モデルになった。

企業にとっては、従来の保守更新とはコスト構造が変わることになる。

  

7. CPUソケット → CPUコア数

ここも重要な変更点。

例えば、

CPU①：32コア

CPU②：32コア

という物理サーバーがあったとする。

合計すると、

32 + 32

= 64コア

となる。

昔は、

2 CPUソケット

という考え方が中心だった。

現在は、

64 CPUコア

を基準にライセンス費用が計算される契約体系が中心となっている。

最近のCPUは、

8コア

16コア

32コア

64コア

...

と多コア化している。

そのため、高性能な物理サーバーを利用している企業ほどライセンス費用への影響が大きくなる可能性がある。

  

8. 製品のバンドル化

以前は比較的、

「この機能が必要だから、このVMware製品を購入する」

という選択がしやすかった。

Broadcom買収後は製品体系が整理され、

VMware Cloud Foundation（VCF）

などを中心としたバンドル販売が強化された。

イメージすると、

昔

  

必要な機能

A ○

B ○

C ×

D ×

  

→ AとBを購入

から、

現在

  

A

B

C

D

  

↓

まとめた製品として契約

という方向。

企業によっては、

「そこまで機能はいらないんだけど……」

という場合でも、以前より大きな契約になる可能性がある。

  

9. そもそも、なぜBroadcomは高価格化したのか？

ここが重要。

単純に、

「VMwareの維持費が高くなったから値上げした」

という話だけではない。

BroadcomはVMwareを、

広く販売するソフトウェアから、大企業・重要システムを中心とした高収益なインフラ事業へ変える

という戦略を進めていると考えると理解しやすい。

  

10. 理由① VMware買収から大きな利益を生み出す

BroadcomはVMwareを約690億ドルという非常に大きな金額で買収した。

当然、企業としては、

VMware買収

   ↓

事業効率化

   ↓

売上・利益を拡大

   ↓

投資を回収

する必要がある。

VMwareは企業の重要システムに深く組み込まれていることが多い。

例えば、

VMware

 ├─ Windows Server × 100

 ├─ Linux × 200

 ├─ DB × 50

 └─ その他 × 100

という環境だった場合、

「VMwareが高くなったから来月AWSへ全部移行しよう」

とはできない。

移行には、

- 設計
- 移行先選定
- アプリケーション調査
- ネットワーク設計
- データ移行
- テスト
- 切り替え
- 障害対策

などが必要になる。

つまり、既存顧客が簡単にはVMwareから離れられないという特徴がある。

  

11. 理由② 顧客数より1社あたりの収益を重視

従来のVMwareは、

小規模企業

中規模企業

大企業

超大規模企業

まで非常に幅広い顧客を持っていた。

Broadcomはここから、

大量の顧客

×

比較的小さな契約

よりも、

重要な大企業

×

大規模な契約

を重視する方向へ進めている。

契約・製品・サポート体系を整理することで、

1社あたりの売上・利益を高める

ことができる。

  

12. 理由③ サブスクリプションで収益を安定させる

買い切り型ソフトウェアには、

2025年：大量に売れた

2026年：あまり売れなかった

2027年：大量に売れた

のように売上が変動しやすい問題がある。

サブスクリプションなら、

2025年：契約

   ↓

2026年：更新

   ↓

2027年：更新

   ↓

2028年：更新

となる。

企業側からすると、

毎年どのくらいの売上が入るのか予測しやすい

というメリットがある。

BroadcomとしてはVMwareを、継続的に収益・キャッシュを生み出す事業にしやすくなる。

  

13. VMware利用企業では何が起きている？

料金体系が変わったことで、企業側では、

VMware更新費用を確認

       ↓

「以前より高い」

       ↓

「本当にVMwareを継続する必要がある？」

       ↓

他の選択肢を調査

という流れが起きる。

代表的な選択肢として、

VMwareを継続

または、

Hyper-V

Nutanix AHV

Proxmox VE

その他の仮想化基盤

への移行。

さらに、

VMware

   ↓

AWS / Azure / GCP

と、パブリッククラウドへ移行する選択肢もある。

  

14. 「VMware脱却」がインフラ案件になる理由

VMwareから別基盤へ移行するといっても、単純にVMをコピーすれば終わりではない。

まず既存環境を調査する。

現在のVM数は？

OSは？

CPU・メモリは？

ストレージ容量は？

ネットワーク構成は？

DBは？

バックアップは？

監視は？

ジョブ管理は？

他システムとの通信は？

その上で移行先を検討する。

既存VMware

    ↓

 ┌───────────────┐

 │ VMware継続     │

 │ Hyper-V        │

 │ Nutanix AHV    │

 │ Proxmox VE     │

 │ AWS            │

 │ Azure          │

 └───────────────┘

そして、

現行調査

 ↓

移行方式検討

 ↓

設計

 ↓

新環境構築

 ↓

テスト

 ↓

データ移行

 ↓

切り替え

 ↓

旧VMware環境廃止

というプロジェクトになる。

  

15. インフラエンジニアに求められること

VMwareの価格体系変更は、インフラエンジニアにとって単なる「値上げニュース」ではない。

重要なのは、

既存環境を理解して、次の基盤へ安全に移行できる能力

である。

例えば、

- VMware / ESXi
- Windows Server
- Linux
- ネットワーク
- ストレージ
- バックアップ
- 監視
- AWS / Azure
- 仮想化
- サーバー構築
- 移行設計
- バージョン管理
- EOL対応
- 変更管理

などの知識がつながってくる。

19. 一言で覚えるなら

昔のVMware

必要なライセンスを購入して、保守費を払いながら長く使う仮想化基盤

現在のVMware

Broadcom買収後、サブスクリプション・コア課金・製品バンドルを中心とした高収益型のビジネスモデルへ大きく転換した

企業側への影響

VMwareをそのまま更新するより、他の仮想基盤やAWS/Azureへ移行した方がよいのではないか、という基盤更改の検討が増えている。

エンジニア側への影響

VMwareそのものの知識だけでなく、既存環境を調査し、バージョン・互換性・EOL・変更ワークフローを管理しながら、新しい基盤へ移行できる能力が重要になっている。
