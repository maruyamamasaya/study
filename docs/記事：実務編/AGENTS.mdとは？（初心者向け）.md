## 概要

**AGENTS.md** は、AI開発エージェント（Claude Code、Cursor、GitHub Copilot Agent、Codexなど）に対して、
**「このプロジェクトではこういうルールで開発してください」** と伝えるための設定ファイルです。

人間向けの **README.md** があるように、AI向けには **AGENTS.md** を用意するイメージです。

近年ではAIがコードを書くだけでなく、ファイル検索・修正・テスト・コミットまで行うようになってきたため、
AIにも「開発ルール」を共有することが重要になっています。

---

# なぜ必要なの？

例えば毎回AIに

- 日本語で回答してください
- TypeScriptで実装してください
- App Routerを使ってください
- anyは禁止です
- Tailwind CSSを使ってください
- テストも作成してください

と伝えるのは大変です。

AGENTS.mdを置いておけば、

> AIは最初にこのファイルを読んでから作業を開始する

ため、毎回同じ指示を書く必要がありません。

---

# 人間で例えると

新しく入社したエンジニアに

「この会社ではこういうルールで開発しています」

という資料を渡します。

例えば

- ブランチ運用
- 命名規則
- フォルダ構成
- コーディングルール
- コミットルール

などです。

AGENTS.mdは

**AI版の新人教育マニュアル**

と言えます。

---

# AIはどう使うの？

例えば

「ログイン画面を作って」

とお願いするとします。

もしAGENTS.mdが無い場合

AIは

```
Reactで作ろうかな
JavaScriptでいいかな
CSS Modulesかな
Bootstrapかな
```

と推測しながら実装します。

しかし

AGENTS.mdに

```
Next.js App Router
TypeScript
Tailwind CSS
Server Components優先
```

と書いてあれば

AIは最初からそのルールに従います。

つまり

**迷わず開発できるようになる**

ということです。

---

# 実務では何を書く？

一般的には次のような内容を書きます。

## ① プロジェクト概要

```
これは予約システムです。
Next.jsで構築しています。
```

---

## ② 使用技術

```
Next.js
TypeScript
Tailwind CSS
Supabase
AWS
```

AIは

「どの技術を使えばいいか」

を理解できます。

---

## ③ ディレクトリ構成

```
app/
components/
hooks/
lib/
types/
```

例えば

```
Buttonを作るなら

components/ui
```

という判断ができます。

---

## ④ コーディングルール

例

```
TypeScript strict

anyは禁止

ESLintエラー禁止

Server Components優先
```

AIはこれらを守って実装します。

---

## ⑤ 命名規則

例えば

```
コンポーネント

PascalCase

UserCard.tsx
```

```
Hooks

useAuth.ts
```

```
API

kebab-case
```

などを書きます。

---

## ⑥ Gitルール

例

```
feature/

fix/

hotfix/
```

コミット例

```
feat:
fix:
docs:
refactor:
```

AIもこのルールでコミットできます。

---

## ⑦ テストルール

```
実装後は必ず

npm test

を実行

Lintも実行

型エラーゼロ
```

Agentは実際にコマンドを実行できます。

# 実務ではどんなことを書く？

例えばECサイトなら

```
商品一覧はServer Component

画像はImageコンポーネント

APIはRoute Handler

データ取得はServer Action

DBはSupabase

状態管理はZustand

anyは禁止

console.logは禁止
```

予約システムなら

```
予約時間の重複チェック必須

決済完了前は予約を確定しない

返金APIを必ず呼ぶ

時刻はUTC保存

画面表示はJST
```

会社ごとの独自ルールも記載できます。

以前は

```
開発ルール

↓

人が読む
```

だけでした。

現在は

```
開発ルール

↓

```

両方が読む時代です。

そのため

「AIにも理解できる形でルールを書く」

ことが、新しい開発スタイルになりつつあります。
