## 概要

AI開発では、Slack・GitHub・Notion・ブラウザ・ファイル管理などの外部ツールを **MCP（Model Context Protocol）** を使って接続できます。

しかし、「便利そうだから全部つないでおこう」という使い方は、かえってAIの性能を下げる原因になります。

---

# なぜ問題なの？

MCPサーバーを接続すると、AIは各ツールの機能や使い方（ツール定義）を読み込みます。

接続するツールが増えるほど、その情報もコンテキストに含まれるため、次のような影響が出ることがあります。

- 使えるコンテキスト（トークン）が減る
- AIがどのツールを使うべきか迷いやすくなる
- 関係ないツールまで考慮してしまう
- 応答速度や判断精度が低下する場合がある

つまり、

> **使わないツールまで毎回読み込むことで、AIの処理効率が悪くなる**ということです。

---

# イメージ

## 悪い例

```
今日の作業：コード修正

接続中
├ GitHub
├ Slack
├ Notion
├ Google Drive
├ Browser
├ Calendar
├ Gmail
├ Files
└ その他多数...
```

実際にはGitHubしか使わないのに、AIはすべてのツールを考慮しながら処理することになります。

---

## 良い例

```
今日の作業：コード修正

接続中
├ GitHub
└ Files
```

必要なツールだけを接続することで、AIはより効率的に作業できます。

---

# Deferred Tool Loadingとは？

**Deferred Tool Loading（遅延ロード）** は、必要になるまでツールの詳細情報を読み込まない仕組みです。

### 従来

```
チャット開始

↓
全ツールを読み込む

GitHub
Slack
Notion
Browser
Files
...
```

最初からすべて読み込むため、コンテキストを多く消費します。

---

### Deferred Tool Loading

```
チャット開始

↓
必要最低限だけ読み込む

↓

GitHubが必要
↓

GitHubだけ読み込む
```

必要になったタイミングでツールを読み込むため、開始時の負荷を大きく減らせます。

# 実務での使い分け

## コードレビューの日

```
使うもの
✅ GitHub
✅ Files

使わないもの
❌ Slack
❌ Notion
❌ Browser
```

---

## ドキュメント作成の日

```
使うもの
✅ Notion
✅ Files

使わないもの
❌ GitHub
❌ Browser
```

---

## 情報調査の日

```
使うもの
✅ Browser
✅ GitHub

使わないもの
❌ Slack
❌ Calendar
```

---

# ベストプラクティス

- 作業内容に必要なMCPだけ接続する
- 使わないMCPは切断する
- 利用できる場合は **Deferred Tool Loading** を活用する
- 「とりあえず全部接続」は避ける

---

# まとめ

MCPは便利ですが、接続するツールが多いほど良いわけではありません。

不要なツールまで読み込むと、AIは余計な情報を抱えながら処理することになり、速度や判断精度に影響する場合があります。

そのため、

> **「必要なツールを、必要なときだけ接続する」**

という運用が、現在のAI開発では推奨されています。
