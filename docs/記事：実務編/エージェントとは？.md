AI開発における**エージェント（Agent）**と**サブエージェント（Sub-agent）**は、一言でいうと

> **「AIが自分で考えて仕事を進める単位」と、「その仕事を分担する専門チーム」**です。

最近のClaude Code、Codex、OpenAI Agents SDK、LangGraph、CrewAIなどでよく出てくる考え方です。

---

# エージェントとは？

エージェントは

> **目的を達成するために、自分で考えて行動できるAI**

です。

普通のChatGPTとの違いは、

- 目的がある
- 必要なら検索する
- 必要ならコードを書く
- 必要ならファイルを読む
- 必要なら別AIへ依頼する

というように、

**「考える→実行→確認→修正」**

を繰り返せます。

例えば

```
「ECサイトを作って」
```

と言われると

```
目的を理解
↓

設計

↓

必要なファイルを作る

↓

実装

↓

テスト

↓

エラー修正

↓

完成
```

まで進めようとします。

---

# イメージ

```
人間
 │
 ▼
Agent
 │
 ├──検索
 ├──コード生成
 ├──Git操作
 ├──テスト
 └──修正
```

つまり

**AI一人が全部やる**

のがAgentです。

---

# サブエージェントとは？

サブエージェントは

> **仕事を専門分野ごとに分担するAI**

です。

例えば

```
ECサイトを作る
```

と言われたら

```
メインAgent

↓

設計担当
↓

UI担当

↓

API担当

↓

DB担当

↓

テスト担当
```

みたいに分けます。

# なぜ分けるの？

理由は3つあります。

## ①専門知識を持たせられる

例えば

Frontend Agent

```
React
Next.js
Tailwind
```

だけ知っていればいい。

---

Backend Agent

```
Go

Java

認証

API
```

だけ詳しければいい。

---

## ②並列実行できる

一人でやると

```
画面

↓

API

↓

DB
```

ですが、

サブエージェントなら

```
画面

API

DB
```

を同時に作れます。

なので速いです。

---

## ③責任範囲が明確

例えば

```
UIがおかしい
```

なら

```
Frontend Agent
```

だけ直せばいい。

# Claude CodeやCodexでは？

Claude CodeでもCodexでも、

メインのAIが必要に応じて役割を分けて進める設計が採用されています。

例えば

```
READMEを書いて

↓

コード生成

↓

ユニットテスト

↓

CI確認

↓

PR作成
```

という一連の流れを、それぞれ得意分野の役割に分けて処理するイメージです。

## まとめ

|用語|役割|人間で例えると|
|---|---|---|
|エージェント (Agent)|目的を理解し、自律的に計画・実行するAI|プロジェクトマネージャー兼エンジニア|
|サブエージェント (Sub-agent)|特定分野を担当する専門AI|フロントエンド担当、バックエンド担当、テスターなど|
|メリット|並列処理・専門性・保守性の向上|チーム開発と同じ考え方|

重要なのは、**サブエージェントは独立したAIというより、「特定の役割や責任を持つAIの単位」と考えると理解しやすい**という点です。メインエージェントが全体を管理し、必要に応じてサブエージェントへ仕事を割り振り、その結果をまとめて最終成果物を完成させます。
