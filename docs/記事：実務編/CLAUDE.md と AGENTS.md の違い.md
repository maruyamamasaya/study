結論から言うと、

> **役割はほぼ同じですが、「誰に読ませるか」が違います。**

最近は **AGENTS.md を共通ルール**にして、必要なら **CLAUDE.md をClaude専用設定**として追加するケースが増えています。

---

# CLAUDE.md と AGENTS.md の違い

|項目|CLAUDE.md|AGENTS.md|
|---|---|---|
|対象|Claude Code|複数のAIエージェント|
|用途|Claude専用ルール|プロジェクト共通ルール|
|移植性|Claude向け|AIが変わっても使いやすい|
|実務|Claudeだけ使うチーム|AIを複数使うチーム|

---

# CLAUDE.md

これは

> **Claude Codeだけに向けた説明書**

です。

例えば

```
CLAUDE.md
```

```
日本語で回答してください

TypeScript strict

npmを使ってください

テストを書いてください
```

Claudeはこれを読んで開発します。

もしCursorを使っても、

GitHub Copilotを使っても、

このファイルは基本的に読まれません。

---

# AGENTS.md

こちらは

> **AI全体向けの説明書**

です。

例えば

```
AGENTS.md
```

```
このプロジェクトはNext.jsです。

anyは禁止

Tailwind CSS

Server Component優先

ESLintエラー禁止
```

AIエージェント全体で共有しやすいルールを書きます。

---

# イメージ

会社ルール

↓

社員全員
```

これが

```
AGENTS.md
```

---

一方

```
Claudeだけに教えること

↓

Claude社員だけ
```

これが

```
CLAUDE.md

# 実務ではどう使う？

例えば会社では

```
AGENTS.md

↓

・プロジェクト概要

・命名規則

・Gitルール

・アーキテクチャ

・テスト
```

を書きます。

そして

```
CLAUDE.md

↓

・Claudeが苦手な部分

・プロンプトのコツ

・回答は日本語

・長文禁止

・思考過程
```

など、

**Claudeだけに伝えたい内容**を書きます。

---

# どちらか一つでもいい？

もちろんOKです。

例えば

```
Claudeしか使わない
```

なら

```
CLAUDE.md
```

だけでも十分です。

逆に

```
Claude

Cursor

Copilot

Codex
```

全部使うなら

```
AGENTS.md
```

だけにまとめる方が管理しやすいでしょう。

# 最近の流れ

以前は

```
CLAUDE.md
```

を書く人が多かったですが、

AIツールが増えてきたため

```
AGENTS.md
```

という**共通のルールファイル**を採用するプロジェクトが増えています。

そのうえで、必要なら

```
AGENTS.md
    ↑
共通ルール

CLAUDE.md
    ↑
Claude専用の追加設定
```

という構成にするケースもあります。

---

# あなたの勉強用リポジトリなら？

今後、ChatGPT・Claude・Cursor・GitHub Copilotなど複数のAIを試す可能性があるなら、

```
AGENTS.md
```

をメインに作るのがおすすめです。

そこに

- プロジェクト概要
- Markdownの書き方
- 用語解説のフォーマット
- ディレクトリ構成
- 命名規則
- AIへの実装ルール

などをまとめておけば、どのAIでも共通の「開発ルール」として活用しやすくなります。

一方で、Claude Code固有の振る舞いを細かく調整したい場合だけ `CLAUDE.md` を追加する、という運用が現在の実務では分かりやすく、保守もしやすい方法です。
