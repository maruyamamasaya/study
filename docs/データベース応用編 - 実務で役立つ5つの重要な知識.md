# 概要

データベースは単に「データを保存する場所」ではありません。

実際のシステムでは、

- 同時に何万人ものユーザーがアクセスする
- データを壊さず更新する
- 大量データを高速に検索する
- 売上やアクセス数を集計する

といったことが求められます。

そのため、テーブルやJOINを覚えた次は、実務で頻繁に使われる応用知識を学ぶことが重要です。

今回は、現場でよく登場する以下の5つを紹介します。

| 項目 | 役割 |
|------|------|
| トランザクション | データを安全に更新する |
| SQL応用 | データを集計・分析する |
| 正規化 | テーブルを設計する |
| インデックス | データを高速検索する |
| ロック | 同時更新による事故を防ぐ |

---

# ① トランザクション（Transaction）

## 概要

トランザクションとは、

**「一連の処理をまとめて、全部成功するか、全部失敗するかを保証する仕組み」**

です。

銀行やECサイトでは必須の機能です。

---

## 基本的な仕組み

例えば銀行送金。

```
Aさん　1000円引く

↓

Bさん　1000円足す
```

もし途中でサーバーが停止すると…

```
Aさんだけ減った

Bさんには入金されていない
```

という大事故になります。

そこでトランザクションを使います。

```
BEGIN

↓

UPDATE

↓

UPDATE

↓

COMMIT
```

成功したら

```
COMMIT
```

途中で失敗したら

```
ROLLBACK
```

で最初の状態に戻します。

イメージ

```
開始
 ↓
処理①
 ↓
処理②
 ↓
成功？
 ↓
Yes → COMMIT
No  → ROLLBACK
```

---

## 具体例

```sql
BEGIN;

UPDATE account
SET balance = balance - 1000
WHERE id = 1;

UPDATE account
SET balance = balance + 1000
WHERE id = 2;

COMMIT;
```

途中でエラーになれば

```sql
ROLLBACK;
```

---

## 実務での使われ方

- ネット銀行
- クレジットカード決済
- ECサイト購入
- 在庫更新
- ポイント付与

データが壊れると困る処理では必ず使われます。

---

## 関連知識

- ACID特性
- COMMIT
- ROLLBACK
- SAVEPOINT

---

# ② SQL応用（GROUP BY・HAVING・サブクエリ）

## 概要

SQLは「データを取り出す」だけではありません。

**集計・分析**も得意です。

例えば

- 商品別売上
- 顧客ごとの注文数
- 人気ランキング

などもSQLだけで作れます。

---

## 基本的な仕組み

### GROUP BY

同じ値ごとにまとめる。

```
注文

A
A
A
B
B

↓

GROUP BY

A 3件

B 2件
```

---

### HAVING

集計後に条件を付けます。

```
購入数が5回以上だけ表示
```

---

### サブクエリ

SQLの中にSQLを書くことです。

```
一番高い商品の価格を取得

↓

その価格の商品を表示
```

---

## 具体例

### 商品ごとの売上件数

```sql
SELECT
  product_id,
  COUNT(*)
FROM orders
GROUP BY product_id;
```

---

### 10件以上売れた商品だけ

```sql
SELECT
  product_id,
  COUNT(*)
FROM orders
GROUP BY product_id
HAVING COUNT(*) >= 10;
```

---

### 平均以上の給与

```sql
SELECT *
FROM employee
WHERE salary >
(
    SELECT AVG(salary)
    FROM employee
);
```

---

## 実務での使われ方

- 売上レポート
- ダッシュボード
- GA4分析
- BIツール
- 管理画面

---

## 関連知識

- COUNT
- SUM
- AVG
- MAX
- MIN
- ORDER BY

---

# ③ 正規化・データベース設計

## 概要

正規化とは

**「データの重複をなくして管理しやすくする設計方法」**

です。

---

## 基本的な仕組み

悪い例

```
注文

注文ID
商品名
価格
説明
```

同じ商品を100回注文すると

```
価格
説明

が100回保存されます。
```

---

良い例

```
商品

商品ID
商品名
価格
```

```
注文

注文ID
商品ID
```

商品情報は1回だけ保存します。

---

## 具体例

```
商品テーブル

1 PC
2 マウス
3 キーボード
```

```
注文

100
商品ID=1

101
商品ID=2
```

これなら価格変更も

```
商品テーブルだけ
```

更新すればOKです。

---

## 実務での使われ方

- ECサイト
- 会員管理
- 社員管理
- 在庫管理
- 顧客管理

ほぼ全ての業務システムで使われています。

---

## 関連知識

- ER図
- 主キー
- 外部キー
- リレーション

---

# ④ インデックスとSQL高速化

## 概要

インデックスとは

**「本の目次」のようなもの**

です。

大量データから目的のデータを素早く探せます。

---

## 基本的な仕組み

インデックスなし

```
100万件

↓

1件ずつ探す
```

時間がかかります。

---

インデックスあり

```
100万件

↓

目次を見る

↓

目的だけ探す
```

かなり高速になります。

---

## 具体例

```sql
CREATE INDEX idx_email
ON users(email);
```

検索

```sql
SELECT *
FROM users
WHERE email='aaa@test.com';
```

インデックスがあると高速です。

---

## 実務での使われ方

- ログイン
- 商品検索
- 顧客検索
- 管理画面
- API

---

## 関連知識

- EXPLAIN
- Full Scan
- Index Scan
- Composite Index

---

# ⑤ ロック・同時更新（排他制御）

## 概要

ロックとは

**「複数人が同時にデータを書き換えないようにする仕組み」**

です。

---

## 基本的な仕組み

在庫が1個。

```
在庫1
```

同時に

```
Aさん購入

Bさん購入
```

すると

```
在庫-1
```

になる可能性があります。

そこで

```
Aさん更新中

↓

Bさん待機
```

という状態を作ります。

これがロックです。

---

## 具体例

```sql
SELECT *
FROM products
WHERE id = 1
FOR UPDATE;
```

このデータを他の人が更新できなくなります。

---

## 実務での使われ方

- 在庫管理
- チケット予約
- 銀行
- ポイント
- 決済システム

---

## 関連知識

- Shared Lock
- Exclusive Lock
- Deadlock
- Transaction

---

# 5つの関係性

```
          データベース

               │

   ┌───────────┼────────────┐

設計する      安全に更新する      高速に検索する

正規化       トランザクション     インデックス

                   │

             同時更新を防ぐ

                 ロック

                   │

            データを分析する

             GROUP BY
             HAVING
             サブクエリ
```

# まとめ

| テーマ | 一言でいうと |
|---------|-------------|
| トランザクション | データを壊さず更新する仕組み |
| SQL応用 | データを集計・分析する技術 |
| 正規化 | 重複のないテーブル設計 |
| インデックス | データ検索を高速化する仕組み |

# 学習のおすすめ順

```
① JOIN・主キー・外部キー
        ↓
② 正規化
        ↓
③ GROUP BY・HAVING・サブクエリ
        ↓
④ インデックス
        ↓
⑤ トランザクション
        ↓
⑥ ロック・排他制御
```

この流れで学ぶと、「データを保存する」だけでなく、「安全・高速・効率的に扱う方法」まで理解できるようになります。これらはECサイトやSNS、銀行システムなど、ほぼすべての業務システムで使われている重要な知識です。
