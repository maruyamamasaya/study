
| 手法        | 特徴                 | 覚え方     |
| --------- | ------------------ | ------- |
| インスペクション  | 役割・手順を決めて正式にレビュー   | 厳格なレビュー |
| ウォークスルー   | 作成者が説明しながら、みんなで確認  | 集まって説明  |
| パスアラウンド   | 成果物を複数人に回して確認してもらう | 回覧レビュー  |
| ペアプログラミング | 2人1組でリアルタイムに開発     | 2人で開発   |

## インスペクション

- **正式で厳格なレビュー手法**
- 参加者の役割やレビューの手順を決めて実施する
- 欠陥や問題点を体系的に発見することが目的
- 作成者以外が進行役（モデレータ）を担当することがある

**覚え方：ルールを決めてしっかりレビュー**

---

## ウォークスルー

- **作成者が成果物を説明**しながらレビューする
- 複数人が集まり、質問や意見を出す
- インスペクションほど厳格ではない

**作成者 → 説明 → みんなで確認**

**覚え方：作成者と一緒に内容を歩いて確認**

---

## パスアラウンド

- 資料やプログラムなどの成果物を**複数のレビュー担当者に回覧**する
- 各担当者が確認して、コメントや指摘を返す
- 全員が同じ場所・時間に集まる必要がない

**成果物 → Aさん → Bさん → Cさん**

**覚え方：資料を回してレビュー**

---

## ペアプログラミング

- **2人1組でプログラムを作成**する開発手法
- 1人がコードを書き、もう1人が内容を確認する
- 必要に応じて役割を交代する
- コーディングしながらリアルタイムにレビューできる

**2人 → 一緒にコーディング**

※厳密にはレビュー専用の手法ではなく、アジャイル開発などで使われる開発手法。

---

## 試験向けの覚え方

- **インスペクション** → 正式・厳格・役割あり
- **ウォークスルー** → 作成者が説明
- **パスアラウンド** → 成果物を回覧
- **ペアプログラミング** → 2人でコーディング
