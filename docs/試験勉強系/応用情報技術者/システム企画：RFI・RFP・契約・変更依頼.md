## 全体の流れ

システム導入・開発を外部ベンダーへ依頼する場合、大まかに次のように進む。

```text
システム化構想・企画
      ↓
RFI
「まず情報をください」
      ↓
情報収集・検討
      ↓
RFP
「この条件で提案してください」
      ↓
ベンダーから提案書
      ↓
評価・選定
      ↓
契約締結
      ↓
開発・導入
      ↓
必要なら変更依頼
```

---

# 1. RFI：情報提供依頼書

**RFI（Request For Information）**

ベンダーに対して、製品・サービス・技術などの**情報提供を依頼する文書**。

まだ具体的な提案を求める段階ではなく、

> **「どんな製品・技術・サービスがありますか？」**

と情報収集するイメージ。

## 例

会社が新しい勤怠管理システムを検討している。

```text
RFI

・どのような製品がありますか？
・どんな機能がありますか？
・クラウド対応していますか？
・導入実績はありますか？
・おおよその価格帯は？
```

複数ベンダーから情報を集め、システム化の方向性やRFP作成などに利用する。

> **RFI = まず情報をください**

---

# 2. RFP：提案依頼書

**RFP（Request For Proposal）**

発注候補のベンダーに対して、具体的なシステム・実現方法・費用などの**提案を依頼する文書**。

日本語では、

**提案依頼書**

と呼ばれる。

## 例

```text
RFP

以下の条件で勤怠管理システムを
提案してください。

・利用者：1,000人
・クラウド型
・スマートフォン対応
・既存給与システムと連携
・2027年4月までに導入

さらに、

・システム構成
・開発方法
・スケジュール
・費用
・保守体制

を提示してください。
```

ベンダーはRFPを基に**提案書**を作成する。

```text
発注者
  ↓
RFP（提案依頼書）
  ↓
ベンダー

ベンダー
  ↓
提案書
  ↓
発注者
```

> **RFP = この条件で具体的に提案してください**

---

# RFIとRFPの違い

ここは重要。

|       | RFI                     | RFP                  |
| ----- | ----------------------- | -------------------- |
| 正式名称  | Request For Information | Request For Proposal |
| 日本語   | 情報提供依頼書                 | 提案依頼書                |
| 目的    | 情報収集                    | 具体的な提案を受ける           |
| タイミング | 比較的早い                   | 方向性が固まった後            |
| 内容    | 製品・技術・実績など              | 方式・費用・納期など           |

覚え方は、

```text
RFI

I = Information
→ 情報ください


RFP

P = Proposal
→ 提案してください
```

---

# 3. 提案書

RFPを受け取った**ベンダー側が作成する文書**。

ここも混同しやすい。

```text
発注者
 ↓
RFP
「提案してください」
 ↓
ベンダー
 ↓
提案書
「こういうシステムはどうでしょう」
 ↓
発注者
```

提案書には例えば、

* システム構成
* 実現方法
* 開発体制
* スケジュール
* 費用
* 運用・保守
* 導入実績

などを記載する。

> **RFP = 発注者 → ベンダー**
>
> **提案書 = ベンダー → 発注者**

---

# 4. ベンダー評価・選定

各社から提出された提案書を比較する。

例えば、

| 評価項目 | A社 | B社 |
| ---- | -: | -: |
| 機能   |  ○ |  ◎ |
| 技術   |  ◎ |  ○ |
| 費用   |  ○ |  ◎ |
| 納期   |  ◎ |  ○ |
| 保守   |  ◎ |  ○ |

単純に最安値だけで決めるのではなく、

* 要求への適合度
* 技術力
* 実績
* 費用
* スケジュール
* 保守体制

などを総合的に評価する。

---

# 5. 契約締結

ベンダーを選定した後、契約内容について合意し**契約を締結する**。

例えば、

```text
・契約金額
・作業範囲
・成果物
・納期
・責任範囲
・検収条件
・支払条件
・著作権
・秘密保持
```

などを明確にする。

## 契約締結依頼書

組織によっては、契約締結のための**社内手続・承認を依頼する文書**として「契約締結依頼書」などを使用する。

ただし、RFI・RFPのように「この名称・形式が世界共通で決まっている」というものではなく、**組織内部の契約手続で使われる文書名**として考える。

> **契約締結依頼書 = 契約を締結するための社内手続・承認を進める文書**

---

# 6. 変更依頼書

プロジェクト開始後などに、

**要求・仕様・スコープなどを変更したい場合に、その変更を正式に依頼する文書**。

例えば、

```text
当初

ログイン
↓
ID・パスワードのみ

変更依頼

↓
多要素認証も追加したい
```

このような変更について、

```text
変更内容
   ↓
影響分析
   ↓
費用は増える？
納期は延びる？
品質への影響は？
   ↓
承認・却下
```

という変更管理を行う。

> **変更依頼書 = 決まった内容を後から変更したい**

---

# 提案依頼書と変更依頼書の違い

名前は似ているが、使う場面が違う。

### 提案依頼書（RFP）

```text
契約前など

「このシステムを
どう実現するか提案してください」
```

→ ベンダー選定などに利用

### 変更依頼書

```text
計画・開発などが進んだ後

「この仕様を変更したい」
```

→ 変更管理に利用

|      | 提案依頼書      | 変更依頼書        |
| ---- | ---------- | ------------ |
| 目的   | 提案を受ける     | 変更を依頼        |
| 主な場面 | ベンダー選定前    | 計画・開発中など     |
| 内容   | システムの要求・条件 | 仕様・スコープなどの変更 |
| 重要事項 | 提案内容の比較    | 変更による影響分析    |

---

# 一連の流れで理解

例えば「勤怠管理システムを導入したい」とする。

```text
① システム企画

「勤怠管理を効率化したい」

        ↓

② RFI

「どんな製品・サービスがありますか？」

        ↓

③ 情報収集

「クラウド型がよさそう」

        ↓

④ RFP

「1,000人規模・クラウド型で
具体的に提案してください」

        ↓

⑤ 提案書

A社「500万円でできます」
B社「600万円でできます」

        ↓

⑥ 評価・選定

「A社にしよう」

        ↓

⑦ 契約

費用・納期・成果物などを合意

        ↓

⑧ 開発・導入

        ↓

⑨ 変更依頼

「多要素認証も追加したい」

        ↓

⑩ 影響分析

費用＋50万円
納期＋2週間

        ↓

⑪ 承認して変更
```

# 試験用まとめ

| 用語          | 一言              |
| ----------- | --------------- |
| **RFI**     | 情報をください         |
| **RFP**     | 提案してください        |
| **提案書**     | ベンダーからの回答・提案    |
| **契約**      | 条件を合意して正式に発注    |
| **契約締結依頼書** | 契約締結の社内手続・承認を依頼 |
| **変更依頼書**   | 決まった内容を変更したい    |

---

# 超短縮版

```text
RFI
→ Information
→ 情報収集

RFP
→ Proposal
→ 提案依頼

提案書
→ ベンダーから回答

契約
→ 発注条件を確定

変更依頼書
→ 後から変更を依頼
```

## 流れで覚える

**情報を集める（RFI）
↓
提案してもらう（RFP）
↓
提案書を比較する
↓
ベンダーを選ぶ
↓
契約する
↓
必要なら変更依頼する**

特に試験では、

> **RFI = 情報提供依頼書**
>
> **RFP = 提案依頼書**

の違いを押さえておく。
