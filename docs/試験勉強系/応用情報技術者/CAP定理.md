# 

## 概要

**CAP定理**とは、分散システムにおいて、

```text id="b1zcms"
C = Consistency
    一貫性

A = Availability
    可用性

P = Partition Tolerance
    分断耐性
```

という3つの性質について考えるもの。

## 最重要ポイント

> **C・A・Pの3つを、ネットワーク分断時に同時に完全保証することはできない。**

特に分散システムではネットワーク分断（P）が起こる可能性があるため、

```text id="wly51u"
ネットワーク分断が発生
        ↓
    Pを維持する
        ↓
   C または A
どちらかを優先する
```

という考え方が重要。

---

# C：Consistency（一貫性）

**どのノードからアクセスしても、一貫した最新のデータを取得できること。**

```text id="mvsnwf"
サーバA → 100
サーバB → 100
サーバC → 100
```

> **C = データを一致させる**

---

# A：Availability（可用性）

**リクエストに対してシステムが応答を返し続けること。**

一部に問題が発生しても、サービスを利用できることを重視する。

> **A = サービスを止めない**

---

# P：Partition Tolerance（分断耐性）

ネットワーク障害によってノード間の通信が分断されても、**システムが動作を継続できること。**

```text id="p9sq7b"
サーバA ───×─── サーバB
            ↑
        通信できない
```

> **P = ネットワーク分断に耐える**

---

# なぜ3つ同時に満たせない？

例えば、

```text id="pmv41f"
サーバA ───×─── サーバB
   ↓
100 → 80

しかし通信障害で
Bに「80」が伝わらない
```

このときサーバBは古い`100`を持っている。

### Cを優先

```text id="nd7r19"
「最新データか確認できないので
サーバBは応答しない」
```

→ **一貫性（C）を維持**

→ 応答できないため**可用性（A）を犠牲**

### Aを優先

```text id="m6ifcc"
「古いデータでも
サーバBは応答する」
```

→ **可用性（A）を維持**

→ `80`と`100`が存在するので**一貫性（C）を犠牲**

---

# 試験用まとめ

| 項目 | 意味                  | 一言               |
| -- | ------------------- | ---------------- |
| C  | Consistency         | **データを合わせる**     |
| A  | Availability        | **サービスを止めない**    |
| P  | Partition Tolerance | **ネットワーク分断に耐える** |

```text id="b3nw08"
       CAP

C = 一貫性
A = 可用性
P = 分断耐性

重要
 ↓
ネットワーク分断時に
3つすべてを同時に完全保証できない

Pを維持する場合
 ↓
┌─────────────┐
↓             ↓
CP            AP
↓             ↓
Cを優先       Aを優先
Aを犠牲       Cを犠牲
```

# 超短縮版

**C = データを合わせる
A = サービスを止めない
P = 分断に耐える**

そして、

> **CAPの3つを、分断時にすべて同時に完全保証することはできない。**

**Pが必要な状況では、CかAのどちらを優先するかを選択する。**
