
| 方式                | 主な目的         | ポイント                |
| ----------------- | ------------ | ------------------- |
| SMTP-AUTH         | メール送信時の認証    | SMTPでユーザー認証         |
| POP before SMTP   | メール送信時の認証    | 先にPOP認証してからSMTP送信   |
| APOP              | メール受信時の認証    | POP3のパスワードをそのまま送らない |
| SMTP over SSL/TLS | メール送信時の通信暗号化 | SMTP通信そのものを暗号化      |

## SMTP-AUTH

SMTPでメールを**送信するときにユーザー認証**を行う方式。

ユーザーID・パスワードなどで認証してからメール送信を許可する。

**認証 → SMTP → メール送信**

- 不正なメール送信を防止
- 現在では一般的な方式

**覚え方：SMTP自身に認証機能を追加**

---

## POP before SMTP

メールを送信する前に、一度**POP3で認証**する方式。

POP3で正常に認証された利用者に対して、
一定時間SMTPによるメール送信を許可する。

**POP3で認証 → SMTPで送信**

SMTP-AUTHが普及する以前によく使われた方式。

**覚え方：送信する前（before）にPOP認証**

---

## APOP

POP3でメールを受信するときの**認証方式**。

通常のPOP3認証よりも、
パスワードをそのままネットワーク上に流さないようにする。

チャレンジレスポンス方式を利用する。

**APOP → メール受信時の認証**

※メール本文そのものを暗号化する仕組みではない。

**覚え方：安全性を高めたPOP認証**

---

## SMTP over SSL/TLS

SMTPによる通信を**SSL/TLSで暗号化**する方式。

認証方式というより、
通信経路を暗号化して盗聴などを防ぐための仕組み。

**SMTP通信 → SSL/TLSで暗号化**

SMTP-AUTHと組み合わせて、

**通信はTLSで暗号化 ＋ SMTP-AUTHで本人確認**

という使い方もできる。

---

# 試験向けの覚え方

- **SMTP-AUTH** → SMTPで送信者を認証
- **POP before SMTP** → POP認証してから送信
- **APOP** → POP3受信時の認証を安全にする
- **SMTP over SSL/TLS** → SMTP通信を暗号化

## 特に重要

**認証**
- SMTP-AUTH
- POP before SMTP
- APOP

**暗号化**
- SMTP over SSL/TLS

「誰が使っているか確認する」→ 認証  
「通信を盗み見されないようにする」→ 暗号化
