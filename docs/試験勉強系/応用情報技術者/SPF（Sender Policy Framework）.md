## SPFとは

**SPF**は、メールの**送信元ドメインのなりすましを検知するための仕組み**。

受信側メールサーバーが、

> **「このドメインのメールを、このIPアドレスのメールサーバーが送信してよいのか？」**

をDNSに問い合わせて確認する。

---

# 登場人物

例えば、

```text
送信元ドメイン
example.com

送信元メールサーバー
IP：203.0.113.10

        ↓ メール送信

受信側メールサーバー
        ↓
受信メール
From：user@example.com
```

というメールが送られてきたとする。

主な登場人物は、

| 登場人物       | 役割                 |
| ---------- | ------------------ |
| 送信元メールサーバー | 実際にメールを送信する        |
| 送信元ドメイン    | メール送信元として使われるドメイン  |
| IPアドレス     | 実際に接続してきた送信サーバーのIP |
| DNS        | SPFレコードを公開する       |
| 受信側メールサーバー | SPFを確認する           |
| 受信メール      | SPFチェックの対象となるメール   |

---

# SPFの事前準備

`example.com`の管理者はDNSに、

```text
example.comのメールは
203.0.113.10
から送信してよい
```

という情報を**SPFレコード**として登録しておく。

イメージ：

```text
DNS

example.com
   ↓
「203.0.113.10 からの
 メール送信を許可しています」
```

---

# メールが送られる

送信元メールサーバーからメールを送信する。

```text
example.com

送信元メールサーバー
203.0.113.10
      │
      │ メール送信
      ↓
受信側メールサーバー
```

受信側メールサーバーは、実際に接続してきた送信元のIPアドレスを確認する。

```text
送信元IP
203.0.113.10
```

---

# 受信側がSPFを確認

受信側メールサーバーはDNSを確認する。

```text
受信側メールサーバー

「example.comのメールを
 203.0.113.10から送っていいの？」
            │
            ↓
           DNS
            │
            ↓
「203.0.113.10は許可されています」
```

一致していれば、

```text
SPF PASS
```

となる。

---

# SPF PASSの流れ

```text
① メール受信

example.com
     ↓
203.0.113.10から送信
     ↓
受信側メールサーバー


② 送信元を確認

ドメイン
example.com

IP
203.0.113.10


③ DNSのSPFを確認

example.com
↓
許可IP：203.0.113.10


④ 比較

実際のIP
203.0.113.10

      ＝

許可されたIP
203.0.113.10


⑤ SPF PASS
```

> **「このIPから送ってOK」と確認できた。**

---

# なりすましの場合

攻撃者が、

```text
example.comを名乗ろう
```

としてメールを送ったとする。

しかし実際の送信元は、

```text
攻撃者メールサーバー

IP
198.51.100.50
```

だった。

```text
example.comを名乗るメール

      ↓

198.51.100.50

      ↓

受信側メールサーバー
```

受信側がDNSを確認すると、

```text
example.com

許可IP
203.0.113.10
```

となっている。

比較すると、

```text
実際の送信元
198.51.100.50

       ≠

SPFで許可
203.0.113.10
```

一致しない。

```text
SPF FAIL
```

となる。

> **「example.comを名乗っているけど、許可されていないサーバーから来ている」**

と判断できる。

---

# SPFの重要ポイント

SPFは基本的に、

```text
ドメイン
    ＋
実際の送信元IPアドレス
```

の関係をチェックする。

つまり、

> **「このドメインのメールを、このIPアドレスから送ってよいか？」**

を確認している。

---

# 誰がチェックする？

ここも重要。

```text
送信側
→ SPF情報をDNSに公開しておく


受信側メールサーバー
→ SPF情報をDNSから取得してチェックする
```

つまり、

> **SPFをチェックするのは受信側メールサーバー**

---

# SPFで防ぎたいもの

主な目的は**送信元ドメインのなりすまし対策**。

```text
攻撃者
   ↓
他人のドメインを名乗る
   ↓
偽メール送信
   ↓
受信メールサーバー
   ↓
SPF確認
   ↓
「そのIPは許可されていない」
```

フィッシングメールや迷惑メール対策の一つとして利用される。

---

# 注意：Fromだけを見るわけではない

試験で少し深く問われる場合は注意。

SPFでは基本的に、メール画面に表示される

```text
From: user@example.com
```

だけをそのまま検証する仕組みではない。

SMTP通信で使われる**エンベロープFrom（MAIL FROM）のドメイン**などを基準に、送信元IPアドレスが許可されているかを検証する。

そのため、

> **SPF = 表示上のFromアドレスそのものを保証する**

と覚えるのは正確ではない。

---

# DKIMとの違い

SPFと一緒に出やすい。

```text
SPF
→ 送信元IPアドレスを確認

DKIM
→ 電子署名を確認
```

|          | SPF       | DKIM        |
| -------- | --------- | ----------- |
| 主に確認するもの | 送信元IP     | 電子署名        |
| DNSに公開   | 許可する送信元情報 | 公開鍵         |
| 目的       | なりすまし対策   | なりすまし・改ざん対策 |

---

# DMARCとの関係

DMARCは、SPFやDKIMの認証結果などを利用して、

```text
認証失敗したメールを

・そのまま受け入れる
・迷惑メール扱い
・拒否する
```

といったポリシーを指定する仕組み。

```text
SPF ─┐
     ├→ DMARC
DKIM ─┘
```

---

# 試験用まとめ

```text
【送信側】

送信元ドメイン
example.com

       ↓

DNSにSPFを登録

「203.0.113.10から
 送信してOK」


【メール送信】

送信元メールサーバー
203.0.113.10

       ↓

受信側メールサーバー


【受信側】

① 実際の送信元IPを確認

② 送信元ドメインの
   SPFレコードをDNSから取得

③ IPアドレスを比較

④ 許可されている
   → SPF PASS

   許可されていない
   → SPF FAIL
```

# 超短縮版

**SPF = 「このドメインを、このIPから送っていい？」を確認する仕組み**

```text
送信側
→ DNSに許可IPを登録

受信側
→ DNSのSPFを確認

実際の送信元IP
      ↓ 比較
SPFで許可されたIP
      ↓
一致 → PASS
不一致 → FAIL
```

## 一言で覚える

**SPF
= ドメイン × 送信元IPアドレスの確認
= チェックするのは受信側メールサーバー
= メールのなりすまし対策**
