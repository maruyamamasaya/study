仮想化には代表的に次の3つの方式がある。

* **ハイパーバイザー型**
* **ホストOS型**
* **コンテナ型**

大きな違いは、**仮想環境ごとにOSを持つかどうか**。

---

# 1. ハイパーバイザー型

物理サーバー上に**ハイパーバイザー**を直接動かし、その上に複数の仮想マシン（VM）を作る方式。

## 構成

```text
┌───────────────┐
│ アプリ │ アプリ │
├───────┼───────┤
│ Windows│ Linux │ ← ゲストOS
├───────┴───────┤
│  ハイパーバイザー  │
├───────────────┤
│   物理サーバー     │
└───────────────┘
```

それぞれのVMが、

**アプリ + ゲストOS**

を持っている。

## 特徴

* 物理サーバー上で複数のOSを動かせる
* VMごとに独立したOSを持つ
* WindowsとLinuxなど異なるOSを同時に利用できる
* サーバー仮想化で広く利用される
* ホストOS型よりオーバーヘッドが小さい

## 代表例

* VMware ESXi
* Microsoft Hyper-V
* KVM

---

# 2. ホストOS型

WindowsやLinuxなどの**ホストOSの上に仮想化ソフトウェアをインストール**して、VMを動かす方式。

## 構成

```text
┌───────────────┐
│ アプリ │ アプリ │
├───────┼───────┤
│ Linux │Windows│ ← ゲストOS
├───────┴───────┤
│   仮想化ソフト     │
├───────────────┤
│    ホストOS       │
├───────────────┤
│   物理マシン      │
└───────────────┘
```

ポイントは、

**物理マシン → ホストOS → 仮想化ソフト → ゲストOS**

という構造。

## 特徴

* 普通のPCに導入しやすい
* 開発・検証環境として使いやすい
* VMごとにゲストOSを持つ
* ホストOSを経由するため、ハイパーバイザー型よりオーバーヘッドが大きい

## 代表例

* Oracle VirtualBox
* VMware Workstation
* VMware Fusion
* Parallels Desktop

---

# 3. コンテナ型

コンテナ型は、VMのように**環境ごとのゲストOSを持たない**。

ホストOSの**カーネルを共有**して、アプリケーションと必要なライブラリなどを分離して動かす。

## 構成

```text
┌────────┬────────┐
│ アプリA  │ アプリB  │
│ライブラリ│ライブラリ│
├────────┴────────┤
│ コンテナエンジン     │
├─────────────────┤
│ ホストOS（カーネル） │
├─────────────────┤
│ 物理サーバー         │
└─────────────────┘
```

VMとの最大の違いは、

**コンテナごとにゲストOSを持たない**

こと。

## 特徴

* OSのカーネルを共有する
* VMより軽量
* 起動が速い
* 必要なCPU・メモリ・ストレージが少ない
* アプリケーションの配布・移動がしやすい
* 多数の環境を効率よく動かせる

## 代表例

* Docker
* Podman

多数のコンテナを管理する仕組みとして、

* Kubernetes
* OpenShift

などがある。

---

# VMとコンテナの最大の違い

## VM

```text
アプリ
 ↓
ゲストOS
 ↓
ハイパーバイザー
 ↓
物理サーバー
```

**VMごとにOSが必要。**

---

## コンテナ

```text
アプリ
 ↓
コンテナ
 ↓
共通のOSカーネル
 ↓
物理サーバー
```

**OSカーネルを共有する。**

そのためコンテナの方が軽量。

---

# 3方式の比較

| 項目     | ハイパーバイザー型 | ホストOS型    | コンテナ型      |
| ------ | --------- | --------- | ---------- |
| 仮想化対象  | マシン       | マシン       | アプリ実行環境    |
| ホストOS  | 基本不要      | 必要        | 必要         |
| ゲストOS  | VMごとに必要   | VMごとに必要   | **不要**     |
| OSカーネル | VMごと      | VMごと      | **共有**     |
| 処理負荷   | 中         | 大きめ       | **小さい**    |
| 起動速度   | 比較的遅い     | 比較的遅い     | **速い**     |
| 異なるOS  | ○         | ○         | 制約あり       |
| 主な用途   | サーバー仮想化   | PCでの開発・検証 | アプリ・クラウド環境 |

---

# なぜコンテナは軽い？

例えば10個の環境を作る場合。

## VMの場合

```text
VM1 → Linux OS + アプリ
VM2 → Linux OS + アプリ
VM3 → Linux OS + アプリ
...
VM10 → Linux OS + アプリ
```

10個のVMそれぞれにOSが必要。

一方コンテナなら、

```text
共通Linuxカーネル
 ├─ コンテナ1 → アプリ
 ├─ コンテナ2 → アプリ
 ├─ コンテナ3 → アプリ
 └─ ...
```

OSカーネルを共有できる。

そのため、

**コンテナはVMより軽量で高速に起動できる。**

---

# 試験対策

## ハイパーバイザー型

**物理マシンの上で直接仮想化**

→ サーバー仮想化
→ VMごとにゲストOS

---

## ホストOS型

**OSの上に仮想化ソフト**

→ 普通のPCでも使いやすい
→ VMごとにゲストOS

---

## コンテナ型

**OSカーネルを共有**

→ ゲストOS不要
→ 軽量・高速

---

# 超簡単に覚える

**ハイパーバイザー型**

`物理 → ハイパーバイザー → VM → OS → アプリ`

**ホストOS型**

`物理 → ホストOS → 仮想化ソフト → VM → OS → アプリ`

**コンテナ型**

`物理 → OS → コンテナ → アプリ`

### 一番重要

> **VMはOSごと仮想化する。**
>
> **コンテナはOSカーネルを共有してアプリの実行環境を分離する。**

特に試験で「軽量」「高速起動」「ホストOSのカーネルを共有」というキーワードが出てきたら、**コンテナ型**を考える。
