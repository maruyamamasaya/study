## 全体像

まず4つは役割が違う。

| 技術          | 種類      | 主な目的         |
| ----------- | ------- | ------------ |
| **AES**     | 共通鍵暗号方式 | データを高速に暗号化   |
| **RSA**     | 公開鍵暗号方式 | 暗号化・デジタル署名など |
| **SHA-256** | ハッシュ関数  | データの改ざん検知など  |
| **PKI**     | 公開鍵基盤   | 公開鍵が誰のものか保証  |

```text id="n63bzb"
AES
→ データを暗号化

RSA
→ 公開鍵・秘密鍵を利用

SHA-256
→ データからハッシュ値を生成

PKI
→ 公開鍵を信用するための仕組み
```

---

# 1. AES

**AES（Advanced Encryption Standard）**

代表的な**共通鍵暗号方式**。

暗号化と復号に**同じ鍵**を使用する。

```text id="3mybmk"
      共通鍵
        ↓
平文 → 暗号化 → 暗号文
                 ↓
               共通鍵
                 ↓
                復号
                 ↓
                平文
```

## 特徴

* 暗号化・復号が高速
* 大量のデータの暗号化に向いている
* 暗号化と復号で同じ鍵を使用
* 鍵を安全に相手へ渡す必要がある

> **AES = 同じ鍵で暗号化・復号**

### 例

```text id="uqkgkr"
鍵：ABC123

「こんにちは」
   ↓ AESで暗号化
「x8#k2...」
   ↓ 同じ鍵で復号
「こんにちは」
```

---

# 2. RSA

**RSA**は代表的な**公開鍵暗号方式**。

2種類の鍵を使用する。

```text id="z3j8vs"
公開鍵
→ 他人に公開してOK

秘密鍵
→ 本人だけが持つ
```

暗号化に利用する場合は、

```text id="h67myh"
送信者
 ↓
受信者の「公開鍵」で暗号化
 ↓
暗号文
 ↓
受信者
 ↓
受信者の「秘密鍵」で復号
```

となる。

> **公開鍵で暗号化 → 秘密鍵で復号**

## 特徴

* 公開鍵を公開できる
* 秘密鍵を相手に渡す必要がない
* AESなどの共通鍵暗号より処理が重い
* 鍵交換やデジタル署名などに利用される

---

# AESとRSAの違い

|       | AES    | RSA      |
| ----- | ------ | -------- |
| 種類    | 共通鍵暗号  | 公開鍵暗号    |
| 鍵     | 同じ鍵    | 公開鍵＋秘密鍵  |
| 処理速度  | **速い** | 比較的遅い    |
| 大量データ | 得意     | 不向き      |
| 鍵の受渡し | 難しい    | 公開鍵を公開可能 |

そのため実際の通信では、

```text id="uh04n3"
RSAなど
→ 鍵を安全に共有・認証する

AES
→ 実際の大量データを暗号化
```

のように、それぞれの長所を組み合わせる方式が使われる。

> **RSA系で鍵の問題を解決して、AESで高速に通信するイメージ**

---

# 3. SHA-256

**SHA-256**は暗号化方式ではなく、**ハッシュ関数**。

データを入力すると、固定長のハッシュ値を生成する。

```text id="5t86hx"
データ
「こんにちは」
     ↓
  SHA-256
     ↓
ハッシュ値
「125aeadf...」
```

SHA-256では**256ビットのハッシュ値**を生成する。

---

# ハッシュ関数の特徴

## ① 元に戻せない

```text id="5v4ohj"
データ
 ↓
SHA-256
 ↓
ハッシュ値
```

基本的に、

```text id="bww57k"
ハッシュ値
 ↓
元データ

× 戻せない
```

暗号化とはここが違う。

---

## ② 同じデータなら同じハッシュ値

```text id="3qrx8b"
ABC
 ↓ SHA-256
XYZ123...

ABC
 ↓ SHA-256
XYZ123...
```

同じ入力なら同じ結果になる。

---

## ③ データが少し変わるとハッシュ値も大きく変わる

```text id="9v1ay5"
「100万円振り込む」
      ↓
ハッシュA

「900万円振り込む」
      ↓
全く異なるハッシュB
```

そのため**改ざん検知**などに利用できる。

---

# 暗号化とハッシュの違い

```text id="sl04ga"
暗号化

平文
 ↓
暗号文
 ↓ 復号
平文

→ 元に戻せる
```

```text id="cagzqd"
ハッシュ

データ
 ↓
ハッシュ値

→ 元に戻すものではない
```

> **AES・RSA = 暗号技術**
>
> **SHA-256 = ハッシュ関数**

---

# 4. PKI

**PKI（Public Key Infrastructure）**
＝ 公開鍵基盤

公開鍵暗号を安全に利用するために、**「この公開鍵は本当にこの人・組織のものですよ」と保証する仕組み**。

---

# なぜPKIが必要？

例えば、

```text id="mvhgnx"
銀行
「これが私の公開鍵です」
```

と言われても、

```text id="op1k5r"
本当に銀行の公開鍵？

攻撃者の公開鍵では？
```

という問題がある。

そこで登場するのが**デジタル証明書**。

```text id="lsdy2u"
認証局（CA）
    ↓
本人確認
    ↓
デジタル証明書を発行
    ↓
「この公開鍵は
 本当に○○社のものです」
```

---

# CA（認証局）

**CA（Certification Authority）**は、デジタル証明書を発行する機関。

```text id="7iqy3e"
        CA
      認証局
        ↓
   証明書を発行
        ↓
Webサイト・企業など
```

> **CA = 公開鍵の身元を保証する機関**

---

# デジタル証明書

デジタル証明書には、

```text id="4wmq8p"
・公開鍵
・所有者情報
・有効期限
・発行したCA
・CAによるデジタル署名
```

などが含まれる。

これによって、

> **「この公開鍵は確かにこのサイト・組織のもの」**

と確認できる。

---

# PKIの全体イメージ

```text id="xgcrfw"
      認証局（CA）
          ↓
   証明書を発行・署名
          ↓
       Webサイト
          ↓
    証明書を利用者へ
          ↓
       利用者
          ↓
証明書・署名などを検証
          ↓
公開鍵を信頼して利用
```

HTTPSなどでも、こうしたデジタル証明書の仕組みが利用されている。

---

# デジタル署名

RSAなどの公開鍵暗号技術とSHA-256などのハッシュ関数は、**デジタル署名**でも関係する。

大まかな流れは、

```text id="5r2hcz"
送信データ
   ↓
SHA-256など
   ↓
ハッシュ値
   ↓
秘密鍵を使って署名
   ↓
デジタル署名
```

受信者側では、

```text id="c0ny0g"
受信データ
   ↓
SHA-256など
   ↓
ハッシュ値を計算
       ＋
公開鍵で署名を検証
       ↓
一致する？
       ↓
改ざん・署名者を確認
```

デジタル署名によって主に、

* 改ざんされていないこと
* 誰が署名したか

などを確認できる。

---

# 4つの関係

Web通信をイメージすると分かりやすい。

```text id="wy3rvo"
【PKI】
「この公開鍵は本物？」
        ↓
証明書・CAによって確認

【RSAなどの公開鍵暗号技術】
公開鍵・秘密鍵を利用
        ↓
鍵交換・署名など

【AES】
実際の大量データ
        ↓
高速に暗号化

【SHA-256】
データ
        ↓
ハッシュ値
        ↓
改ざん検知・署名など
```

※実際のTLSではRSA以外の方式も広く利用されるため、「HTTPS＝RSA」と覚えないこと。

---

# 試験用比較

| 用語          | 分類    | 鍵       | 特徴               |
| ----------- | ----- | ------- | ---------------- |
| **AES**     | 共通鍵暗号 | 同じ鍵     | 高速               |
| **RSA**     | 公開鍵暗号 | 公開鍵＋秘密鍵 | 鍵交換・署名など         |
| **SHA-256** | ハッシュ  | なし      | 256ビットのハッシュ値     |
| **PKI**     | 公開鍵基盤 | ―       | 証明書・CAによって公開鍵を信頼 |

---

# 問題文での見分け方

```text id="f1ax6a"
「高速」「同じ鍵」「大量データ」
→ AES

「公開鍵・秘密鍵」
→ RSA

「256ビット」「ハッシュ」「改ざん検知」
→ SHA-256

「認証局」「CA」「デジタル証明書」
→ PKI
```

# 超短縮版

```text id="xctvpe"
AES
→ 共通鍵暗号
→ 同じ鍵
→ 高速

RSA
→ 公開鍵暗号
→ 公開鍵＋秘密鍵

SHA-256
→ ハッシュ関数
→ 元に戻せない
→ 改ざん検知

PKI
→ 公開鍵を信頼する仕組み
→ CA＋デジタル証明書
```

## 一言で覚える

**AES = データを速く隠す
RSA = 公開鍵と秘密鍵を使う
SHA-256 = データの指紋を作る
PKI = その公開鍵が本物だと証明する**
