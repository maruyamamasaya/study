## 基本的な考え方

ネットワーク通信では、次のように覚えると分かりやすい。

> **IPアドレス = 最終的な宛先**
>
> **MACアドレス = 次に渡す相手**

つまり、

* **IPパケット** → 最終的にどのホストへ届けるか
* **イーサネットフレーム** → 今いるLANの中で次に誰へ渡すか

を表している。

---

# 今回の構成

```text
【LAN1】

ホストA
MAC1 / IP1
   │
   │
ルータ
MAC3 / IP3
   │
   │
──────────────
【LAN2】
   │
   │
ルータ
MAC4 / IP4
   │
   │
ホストB
MAC2 / IP2
```

ホストAからホストBへ通信する。

しかし、ホストAとホストBは**別のLAN**に存在する。

そのため、

```text
ホストA
   ↓
ルータ
   ↓
ホストB
```

という順番でデータを渡す。

---

# ① ホストAが送信する

ホストAが最終的に送りたい相手は、

**ホストB（IP2）**

である。

そのため、IPパケットは、

```text
送信元IP：IP1
宛先IP　：IP2
```

となる。

## しかしMACアドレスは？

ホストBは別のLANにいるので、ホストAから直接送れない。

そこで、まずLAN1にいる**ルータ**へ渡す。

ルータのLAN1側は、

```text
MAC3 / IP3
```

なので、イーサネットフレームは、

```text
送信元MAC：MAC1
宛先MAC　：MAC3
```

となる。

---

# LAN1を流れるデータ

```text
┌──────────────────────────┐
│ イーサネットフレーム       │
│                          │
│ 送信元MAC：MAC1           │
│ 宛先MAC　：MAC3           │ ← 次の相手（ルータ）
│                          │
│  ┌────────────────────┐  │
│  │ IPパケット           │  │
│  │                    │  │
│  │ 送信元IP：IP1       │  │
│  │ 宛先IP　：IP2       │  │ ← 最終目的地（ホストB）
│  └────────────────────┘  │
│                          │
└──────────────────────────┘
```

つまりLAN1では、

| 種類  | 送信元  | 宛先       |
| --- | ---- | -------- |
| MAC | MAC1 | **MAC3** |
| IP  | IP1  | **IP2**  |

となる。

---

# ② ルータが受け取る

ルータは、

```text
MAC1 → MAC3
```

のイーサネットフレームを受け取る。

そして外側のイーサネットフレームを処理する。

中に入っているIPパケットを見る。

```text
送信元IP：IP1
宛先IP　：IP2
```

ルータは宛先IPを確認して、

> 「IP2はLAN2側にいる」

と判断する。

そして、LAN2用の**新しいイーサネットフレーム**を作る。

---

# ③ ルータからホストBへ送信

LAN2では、

```text
ルータ → ホストB
```

と通信する。

そのためMACアドレスは、

```text
送信元MAC：MAC4
宛先MAC　：MAC2
```

となる。

一方、IPパケットは引き続き、

```text
送信元IP：IP1
宛先IP　：IP2
```

となる。

---

# LAN2を流れるデータ

```text
┌──────────────────────────┐
│ イーサネットフレーム       │
│                          │
│ 送信元MAC：MAC4           │
│ 宛先MAC　：MAC2           │ ← 次の相手（ホストB）
│                          │
│  ┌────────────────────┐  │
│  │ IPパケット           │  │
│  │                    │  │
│  │ 送信元IP：IP1       │  │
│  │ 宛先IP　：IP2       │  │ ← 最終目的地
│  └────────────────────┘  │
│                          │
└──────────────────────────┘
```

---

# A → Bの通信をまとめる

```text
【ホストA】
MAC1 / IP1

      │
      │ LAN1
      │
      │ MAC：MAC1 → MAC3
      │ IP ：IP1  → IP2
      ▼

【ルータ】
LAN1：MAC3 / IP3
LAN2：MAC4 / IP4

      │
      │ LAN2
      │
      │ MAC：MAC4 → MAC2
      │ IP ：IP1  → IP2
      ▼

【ホストB】
MAC2 / IP2
```

---

# MACアドレスは途中で変わる

LAN1では、

```text
MAC1 → MAC3
```

LAN2では、

```text
MAC4 → MAC2
```

つまり、

> **MACアドレスはLANを移動するたびに変わる。**

ルータが新しいイーサネットフレームを作るため。

---

# IPアドレスは基本的に変わらない

LAN1でも、

```text
IP1 → IP2
```

LAN2でも、

```text
IP1 → IP2
```

つまり、

> **送信元から最終目的地までIPアドレスは基本的に変わらない。**

※NATなどが存在する場合はIPアドレスが書き換えられることもある。

---

# 宅配便で考える

IPアドレスは、

**荷物に書かれた最終目的地の住所**

と考える。

```text
東京のA
  ↓
配送センター
  ↓
大阪のB
```

最終目的地は最初から最後まで、

**大阪のB**

なので変わらない。

一方MACアドレスは、

**次に荷物を渡す相手**

と考える。

```text
A
 ↓
配送センター①
 ↓
配送センター②
 ↓
B
```

次に渡す相手は、その都度変わる。

---

# IPパケットとイーサネットフレームの違い

| 項目         | IPパケット          | イーサネットフレーム |
| ---------- | --------------- | ---------- |
| 主に使うアドレス   | IPアドレス          | MACアドレス    |
| 宛先         | **最終目的地**       | **次に渡す相手** |
| ルータ通過時     | 基本的に送信元・宛先IPは維持 | 新しく作り直される  |
| 今回のLAN1の宛先 | **IP2**         | **MAC3**   |
| 今回のLAN2の宛先 | **IP2**         | **MAC2**   |

---

# 今回の問題の答え

問題は、

> LAN1における
> 「イーサネットフレームの宛先」と
> 「IPデータグラムの宛先」

を聞いている。

LAN1では、

```text
ホストA → ルータ
```

なので、

**イーサネットフレームの宛先**

```text
MAC3
```

最終的に届けたいのはホストBなので、

**IPデータグラムの宛先**

```text
IP2
```

したがって、

```text
イーサネットフレームの宛先：MAC3
IPデータグラムの宛先　　：IP2
```

となる。

---

# 試験対策：これだけ覚える

## IP

**「最終的に誰に届けたい？」**

→ 最終目的地のIPアドレス

## MAC

**「次に誰に渡す？」**

→ 同じLAN内の次の相手のMACアドレス

### 一言で覚える

> **MACは次、IPは最後**

ルータを通過すると、

**MACは変わる、IPは基本的に変わらない。**
