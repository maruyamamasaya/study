## UMLとは

**UML（Unified Modeling Language）**とは、システムやソフトウェアの構造・振る舞いを図で表現するためのモデリング言語。

大きく、

* **構造を表す図**
* **振る舞いを表す図**

に分けて考えると分かりやすい。

---

# 1. アクティビティ図

処理や業務の**流れ・手順**を表す図。

フローチャートに近い。

## 主な用途

* 業務フロー
* 処理手順
* 条件分岐
* 並行処理

## イメージ

```text
開始
 ↓
注文受付
 ↓
在庫確認
 ↓
在庫あり？
 ├─ YES → 発送
 └─ NO  → 入荷待ち
 ↓
終了
```

### 覚え方

> **アクティビティ図 = 処理の流れ**

---

# 2. クラス図

システム内の**クラスの構造や関係**を表す図。

オブジェクト指向設計で非常によく使う。

## 表すもの

* クラス名
* 属性
* メソッド
* クラス同士の関係

## 例

```text
+----------------+
| 顧客           |
+----------------+
| 顧客ID         |
| 氏名           |
+----------------+
| 注文する()     |
+----------------+
        |
        | 1
        |
        | *
+----------------+
| 注文           |
+----------------+
| 注文ID         |
| 注文日         |
+----------------+
```

### 主な関係

* 関連
* 継承
* 集約
* コンポジション

### 覚え方

> **クラス図 = システムの静的な構造**

---

# 3. コンポーネント図

システムを構成する**ソフトウェア部品同士の関係**を表す。

## 例

```text
Web画面
   ↓
API
   ↓
業務ロジック
   ↓
データベース
```

より実際には、

```text
[Webフロント]
      |
      v
[APIサーバ]
      |
      v
[DBアクセス部品]
      |
      v
[Database]
```

## 主な用途

* ソフトウェア構成
* モジュール構成
* コンポーネント間の依存関係
* インターフェース

### 覚え方

> **コンポーネント図 = ソフトウェア部品の構成図**

---

# 4. コミュニケーション図

複数のオブジェクトが**どのようにメッセージをやり取りするか**を表す。

シーケンス図と似ているが、
**時間の流れより、オブジェクト間の関係を重視**する。

## 例

```text
顧客画面
  |
  | 1: 注文()
  v
注文処理
  |
  | 2: 在庫確認()
  v
在庫管理
```

メッセージに、

```text
1:
2:
3:
```

のような番号を付けて、実行順序を表す。

### 覚え方

> **コミュニケーション図 = オブジェクト同士のやり取り**

---

# 5. シーケンス図

オブジェクト間のメッセージのやり取りを、
**時間の流れに沿って**表す。

## イメージ

```text
ユーザー   Web   API   DB
   |        |     |     |
   |------->|     |     |
   |        |---->|     |
   |        |     |---->|
   |        |     |<----|
   |        |<----|     |
   |<-------|     |     |
```

時間は上から下へ進む。

### 覚え方

> **シーケンス図 = 時系列でメッセージを見る**

---

# コミュニケーション図との違い

| 図          | 重視するもの      |
| ---------- | ----------- |
| シーケンス図     | 時間・処理順序     |
| コミュニケーション図 | オブジェクト同士の関係 |

```text
シーケンス図
→ 時間を重視

コミュニケーション図
→ 関係を重視
```

---

# 6. ユースケース図

システムを**誰が、どのように利用するか**を表す。

## 要素

* アクター
* ユースケース

## 例

```text
      ┌─────────────┐
顧客 →│ 商品を検索する │
      └─────────────┘

      ┌─────────────┐
顧客 →│ 商品を購入する │
      └─────────────┘
```

### 覚え方

> **ユースケース図 = 誰が何をするか**

---

# 7. 状態マシン図

オブジェクトの**状態の変化**を表す。

## 例

注文の場合、

```text
受付
 ↓
支払済
 ↓
発送済
 ↓
完了
```

途中で、

```text
受付
 ↓
キャンセル
```

なども表現できる。

### 覚え方

> **状態マシン図 = 状態の遷移**

---

# 8. オブジェクト図

クラス図が設計上の構造を表すのに対して、
オブジェクト図は**ある時点の具体的なインスタンスの状態**を表す。

## クラス図

```text
顧客
- 顧客ID
- 氏名
```

## オブジェクト図

```text
顧客1
顧客ID = 001
氏名 = 田中
```

### 覚え方

> **クラス図 = 設計図**
>
> **オブジェクト図 = 実際の具体例**

---

# 9. パッケージ図

クラスやコンポーネントなどを、
**パッケージ単位でグループ化した構造**を表す。

## 例

```text
[画面]
   ↓
[業務ロジック]
   ↓
[データアクセス]
```

### 覚え方

> **パッケージ図 = 大きなグループ分け**

---

# 10. 配置図

サーバ、端末、ネットワークなどの**物理的な配置**を表す。

## 例

```text
[クライアントPC]
        |
        v
[Webサーバ]
        |
        v
[DBサーバ]
```

### 主な用途

* サーバ構成
* ネットワーク構成
* システムの配置場所

### 覚え方

> **配置図 = どこに配置するか**

---

# 試験用まとめ

| UML図       | 表すもの             |
| ---------- | ---------------- |
| アクティビティ図   | 処理・業務の流れ         |
| クラス図       | クラスの構造・関係        |
| コンポーネント図   | ソフトウェア部品の構成      |
| コミュニケーション図 | オブジェクト間の関係・メッセージ |
| シーケンス図     | 時系列のメッセージ        |
| ユースケース図    | 誰が何をするか          |
| 状態マシン図     | 状態の変化            |
| オブジェクト図    | 具体的なインスタンス       |
| パッケージ図     | グループ・まとまり        |
| 配置図        | サーバなどの物理配置       |

---

# 最低限覚える

```text
アクティビティ図
→ 処理の流れ

クラス図
→ クラスの構造

コンポーネント図
→ ソフトウェア部品

コミュニケーション図
→ オブジェクト同士の関係

シーケンス図
→ 時系列のやり取り

ユースケース図
→ 誰が何をするか

状態マシン図
→ 状態の変化

配置図
→ サーバなどの配置
```

---

# 特に混同しやすいもの

```text
シーケンス図
→ 「いつ・どの順番で」

コミュニケーション図
→ 「誰と誰がやり取りするか」
```

```text
クラス図
→ ソフトウェアの論理構造

コンポーネント図
→ ソフトウェア部品の構成

配置図
→ ハードウェア・サーバ上の配置
```

```text
アクティビティ図
→ 処理の流れ

状態マシン図
→ 状態そのものの変化
```
