## WBSとは

**WBS（Work Breakdown Structure：作業分解構成図）**とは、プロジェクトで必要な成果物や作業範囲を、**管理可能な単位まで階層的に分解したもの**。

```text id="7dx92e"
プロジェクト全体
   ↓
大きな成果物・作業
   ↓
さらに分解
   ↓
ワークパッケージ
   ↓
アクティビティ
```

> **WBS = プロジェクトのスコープを細かく分解する**

---

# プロジェクトスコープ

**プロジェクトで「何を実施し、何を成果物として作るのか」という範囲。**

例えば、

```text id="zd2bbg"
ECサイト構築プロジェクト

・会員機能
・商品検索
・購入機能
・決済機能
・テスト
```

などがプロジェクトの対象範囲になる。

このスコープを階層的に分解していくとWBSになる。

---

# WBS

例えば「ECサイト構築」を分解すると、

```text id="8ylc0b"
ECサイト構築
│
├─ 会員機能
│   ├─ ログイン
│   └─ 会員登録
│
├─ 商品機能
│   ├─ 商品一覧
│   └─ 商品検索
│
└─ 決済機能
    ├─ カード決済
    └─ 決済結果処理
```

上位の成果物を、管理できる大きさまで細かくしていく。

---

# ワークパッケージ

**WBSで管理する最下位レベルの構成要素。**

コスト・期間・担当などを見積もり、管理できる程度まで分解された単位。

```text id="2kgy57"
ECサイト
  ↓
会員機能
  ↓
ログイン機能
  ↓
【ワークパッケージ】
```

> **ワークパッケージ = WBS上の最下位の管理単位**

重要なのは、

**ワークパッケージ ≠ 個々の具体的作業**

という点。

さらに実際の作業へ分解することができる。

---

# アクティビティ

ワークパッケージを実現するために必要となる、**具体的な作業**。

例えば、

```text id="pg6hmn"
ワークパッケージ
「ログイン機能」
       ↓
アクティビティ
├─ 画面設計
├─ DB設計
├─ プログラム実装
├─ 単体テスト
└─ レビュー
```

> **アクティビティ = 実際に行う具体的な作業**

---

# アクティビティリスト

プロジェクトで実施する**アクティビティを一覧化したもの**。

例えば、

| ID  | アクティビティ  |
| --- | -------- |
| A01 | ログイン画面設計 |
| A02 | DB設計     |
| A03 | ログイン機能実装 |
| A04 | 単体テスト    |
| A05 | レビュー     |

これを基に、

```text id="0u30gj"
作業順序
期間
担当者
必要資源
スケジュール
```

などを検討していく。

> **アクティビティリスト = 実際にやる作業の一覧**

---

# WBS辞書

**WBSの各構成要素について詳細情報を記載した文書。**

WBSだけでは、

```text id="1ngpfm"
1.2.3 ログイン機能
```

程度しか分からない場合がある。

そこでWBS辞書に、

```text id="8zbkwp"
WBS ID：1.2.3

名称：
ログイン機能

内容：
メールアドレスとパスワードによる認証

成果物：
ログイン画面・認証機能

担当：
開発チームA

受入基準：
正常ログイン・エラー処理が動作すること
```

などの詳細情報を記載する。

> **WBS辞書 = WBSの各項目の説明書**

---

# 全体の関係

ここを理解しておくと試験で判断しやすい。

```text id="cifzkg"
【プロジェクトスコープ】
何を実現するか
        ↓
【WBS】
階層的に分解
        ↓
【ワークパッケージ】
WBSの最下位の管理単位
        ↓
【アクティビティ】
実際に行う具体的作業
        ↓
【アクティビティリスト】
具体的作業を一覧化
```

一方、

```text id="8z4o5j"
WBS
 ↓
各構成要素の詳細説明
 ↓
WBS辞書
```

となる。

---

# WBSとWBS辞書の違い

```text id="a4dkz9"
WBS
→ 「何があるか」を階層的に示す

WBS辞書
→ 「その項目は具体的に何なのか」を説明する
```

例えば、

```text id="nmw6bp"
WBS

1. ECサイト
   1.1 会員機能
       1.1.1 ログイン機能
```

に対して、

```text id="rc91z6"
WBS辞書

1.1.1 ログイン機能

・作業内容
・成果物
・担当
・受入基準
・前提条件
など
```

という関係。

---

# WBSとアクティビティリストの違い

ここも重要。

```text id="ft6mcn"
WBS
→ スコープを階層的に分解

アクティビティリスト
→ 実際に実施する作業を一覧化
```

例えば、

```text id="ow0cnq"
WBS
ログイン機能
   ↓
ワークパッケージ
   ↓
アクティビティリスト

・画面設計
・実装
・テスト
・レビュー
```

---

# 試験用まとめ

| 用語         | 意味                 |
| ---------- | ------------------ |
| プロジェクトスコープ | プロジェクトで実施・実現する範囲   |
| WBS        | スコープを階層的に分解したもの    |
| ワークパッケージ   | **WBSの最下位の管理単位**   |
| WBS辞書      | WBS各構成要素の詳細説明      |
| アクティビティ    | ワークパッケージを実現する具体的作業 |
| アクティビティリスト | アクティビティを一覧化したもの    |

---

# 一連の流れ

```text id="bf8atx"
プロジェクトスコープ
「何をやる？」
        ↓
WBS
「細かく分けよう」
        ↓
ワークパッケージ
「ここまでを管理単位にしよう」
        ↓
アクティビティ
「具体的に何をする？」
        ↓
アクティビティリスト
「作業を一覧にしよう」
```

そしてWBSの各項目について、

```text id="4sh72h"
「この項目って具体的に何？」
        ↓
WBS辞書
```

---

# 超短縮版

```text id="2xk8vy"
プロジェクトスコープ
→ プロジェクトの範囲

WBS
→ スコープを階層的に分解

ワークパッケージ
→ WBSの最下位の管理単位

アクティビティ
→ 実際の具体的作業

アクティビティリスト
→ 作業の一覧

WBS辞書
→ WBS各項目の詳しい説明
```

## 覚え方

**スコープ → 分解してWBS → 最下位がワークパッケージ → さらに具体的な作業がアクティビティ**

特に、

> **「WBSの最下位＝ワークパッケージ」
> 「ワークパッケージを実行するための具体的作業＝アクティビティ」**

の違いを押さえておく。
