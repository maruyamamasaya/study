正規化は、**「データの重複を減らし、更新しやすくするためにテーブルを分けること」**です。

一番イメージしやすい例は「ネットショップ」です。

---

# 正規化とは？

例えば、注文情報を1つのテーブルだけで管理するとします。

|注文ID|商品名|商品価格|注文者|電話番号|
|---|---|---|---|---|
|1|ノートPC|120,000円|山田|090-1111|
|2|マウス|3,000円|山田|090-1111|
|3|キーボード|8,000円|山田|090-1111|

一見問題なさそうですが…

- 山田さんの電話番号が3回書かれている
- 名前を変更すると全部修正しないといけない
- 修正漏れが起こる可能性がある

これが「重複」です。

---

# 正規化すると？

顧客情報を別テーブルに分けます。

## 顧客テーブル

|顧客ID|名前|電話番号|
|---|---|---|
|1|山田|090-1111|

---

## 注文テーブル

|注文ID|顧客ID|商品ID|
|---|---|---|
|1|1|101|
|2|1|102|
|3|1|103|

---

## 商品テーブル

|商品ID|商品名|価格|
|---|---|---|
|101|ノートPC|120,000円|
|102|マウス|3,000円|
|103|キーボード|8,000円|

---

こうすると、

山田さんの電話番号は

```
090-1111
```

たった1回だけ保存されます。

---

# もし電話番号が変わったら？

正規化前

```
090-1111
090-1111
090-1111
```

↓

全部修正しなければならない

---

正規化後

顧客テーブルだけ

```
090-2222
```

に変えるだけ。

注文テーブルは一切変更不要です。

# なぜ正規化するの？

正規化することで、次のようなメリットがあります。

|メリット|内容|
|---|---|
|データが重複しない|同じ情報を何度も保存しなくて済む|
|更新が簡単|1か所直せば全体に反映される|
|容量を節約できる|無駄なデータが減る|
|不整合を防げる|修正漏れによる矛盾が起きにくい|

# 実務では

ECサイトなら

- 顧客テーブル
- 商品テーブル
- 注文テーブル
- 配送先テーブル
- 支払いテーブル

のように役割ごとに分けて管理します。

そして画面で注文履歴を見るときは、**JOIN** を使って必要な情報を結合して表示します。

---

## 一言でまとめると

> **正規化とは、「同じ情報を何度も持たず、役割ごとにテーブルを分けて管理する設計」のことです。**

初心者向けには、**「Excelで同じ名前や電話番号を何度も書いていたものを、別シートにまとめるイメージ」**と考えると理解しやすいです。
