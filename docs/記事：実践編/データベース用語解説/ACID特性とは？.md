## トランザクションが安全に動作するための4つのルール

---

# 概要

**ACID（アシッド）特性**とは、

**トランザクションが正しく、安全に動作するために守るべき4つの性質**のことです。

ACIDは4つの英単語の頭文字を取った名前です。

| 頭文字 | 英語 | 意味 |
|---------|------|------|
| A | Atomicity | 原子性 |
| C | Consistency | 一貫性 |
| I | Isolation | 独立性 |
| D | Durability | 永続性 |

これら4つを満たすことで、データベースは安全にデータを管理できます。

---

# なぜ必要なの？

例えば銀行の送金では、

```
Aさん → Bさんへ1000円送金
```

という1つの操作でも、

実際には複数の処理が行われています。

```
残高を減らす

↓

残高を増やす

↓

履歴を保存する
```

もし途中で

- サーバー停止
- 通信エラー
- 同時アクセス

などが起きても、

データが壊れないようにするためのルールがACID特性です。

---

# A：Atomicity（原子性）

## 「全部成功するか、全部失敗するか」

Atomicは「原子」という意味ですが、

ここでは

**「これ以上分けられない1つの処理」**

という意味で使われています。

例えば送金なら

```
① 残高を減らす

② 残高を増やす
```

この2つはセットです。

途中で失敗したら

```
全部取り消す
```

つまり

```
ROLLBACK
```

になります。

---

### イメージ

```
〇

全部成功

または

×

全部失敗
```

途中だけ成功はありません。

---

# C：Consistency（一貫性）

## 「データのルールが壊れない」

データベースには

```
残高はマイナスにならない

メールアドレスは重複しない

会員IDは必ず存在する
```

などのルールがあります。

処理が終わったあとも

これらのルールが守られている状態が

**一貫性（Consistency）**です。

---

### イメージ

```
更新前

正常

↓

更新後

正常
```

どちらも正しい状態である必要があります。

---

# I：Isolation（独立性）

## 「他の処理の影響を受けない」

例えば

```
Aさん

購入中
```

と

```
Bさん

購入中
```

が同時に行われた場合、

途中のデータを見られてしまうと

誤った計算になる可能性があります。

そのため、

トランザクション同士を

**お互い独立して実行する**

仕組みがあります。

これを

**Isolation（独立性）**

といいます。

---

### イメージ

```
Aさん処理

───────

Bさん処理
```

お互いが干渉しないように動作します。

---

# D：Durability（永続性）

## 「保存したデータは消えない」

COMMITが終わったら、

そのデータは正式なデータになります。

もし

```
COMMIT

↓

サーバー停止
```

となっても

```
保存したデータ
```

は残っています。

これが

**Durability（永続性）**

です。

---

### イメージ

```
COMMIT

↓

保存

↓

停電

↓

再起動

↓

データは残っている
```

---

# 実務ではどう役立つ？

例えばECサイト。

```
注文登録

↓

在庫更新

↓

決済

↓

履歴保存
```

ACIDがあることで

- 注文だけ登録される
- 決済だけ成功する
- 在庫だけ減る

といった事故を防げます。

銀行、証券会社、病院、会員管理など、

**信頼性が重要なシステムでは必須の考え方**です。

---

# ACIDを覚えるコツ

| 頭文字 | 覚え方 |
|---------|--------|
| A | 全部成功・全部失敗 |
| C | データのルールを守る |
| I | 他の処理と干渉しない |
| D | 保存したら消えない |

---

# 4つの関係

```
ACID

├── A：Atomicity
│      全部成功・全部失敗
│
├── C：Consistency
│      データの整合性を保つ
│
├── I：Isolation
│      他の処理と干渉しない
│
└── D：Durability
       保存したデータは消えない
```

---

# まとめ

- ACID特性は**トランザクションの信頼性を支える4つのルール**
- **A（Atomicity）**：全部成功するか、全部失敗するか
- **C（Consistency）**：データのルールを保つ
- **I（Isolation）**：他のトランザクションの影響を受けない
- **D（Durability）**：COMMITしたデータは消えない

> **一言で覚えるなら**
>
> **「ACID = トランザクションを安全・正確・確実に実行するための4つの約束」**
