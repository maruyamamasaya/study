## 同時更新によるデータの不整合を防ぐ仕組み

---

# 概要

**排他制御（はい他制御）**とは、

**複数のユーザーが同じデータを同時に更新しないように制御する仕組み**です。

簡単に言うと、

> **「同じデータは、一度に1人だけ更新できるようにする仕組み」**

です。

データベースでは、多くのユーザーが同時にアクセスするため、排他制御はデータの整合性を保つために欠かせません。

---

# なぜ必要なの？

例えば、

銀行口座の残高が

```
100,000円
```

だったとします。

同じタイミングで、

- Aさんが30,000円引き出す
- Bさんが20,000円引き出す

という処理が実行された場合を考えます。

---

## 排他制御がない場合

Aさん

```
残高を見る

100,000円
```

↓

30,000円引き出す

↓

70,000円

---

同時に

Bさん

```
残高を見る

100,000円
```

↓

20,000円引き出す

↓

80,000円

最終結果

```
80,000円
```

になってしまいました。

本来は

```
100,000円

↓

30,000円

↓

20,000円

↓

50,000円
```

であるべきです。

これを**更新の競合（Lost Update）**と呼びます。

---

# 排他制御がある場合

Aさんが更新を開始すると、

```
口座データ

↓

🔒 ロック
```

されます。

```
Aさん

更新中
```

↓

```
Bさん

待機
```

↓

```
Aさん

COMMIT
```

↓

```
Bさん

更新開始
```

となります。

その結果、

```
100,000円

↓

70,000円

↓

50,000円
```

と正しい結果になります。

---

# イメージ図

```
データ

↓

🔒 排他制御

↓

Aさん更新

↓

COMMIT

↓

🔓

↓

Bさん更新
```

更新は必ず順番に行われます。

---

# 排他制御はどう実現する？

排他制御を実現する方法はいくつかありますが、

最もよく使われるのが**ロック**です。

```
更新開始

↓

ロック

↓

更新

↓

COMMIT

↓

ロック解除
```

ロックによって、

他のユーザーは更新が終わるまで待機します。

---

# 排他制御の種類

## ① 悲観的排他制御（Pessimistic Lock）

「同時更新は起こるもの」と考え、

最初からロックをかける方法です。

```
更新開始

↓

ロック

↓

更新

↓

COMMIT
```

### 特徴

- データの安全性が高い
- 同時更新に強い
- 待ち時間が発生することがある

---

## ② 楽観的排他制御（Optimistic Lock）

「同時更新はあまり起こらない」と考え、

ロックをかけずに更新し、

最後に競合がないか確認します。

例えば、

```
バージョン番号

更新日時
```

などを比較し、

他の人が更新していた場合は

```
エラー

↓

再実行
```

となります。

### 特徴

- 待ち時間が少ない
- 読み取りが多いシステムに向いている
- 競合時は再実行が必要

---

# SQLではどうなる？

例えば、

```sql
BEGIN;

UPDATE products
SET stock = stock - 1
WHERE id = 1;

COMMIT;
```

更新中は

```
商品ID = 1
```

にロックがかかります。

他のユーザーが同じ商品を更新しようとすると、

```
待機
```

になります。

これが排他制御です。

---

# 排他制御とロックの違い

初心者が混同しやすいポイントです。

| 排他制御 | ロック |
|----------|--------|
| データを安全に更新するための考え方 | 排他制御を実現する具体的な仕組み |
| 「同時更新を防ぐ」という目的 | 「鍵をかける」という手段 |

つまり、

```
排他制御

↓

ロックを使って実現する
```

という関係になります。

---

# 排他制御とデッドロック

ロックを使うことで、

まれに

```
AがB待ち

↓

BがA待ち
```

となることがあります。

これが

**デッドロック**です。

そのため、

- 更新順序を統一する
- トランザクションを短くする

などの工夫が重要になります。

---

# 実務ではどこで使われる？

排他制御は、

同時更新が発生するシステムでは必ず使われています。

### ECサイト

- 在庫更新
- 注文処理

---

### 銀行システム

- 振込
- 入出金

---

### ホテル・航空券予約

- 空席予約
- 客室予約

---

### ゲーム

- アイテム購入
- ポイント更新

---

### SNS

- いいね数
- フォロワー数

---

```

```

```
デッドロック
```

が発生することがあります。

---

# まとめ

- 排他制御は**同じデータを同時に更新しないようにする仕組み**
- データの整合性を保つために重要
- 一般的にはロックを使って実現される
- 「悲観的排他制御」と「楽観的排他制御」の2種類がある
- 銀行・ECサイト・予約システムなど、同時更新が発生するシステムでは必須の考え方

> **一言で覚えるなら**
>
> **「排他制御 = 同じデータを一度に1人だけ更新できるようにする仕組み」**
