## データを素早く見つけるための「索引」の仕組み

---

# 概要

**インデックス（Index）**とは、

**データベースで検索を高速化するための仕組み**です。

簡単に言うと、

> **「本の索引（さくいん）」**

のようなものです。

インデックスを作ることで、

目的のデータをすばやく見つけられるようになります。

---

# なぜ必要なの？

例えば、

100万件の社員データがあるとします。

その中から

```
社員ID = 950000
```

の社員を探したい場合、

インデックスがないと…

```
1件目

↓

2件目

↓

3件目

↓

・・・

↓

950000件目
```

というように、

最初から順番に探していく必要があります。

これを**フルスキャン（全件検索）**と呼びます。

データが多くなるほど時間がかかります。

---

# インデックスがあるとどうなる？

インデックスがあると、

データを順番に探す必要がありません。

イメージとしては、

```
社員ID

↓

950000

↓

場所がすぐ分かる

↓

データを取得
```

という流れになります。

つまり、

目的のデータへ最短でたどり着けます。

---

# 本の索引で考えてみよう

例えば500ページある本で、

「インデックス」という言葉を探したいとします。

### インデックスがない場合

```
1ページ

↓

2ページ

↓

3ページ

↓

・・・

↓

500ページ
```

すべて読む必要があります。

---

### インデックスがある場合

本の最後を見ると

```
インデックス

・・・

P348
```

と書いてあります。

```
索引を見る

↓

348ページ

↓

目的の内容
```

すぐに見つけられます。

データベースのインデックスも

これと同じ考え方です。

---

# イメージ図

```
インデックスなし

データ

①

②

③

④

⑤

⑥

⑦

・・・

↓

全部見る
```

---

```
インデックスあり

索引

950000

↓

場所が分かる

↓

データ取得
```

---

# SQLではどう書く？

例えば社員テーブル。

```sql
CREATE TABLE employee (
    id INT,
    name VARCHAR(100),
    department VARCHAR(50)
);
```

名前で検索することが多いなら、

```sql
CREATE INDEX idx_name
ON employee(name);
```

これで

```
name
```

にインデックスが作成されます。

---

# インデックスが効果を発揮する検索

例えば、

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

インデックスがあると、

名前からすぐに探せます。

---

主キー検索も同じです。

```sql
SELECT *
FROM employee
WHERE id = 100;
```

Primary Keyには、

多くのデータベースで自動的にインデックスが作成されます。

そのため、

主キー検索は非常に高速です。

---

# インデックスのメリット

## ① 検索が速くなる

```
100万件

↓

数件だけ確認
```

で済みます。

---

## ② JOINも速くなる

```sql
JOIN employee
ON orders.employee_id = employee.id
```

JOINでは

Primary KeyやForeign Keyを使うことが多いため、

インデックスがあると結合処理も高速になります。

---

## ③ ORDER BYも速くなることがある

```sql
ORDER BY name
```

インデックスの順番を利用できれば、

並び替えも効率的になります。

---

# インデックスのデメリット

良いことばかりではありません。

### ① 更新が少し遅くなる

データを追加するとき、

```
データ追加

↓

インデックス更新
```

も行われます。

そのため、

INSERT・UPDATE・DELETEは少し遅くなります。

---

### ② 保存容量が増える

インデックス自体も

データとして保存されるため、

ディスク容量を使用します。

---

### ③ 作りすぎは逆効果

例えば、

すべての列にインデックスを付けると…

```
更新が遅い

容量が大きい

管理が大変
```

となります。

そのため、

**よく検索される列だけ**に作成するのが基本です。

---

# 実務ではどこで使われる？

インデックスは、

検索が多い列によく作られます。

### ECサイト

```
商品ID

商品名

カテゴリ
```

---

### 会員管理

```
メールアドレス

会員ID
```

---

### 社員管理

```
社員番号

部署
```

---

### SNS

```
ユーザーID

投稿日時
```

このように、

検索条件として頻繁に使われる列に設定されます。

---

# Primary Keyとの関係

以前学んだPrimary Keyには、

多くのデータベースで

**自動的にインデックス**が作成されます。

そのため、

```sql
SELECT *
FROM employee
WHERE id = 1;
```

のような検索は、

非常に高速です。

---

# フルスキャンとの違い

| フルスキャン | インデックス検索 |
|-------------|------------------|
| 全件を見る | 必要な場所だけ見る |
| データが多いと遅い | データが多くても速い |
| インデックス不要 | インデックスが必要 |

---

# まとめ

- インデックスは**検索を高速化するための仕組み**
- 本の「索引」のような役割を持つ
- WHERE・JOIN・ORDER BYなどで効果を発揮する
- Primary Keyには自動で作成されることが多い
- 作りすぎると更新速度や容量に影響するため、必要な列だけに設定する

> **一言で覚えるなら**
>
> **「インデックス = データをすばやく見つけるための索引」**
