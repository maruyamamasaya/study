## テーブルのデータを最初から最後まで全部読む検索方法

---

# 概要

**Full Scan（フルスキャン）**とは、

**テーブル内のすべてのデータを順番に読み込んで検索する方法**です。

データベースによっては、

- **Table Scan**
- **Full Table Scan**
- **Sequential Scan（PostgreSQL）**

などと呼ばれることもあります。

簡単に言うと、

> **「テーブルを最初から最後まで全部調べる検索方法」**

です。

---

# なぜFull Scanになるの？

例えば、

100万件の社員データがあるとします。

その中から

```
名前が「山田」の社員
```

を探したいとします。

しかし、

名前にインデックスが無い場合、

データベースは

```
1件目

↓

2件目

↓

3件目

↓

・・・

↓

100万件目
```

と、

順番に確認するしかありません。

これが

**Full Scan**

です。

---

# イメージ図

```
社員テーブル

────────────

①

②

③

④

⑤

⑥

⑦

⑧

・・・

100万件
```

検索すると…

```
① ✓

② ✓

③ ✓

④ ✓

⑤ ✓

⑥ ✓

・・・

全部見る
```

必要なデータが最後にあった場合でも、

すべて確認します。

---

# 本で例えると

500ページある本で

```
「データベース」
```

という単語を探したいとします。

索引（インデックス）が無ければ、

```
1ページ

↓

2ページ

↓

3ページ

↓

・・・

↓

500ページ
```

全部読むしかありません。

これがFull Scanです。

---

# SQLではどうなる？

例えば、

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

名前にインデックスが無い場合、

EXPLAINでは

```
Full Scan

または

Table Scan
```

と表示されることがあります。

つまり、

```
全件検索しています
```

という意味です。

---

# EXPLAINのイメージ

```sql
EXPLAIN
SELECT *
FROM employee
WHERE name = '山田';
```

結果（イメージ）

| Operation | Rows |
|-----------|------:|
| Full Table Scan | 1000000 |

これは、

```
100万件読む予定
```

という意味になります。

---

# Full Scanが悪いわけではない

初心者は

```
Full Scan = 悪い
```

と思いがちですが、

必ずしもそうではありません。

例えば、

```sql
SELECT *
FROM employee;
```

これは

```
全部の社員を取得したい
```

ので、

最初から全部読むのが一番効率的です。

---

また、

10件しかデータが無いテーブルなら、

```
全部読む
```

ほうが速い場合もあります。

---

# Full Scanになるケース

### インデックスが無い

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

---

### 全件取得

```sql
SELECT *
FROM employee;
```

---

### 条件に一致するデータが多い

例えば、

```sql
WHERE gender = '男性'
```

のように、

ほとんどのデータが対象になる場合は、

インデックスを使うより、

全部読んだほうが速いことがあります。

---

# Index Scanとの違い

| Index Scan | Full Scan |
|------------|-----------|
| インデックスを利用する | インデックスを利用しない |
| 必要なデータだけ読む | 全件読む |
| データが多いほど有利 | データが多いほど遅くなりやすい |
| 主キー検索などが得意 | 全件取得などが得意 |

---

# 実務ではどこで使われる？

Full Scanは、

次のような場面で発生します。

### インデックスが無い検索

```
商品名検索

メールアドレス検索

社員名検索
```

---

### 全件集計

```sql
SELECT COUNT(*)
FROM employee;
```

---

### レポート作成

全社員一覧

全注文一覧

売上集計

など、

すべてのデータを対象とする処理では、

Full Scanになることがあります。

---

# Full Scanを減らすには？

検索が遅い場合は、

次のような改善を行います。

### インデックスを作成する

```sql
CREATE INDEX idx_name
ON employee(name);
```

---

### WHERE条件を見直す

不要な検索を減らします。

---

### EXPLAINで確認する

```sql
EXPLAIN
SELECT ...
```

を実行し、

```
Full Scan

↓

Index Scan
```

へ改善できないか確認します。

---

# 関連知識

今回学んだ内容は、

次のようにつながっています。

```
インデックスを作る

↓

EXPLAINで確認する

↓

Index Scanなら高速

↓

Full Scanなら改善を検討
```

この流れは、

SQLのパフォーマンス改善で非常によく使われます。

---

# まとめ

- Full Scanは**テーブル全体を順番に読み込む検索方法**
- インデックスが無い場合によく発生する
- データ量が多いと時間がかかりやすい
- 全件取得や小さなテーブルでは、Full Scanの方が効率的な場合もある
- EXPLAINを使って、Full Scanになっていないか確認し、必要に応じてインデックスを追加する

> **一言で覚えるなら**
>
> **「Full Scan = テーブルを最初から最後まで全部読む検索方法」**
