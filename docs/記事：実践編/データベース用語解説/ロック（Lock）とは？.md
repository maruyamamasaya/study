## データを安全に更新するための「鍵」の仕組み

---

# 概要

**ロック（Lock）**とは、

**複数のユーザーが同じデータを同時に更新しないように、一時的にデータを保護する仕組み**です。

簡単に言うと、

> **「今このデータを使っています。終わるまで待ってください。」**

という仕組みです。

データベースでは、多くの人が同時にアクセスするため、ロックはデータの整合性を保つうえで欠かせません。

---

# なぜ必要なの？

例えば、

ECサイトで商品の在庫が

```
在庫：1個
```

だったとします。

同じタイミングで、

AさんとBさんが購入ボタンを押しました。

---

## ロックが無い場合

```
Aさん

在庫 = 1

↓

購入

↓

在庫 = 0
```

同時に

```
Bさん

在庫 = 1

↓

購入

↓

在庫 = 0
```

どちらも

```
在庫 = 1
```

を見てしまったため、

**1個しかない商品が2人に売れてしまいます。**

---

# ロックがある場合

Aさんが更新を始めると、

```
商品

↓

ロック
```

されます。

```
Aさん

更新中
```

↓

```
Bさん

待機
```

↓

```
Aさん

COMMIT
```

↓

```
Bさん

更新開始
```

となります。

このように、

同時更新を防ぐことができます。

---

# イメージ図

```
商品データ

在庫 = 1

↓

🔒 ロック

↓

更新中

↓

COMMIT

↓

🔓 ロック解除
```

ロックが解除されるまで、

他の更新は待機します。

---

# ロックの種類

## ① 共有ロック（Shared Lock）

**読み取り専用**のロックです。

```
読む

↓

読む

↓

読む
```

複数人が同時に読むことができます。

しかし、

更新はできません。

イメージ

```
👀

👀

👀
```

みんな閲覧できます。

---

## ② 排他ロック（Exclusive Lock）

更新するときに使われるロックです。

```
読む

×

更新

×

削除
```

他のユーザーは、

ロックが解除されるまで待機します。

イメージ

```
🔒

更新中

↓

他の人は待機
```

---

# SQLではどうなる？

例えば、

```sql
BEGIN;

UPDATE products
SET stock = stock - 1
WHERE id = 1;

COMMIT;
```

更新中は、

商品ID=1に

```
排他ロック
```

がかかります。

他のユーザーが

同じ商品を更新しようとすると、

```
待機
```

になります。

---

# ロックはいつ解除される？

通常は、

トランザクションが終了すると解除されます。

```
BEGIN

↓

UPDATE

↓

COMMIT

↓

ロック解除
```

または

```
BEGIN

↓

UPDATE

↓

ROLLBACK

↓

ロック解除
```

になります。

---

# ロックが長いとどうなる？

例えば、

```
BEGIN

↓

UPDATE

↓

10分放置…

↓

COMMIT
```

となると、

その10分間、

他のユーザーは更新できません。

そのため、

**トランザクションはできるだけ短くする**ことが重要です。

---

# ロックとデッドロックの違い

初心者が混同しやすいのが、

ロックとデッドロックです。

| ロック | デッドロック |
|---------|-------------|
| データを守るための仕組み | ロック同士がぶつかって処理が止まる状態 |
| 正常な動作 | 問題が発生した状態 |
| データの整合性を保つ | 一方の処理をROLLBACKして解消することが多い |

つまり、

**ロックは必要な仕組み**であり、

そのロックが複雑に絡み合うことで

**デッドロック**が発生することがあります。

---

# 実務ではどこで使われる？

ロックは、

ほぼすべての業務システムで使われています。

### ECサイト

- 在庫更新
- 注文処理

---

### 銀行システム

- 入出金
- 振込

---

### 予約システム

- ホテル予約
- 飛行機の座席予約

---

### SNS

- いいね数更新
- ポイント更新

このように、

**同じデータを複数人が同時に更新する可能性がある場面**では必ず利用されています。

---

# 関連知識

今回学んだ内容は、

次のようにつながっています。

```
トランザクション

↓

ロック

↓

データを安全に更新

↓

更新完了

↓

COMMIT

↓

ロック解除
```

もし、

```
ロックA待ち

↓

ロックB待ち
```

となると、

前回学んだ**デッドロック**が発生します。

---

# まとめ

- ロックは**データを安全に更新するための仕組み**
- 更新中は他のユーザーが同じデータを変更できない
- 主に「共有ロック」と「排他ロック」の2種類がある
- COMMITやROLLBACKでロックは解除される
- トランザクションを短く保つことで、ロックによる待ち時間やデッドロックを減らせる

> **一言で覚えるなら**
>
> **「ロック = データを安全に更新するための一時的な鍵」**
