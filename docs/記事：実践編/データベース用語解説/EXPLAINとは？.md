## SQLがどのように実行されるかを確認するためのコマンド

---

# 概要

**EXPLAIN（エクスプレイン）**とは、

**SQLがどのような手順で実行されるかを確認するためのコマンド**です。

簡単に言うと、

> **「データベースがSQLをどう実行する予定なのかを見るための設計図」**

です。

SQLの実行速度が遅いとき、

「どこに原因があるのか」を調べるためによく使われます。

---

# なぜ必要なの？

例えば、

100万件の社員データから

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

を実行するとします。

結果はすぐ返ってきました。

しかし、

内部では

```
100万件すべて見た

のか

名前だけ見てすぐ見つけた

のか
```

は分かりません。

そこでEXPLAINを使うと、

データベースが

```
どのような方法で検索したか
```

を見ることができます。

---

# 基本的な仕組み

EXPLAINは、

SQLを実行する前に

```
このSQLはこう実行します
```

という実行計画（Execution Plan）を表示します。

流れは

```
SQLを書く

↓

EXPLAIN

↓

実行計画を見る

↓

改善する
```

となります。

---

# イメージ図

```
SQL

↓

EXPLAIN

↓

データベース

↓

「まずemployeeテーブルを見る」

↓

「インデックスを使う」

↓

「10件取得する」
```

このように、

SQLの実行手順を確認できます。

---

# SQLではどう書く？

例えば、

```sql
SELECT *
FROM employee
WHERE id = 100;
```

このSQLの実行計画を見るには、

```sql
EXPLAIN
SELECT *
FROM employee
WHERE id = 100;
```

と書きます。

実際には、

このような結果が返ってきます。

| id | table | type | key | rows |
|----|-------|------|-----|------:|
|1|employee|const|PRIMARY|1|

---

# よく見る項目

EXPLAINには多くの項目がありますが、

初心者は次の4つを覚えるだけで十分です。

| 項目 | 意味 |
|------|------|
| table | どのテーブルを見るか |
| type | どの方法で検索したか |
| key | 使用したインデックス |
| rows | 読み込む予定の件数 |

---

## table

```
employee
```

なら、

employeeテーブルを検索します。

---

## key

```
PRIMARY
```

なら、

Primary Keyのインデックスを使っています。

```
NULL
```

なら、

インデックスを使っていません。

---

## rows

```
1
```

なら、

1件だけ確認します。

```
1000000
```

なら、

100万件読む予定です。

rowsの数が多いほど、

時間がかかる可能性があります。

---

## type

一番重要なのが

```
type
```

です。

これは

**検索方法**

を表しています。

---

# typeの代表例

### const

```
Primary Key検索
```

最も高速です。

---

### ref

```
インデックス検索
```

かなり高速です。

---

### range

```
範囲検索
```

```sql
WHERE price > 1000
```

などで使われます。

---

### ALL

```
全件検索
```

つまり、

フルスキャンです。

100万件あれば、

100万件すべて読みます。

できれば避けたい検索方法です。

---

# インデックスの有無で比較

## インデックスあり

```sql
SELECT *
FROM employee
WHERE id = 100;
```

EXPLAIN

| type | key | rows |
|------|-----|------:|
|const|PRIMARY|1|

---

## インデックスなし

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

EXPLAIN

| type | key | rows |
|------|-----|------:|
|ALL|NULL|1000000|

この場合、

100万件すべて検索するため、

非常に遅くなります。

---

# 実務ではどこで使われる？

EXPLAINは、

SQLの性能改善で非常によく使われます。

例えば、

### ECサイト

- 商品検索が遅い
- 注文一覧が開かない

---

### 社員管理

- 社員検索が重い

---

### SNS

- 投稿一覧が表示されない
- コメント取得が遅い

---

### ダッシュボード

- 集計SQLが数十秒かかる

このような場面で、

EXPLAINを使って原因を調査します。

---

# EXPLAINで分かること

例えば、

```
rows = 1000000

↓

type = ALL

↓

key = NULL
```

となっていたら、

「インデックスが使われていないため、全件検索している」

と判断できます。

そこから、

```
インデックスを追加する
```

などの改善につなげることができます。

---

# インデックスとの関係

前回学んだ

**インデックス**が正しく使われているかを確認するのが、

EXPLAINの代表的な使い方です。

つまり、

```
インデックスを作る

↓

EXPLAINで確認する

↓

高速になったかを見る
```

という流れになります。

---

# まとめ

- EXPLAINは**SQLの実行計画を確認するコマンド**
- SQLがどのような順番・方法で実行されるかが分かる
- `table`・`type`・`key`・`rows` が特に重要
- `type = ALL` は全件検索（フルスキャン）なので注意
- インデックスが使われているかを確認し、SQLの性能改善に役立つ

> **一言で覚えるなら**
>
> **「EXPLAIN = SQLの実行方法を見える化するコマンド」**
