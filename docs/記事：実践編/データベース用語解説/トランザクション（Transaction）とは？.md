## データを安全に更新するための仕組み

---

# 概要

トランザクション（Transaction）とは、

**「複数のデータ更新を、ひとまとまりの処理として扱う仕組み」**です。

簡単に言うと、

> **全部成功するか、全部失敗するかを保証する仕組み**

とも言えます。

データベースでは、途中まで更新されてデータが壊れてしまうことを防ぐために使われます。

---

# なぜ必要なの？

例えば銀行の送金を考えてみます。

AさんからBさんへ1,000円送金する場合、

本当は次の2つの処理を行います。

```
① Aさんの残高を1000円減らす

② Bさんの残高を1000円増やす
```

しかし、①が終わった直後にサーバーが停止すると…

```
Aさん：-1000円

Bさん：変わらない
```

という状態になります。

これでは、お金がどこかへ消えてしまいます。

そこでトランザクションを使うことで、

```
両方成功する

または

両方元に戻す
```

という動きになります。

---

# 基本的な仕組み

トランザクションの流れは非常にシンプルです。

```
開始

↓

処理①

↓

処理②

↓

成功？

↓

Yes → COMMIT（確定）

No → ROLLBACK（元に戻す）
```

# イメージしやすい例

## ECサイト

あなたが商品を購入すると、

実は裏側ではたくさんの処理が動いています。

```
注文を登録

↓

在庫を減らす

↓

決済する

↓

ポイントを付与する

↓

購入履歴を保存する
```

もし途中で失敗すると…

```
注文だけ登録された

でも決済されていない
```

や

```
決済された

でも注文が存在しない
```

というおかしな状態になります。

そのため、

```
全部成功

または

全部失敗
```

にする必要があります。

---

# SQLではどう書く？

まずトランザクションを開始します。

```sql
BEGIN;
```

処理を書きます。

```sql
UPDATE account
SET balance = balance - 1000
WHERE id = 1;

UPDATE account
SET balance = balance + 1000
WHERE id = 2;
```

問題なければ

```sql
COMMIT;
```

途中でエラーになれば

```sql
ROLLBACK;
```

を実行して最初の状態へ戻します。

---

# 実務ではどこで使われる？

トランザクションはほぼすべての業務システムで使われています。

例えば

- ネット銀行
- クレジットカード決済
- ECサイト
- 会員登録
- ポイント付与
- 在庫管理
- チケット予約
- ゲームのアイテム購入

など、

**複数のデータをまとめて更新する処理**では必ずと言っていいほど利用されています。

---

# トランザクションがないとどうなる？

例えば購入処理。

```
注文登録　　○

在庫更新　　○

決済　　　　×

ポイント　　×

履歴保存　　×
```

途中で止まると

```
注文だけ存在する
```

という壊れたデータになります。

トランザクションがあると

```
全部成功

または

全部キャンセル
```

になるので、安全にデータを管理できます。

---

# よく一緒に出てくる用語

| 用語 | 意味 |
|------|------|
| BEGIN | トランザクション開始 |
| COMMIT | 更新内容を確定する |
| ROLLBACK | 更新内容を元に戻す |
| ACID | トランザクションが守る4つの性質 |
| Lock（ロック） | 同時更新を防ぐ仕組み |

---

# まとめ

- トランザクションは**複数の処理を1つのまとまりとして扱う仕組み**
- **全部成功するか、全部失敗するか**を保証する
- データが途中で壊れることを防ぐ
- 銀行・ECサイト・予約システムなどで必須の機能
- COMMITで確定、ROLLBACKで元に戻す

> **一言で覚えるなら**
>
> **「トランザクション = データを安全に更新するための保険」**
