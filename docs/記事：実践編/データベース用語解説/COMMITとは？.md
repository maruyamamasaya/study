## トランザクションで行った変更を「正式に保存する」命令

---

# 概要

**COMMIT（コミット）**とは、

**トランザクション内で行ったデータの変更を確定し、データベースへ正式に保存する命令**です。

簡単に言うと、

> **「ここまでの変更で問題ないので、保存してください！」**

とデータベースに伝える命令です。

---

# なぜ必要なの？

トランザクション中は、データの変更が一時的な状態になっています。

例えば銀行の送金では、

```
BEGIN

↓

Aさん -1000円

↓

Bさん +1000円
```

ここまではまだ「仮の変更」です。

最後に

```sql
COMMIT;
```

を実行すると、

```
Aさん -1000円

Bさん +1000円
```

が正式なデータとして保存されます。

---

# 基本的な仕組み

トランザクションの流れは次のようになります。

```
BEGIN

↓

UPDATE

↓

UPDATE

↓

COMMIT
```

COMMITが実行されるまでは、

**「まだ取り消せる状態」**

です。

COMMITした瞬間に、

**「変更が確定し、元に戻せなくなる」**

というイメージです。

---

# 具体例

銀行送金の例です。

```sql
BEGIN;

UPDATE account
SET balance = balance - 1000
WHERE id = 1;

UPDATE account
SET balance = balance + 1000
WHERE id = 2;

COMMIT;
```

この最後の

```sql
COMMIT;
```

によって、

- Aさんの残高
- Bさんの残高

両方が正式に保存されます。

---

# COMMITしなかったら？

もしCOMMITしないまま処理が終了すると、

データベースによっては変更が破棄されます。

```
BEGIN

↓

UPDATE

↓

終了
```

結果

```
変更されていない
```

となることがあります。

そのため、トランザクションを使う場合は、

```
BEGIN

↓

処理

↓

COMMIT
```

までが1セットになります。

---

# 実務での使われ方

COMMITは、複数の更新がすべて成功したときに実行されます。

例えば、

### ECサイト

```
注文登録

↓

在庫更新

↓

決済完了

↓

ポイント付与

↓

COMMIT
```

---

### 会員登録

```
ユーザー作成

↓

プロフィール作成

↓

初期設定登録

↓

COMMIT
```

---

### 銀行送金

```
引き落とし

↓

入金

↓

履歴保存

↓

COMMIT
```

---

# ROLLBACKとの違い

| COMMIT | ROLLBACK |
|---------|----------|
| 変更を保存する | 変更を元に戻す |
| 成功時に使う | エラー時に使う |
| データが正式に更新される | 更新前の状態へ戻る |

---

# よくあるイメージ

例えばWordで文章を書いているとします。

```
文章を書く
```

↓

```
保存ボタンを押す
```

この

**「保存ボタン」**

がCOMMITです。

保存する前なら編集をやり直せますが、

保存した後は、その内容が正式なデータになります。

---

# まとめ

- COMMITは**変更内容を正式に保存する命令**
- トランザクションの最後に実行する
- COMMITするまでは変更は仮の状態
- COMMITすると変更が確定する
- 実務では決済・注文・会員登録など、多くの処理で使われる

> **一言で覚えるなら**
>
> **「COMMIT = 変更内容を確定して保存する命令」**
