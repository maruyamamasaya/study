## お互いに待ち続けて処理が止まってしまう状態

---

# 概要

**デッドロック（Deadlock）**とは、

**複数の処理がお互いの処理が終わるのを待ち続け、どちらも先に進めなくなる状態**です。

簡単に言うと、

> **「お互いに譲らず、永遠に待ち続けてしまう状態」**

のことです。

データベースでは、複数のユーザーが同時にデータを更新するときに発生することがあります。

---

# なぜ起こるの？

例えば、

社員Aと社員Bが同時にデータを更新しているとします。

### 社員A

```
商品Aをロック
```

↓

```
商品Bも更新したい
```

---

### 社員B

```
商品Bをロック
```

↓

```
商品Aも更新したい
```

すると…

```
社員A

商品Aを持っている

↓

商品Bを待つ


社員B

商品Bを持っている

↓

商品Aを待つ
```

お互いが相手の終了を待ってしまい、

**どちらも処理を続けられなくなります。**

これがデッドロックです。

---

# イメージ図

```
社員A

商品Aをロック

↓

商品B待ち

        ▲
        │
        │
        │
商品A待ち

↓

商品Bをロック

社員B
```

お互いに待ち続けるため、

処理が止まってしまいます。

---

# 日常生活で例えると

狭い一本道で、

2人が向かい合ってしまったとします。

```
A → ← B
```

Aは

```
Bが動くまで進めない
```

Bも

```
Aが動くまで進めない
```

すると、

```
誰も動けない
```

状態になります。

これがデッドロックです。

---

# SQLではどんな場面？

例えば、

## トランザクションA

```sql
BEGIN;

UPDATE products
SET stock = stock - 1
WHERE id = 1;

-- 次に商品2も更新
UPDATE products
SET stock = stock - 1
WHERE id = 2;

COMMIT;
```

---

## トランザクションB

```sql
BEGIN;

UPDATE products
SET stock = stock - 1
WHERE id = 2;

-- 次に商品1も更新
UPDATE products
SET stock = stock - 1
WHERE id = 1;

COMMIT;
```

もし同時に実行されると…

```
A

商品1をロック

↓

商品2待ち


B

商品2をロック

↓

商品1待ち
```

となり、

デッドロックが発生します。

---

# データベースはどうするの？

実は、

ほとんどのデータベースは

デッドロックを自動で検知します。

検知すると、

```
どちらか一方の処理

↓

強制終了（ROLLBACK）
```

します。

例えば、

```
A 続行

B ROLLBACK
```

のようになります。

これにより、

もう一方は処理を続けられます。

---

# デッドロックを防ぐ方法

## ① 更新する順番を統一する

例えば、

```
必ず

商品1

↓

商品2
```

の順番で更新すると決めます。

すると、

お互いが同じ順番になるので、

待ち状態になりにくくなります。

---

## ② トランザクションを短くする

```
BEGIN

↓

更新

↓

COMMIT
```

までを素早く終わらせることで、

ロック時間を短くできます。

---

## ③ 必要以上にロックしない

更新する必要のないデータまで

ロックしないようにします。

---

## ④ エラー時は再実行する

デッドロックは、

完全に防ぐことが難しい場合もあります。

そのため実務では、

```
デッドロック発生

↓

ROLLBACK

↓

もう一度実行
```

という仕組みを作ることもあります。

---

# 実務ではどこで使われる？

デッドロックは、

同時更新が多いシステムで発生する可能性があります。

### ECサイト

- 在庫更新
- 注文処理

---

### 銀行システム

- 口座振替
- 入出金処理

---

### 予約システム

- 座席予約
- ホテル予約

---

### ゲーム

- アイテム購入
- ポイント更新

同じデータを同時に更新する場面では、

デッドロック対策が重要になります。

---

# ロックとの関係

以前学んだ

**ロック**は、

データを安全に更新するための仕組みでした。

しかし、

```
ロックA

↓

ロックB待ち

↓

ロックB

↓

ロックA待ち
```

となると、

デッドロックが発生します。

つまり、

**デッドロックはロックを使うことで起こり得る問題**です。

---

# まとめ

- デッドロックは**お互いに待ち続けて処理が止まる状態**
- 同時更新時に発生しやすい
- データベースは通常、デッドロックを検知して一方をROLLBACKする
- 更新順序を統一し、トランザクションを短くすることで発生を減らせる
- 同時アクセスが多いシステムでは、必ず意識したい重要な概念

> **一言で覚えるなら**
>
> **「デッドロック = お互いにロックを待ち続け、どちらも進めなくなる状態」**
