## テーブル同士を「正しく関連付ける」ための仕組み

---

# 概要

データベースでは、1つのテーブルだけで管理することは少なく、

- 商品
- 注文
- 会員
- 部署

など、役割ごとに複数のテーブルへ分けて管理します。

そのテーブル同士をつなぐために使われるのが、

- **Primary Key（主キー）**
- **Foreign Key（外部キー）**

です。

簡単に言うと、

> **Primary Keyは「自分自身を識別するID」**
>
> **Foreign Keyは「他のテーブルを指すID」**

になります。

---

# なぜ必要なの？

例えばECサイトを考えてみます。

注文データには

```
注文ID：100
商品：パソコン
価格：120,000円
メーカー：A社
```

という情報を保存することもできます。

しかし、

パソコンが1000件売れたら…

```
商品名

価格

メーカー
```

が1000回保存されることになります。

そのため、

```
商品情報

↓

商品テーブル
```

```
注文情報

↓

注文テーブル
```

のように分けて管理します。

すると、

「この注文はどの商品なの？」

という情報が必要になります。

そこで使われるのが

**Primary Key**と**Foreign Key**です。

---

# Primary Key（主キー）とは？

Primary Keyとは、

**テーブル内の1件のデータを一意に識別するためのキー**です。

つまり、

> **「このデータは世界に1つだけ」と識別するための番号**

になります。

例えば商品テーブル。

| 商品ID | 商品名 | 価格 |
|--------|--------|------:|
| 1 | パソコン |120,000円|
| 2 | マウス |5,000円|
| 3 | キーボード |8,000円|

ここでは

```
商品ID
```

がPrimary Keyです。

---

## Primary Keyの特徴

### ① 重複できない

```
1

2

3
```

はOKですが、

```
1

1

2
```

はNGです。

同じIDが2つあると、

どちらのデータか分からなくなります。

---

### ② NULLにできない

```
商品ID

NULL
```

では、

データを識別できません。

そのため、

Primary Keyは必ず値を持っています。

---

# Foreign Key（外部キー）とは？

Foreign Keyとは、

**他のテーブルのPrimary Keyを参照するためのキー**です。

簡単に言うと、

> **「このデータは、どのデータと関連していますか？」**

を表すIDです。

---

例えば注文テーブル。

| 注文ID | 商品ID |
|--------|--------|
|100|1|
|101|2|
|102|1|

ここで

```
商品ID
```

は、

商品テーブルの

```
商品ID
```

を指しています。

つまり、

注文テーブルの

```
商品ID
```

がForeign Keyです。

---

# イメージ図

```
商品テーブル

──────────────

商品ID（Primary Key）

1 パソコン

2 マウス

3 キーボード


        ▲
        │
        │ 参照
        │


注文テーブル

──────────────

注文ID

100 → 商品ID = 1

101 → 商品ID = 2

102 → 商品ID = 1
```

つまり、

注文テーブルは

商品テーブルのIDを見て、

「どの商品を注文したか」

を判断しています。

---

# SQLではどう書く？

商品テーブル

```sql
CREATE TABLE products (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    price INT
);
```

注文テーブル

```sql
CREATE TABLE orders (
    id INT PRIMARY KEY,
    product_id INT,
    FOREIGN KEY (product_id)
        REFERENCES products(id)
);
```

この

```sql
REFERENCES products(id)
```

によって、

```
orders.product_id

↓

products.id
```

という関係が作られます。

---

# JOINとの関係

以前学んだJOINは、

Primary KeyとForeign Keyを利用して

テーブル同士を結合しています。

例えば、

```sql
SELECT
    orders.id,
    products.name
FROM orders
JOIN products
ON orders.product_id = products.id;
```

結果

| 注文ID | 商品名 |
|--------|--------|
|100|パソコン|
|101|マウス|
|102|パソコン|

このように、

注文テーブルだけでは分からなかった

商品名まで取得できます。

---

# Foreign Keyがあるメリット

## 存在しないデータを防げる

例えば、

商品テーブルに

```
商品ID = 5
```

が存在しないのに、

注文テーブルへ

```
商品ID = 5
```

を登録してしまうと、

存在しない商品を注文したことになります。

Foreign Key制約があると、

このような登録はエラーになります。

つまり、

**テーブル同士の整合性（正しさ）を保つことができます。**

---

# 実務ではどこで使われる？

Primary KeyとForeign Keyは、

ほぼすべてのシステムで利用されています。

### ECサイト

```
商品

↓

注文
```

---

### SNS

```
ユーザー

↓

投稿

↓

コメント
```

コメントには

```
投稿ID

ユーザーID
```

が保存されています。

---

### 社員管理

```
部署

↓

社員
```

社員は

```
部署ID
```

を持っています。

---

### 学校システム

```
授業

↓

履修情報

↓

学生
```

このように、

**テーブル同士をつなぐための基本となる仕組み**です。

---

# Primary KeyとForeign Keyの違い

| Primary Key | Foreign Key |
|--------------|-------------|
| データを識別するID | 他のデータを指すID |
| テーブル内で一意 | 同じ値を持ってもよい |
| NULL不可 | 設計によってNULL可 |
| 通常1テーブルに1つ | 必要に応じて複数持てる |

---

# 初心者向けの覚え方

## Primary Key

> **「自分のマイナンバー・社員番号」**

自分自身を識別する番号です。

---

## Foreign Key

> **「相手へのリンク」**

「どの商品？」

「どの部署？」

「どのユーザー？」

を示す番号です。

---

# まとめ

- **Primary Key**は、データを一意に識別するためのID
- **Foreign Key**は、他のテーブルのPrimary Keyを参照するID
- テーブル同士を関連付けるために使われる
- JOINは、この2つのキーを使ってデータを結合する
- データの整合性を保つために、実務では非常に重要な役割を持つ

> **一言で覚えるなら**
>
> **「Primary Key = 自分のID、Foreign Key = 相手を指すID」**
