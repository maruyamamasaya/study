## インデックスを使って効率よくデータを探す検索方法

---

# 概要

**Index Scan（インデックススキャン）**とは、

**インデックスを利用してデータを検索する方法**です。

簡単に言うと、

> **「インデックス（索引）を使って、必要なデータだけを探す検索方法」**

です。

EXPLAINでSQLを確認すると、

実行方法として表示されることがあります。

---

# なぜ必要なの？

例えば、

100万件の社員データがあるとします。

その中から

```
社員ID = 950000
```

の社員を探したい場合、

インデックスがないと…

```
1件目

↓

2件目

↓

3件目

↓

・・・

↓

950000件目
```

と順番に探さなければなりません。

これを**フルスキャン（Full Table Scan）**と呼びます。

非常に時間がかかります。

---

# Index Scanならどうなる？

インデックスがあると、

まず索引を見ます。

```
インデックス

↓

社員ID = 950000

↓

保存場所が分かる

↓

データ取得
```

必要な場所だけ読むので、

検索がとても速くなります。

---

# 本の索引で考えてみよう

500ページの本で

「インデックス」という言葉を探すとします。

### フルスキャン

```
1ページ

↓

2ページ

↓

3ページ

↓

・・・

↓

500ページ
```

全部読む必要があります。

---

### Index Scan

```
本の索引

↓

インデックス

↓

348ページ

↓

348ページを見る
```

すぐに目的のページへたどり着けます。

データベースでも同じ考え方です。

---

# イメージ図

```
インデックス

──────────

山田

↓

120番

佐藤

↓

350番

鈴木

↓

900番


        │

        ▼

実際のデータ

──────────

・・・

120 山田

・・・

350 佐藤

・・・

900 鈴木
```

まずインデックスを調べてから、

必要なデータだけ取得します。

---

# SQLではどう使われる？

例えば、

```sql
SELECT *
FROM employee
WHERE id = 100;
```

Primary Keyには

通常インデックスがあります。

EXPLAINすると、

データベースによっては

```
Index Scan
```

や

```
Index Lookup
```

などが表示されます。

つまり、

インデックスを利用して検索しているという意味です。

---

# EXPLAINのイメージ

例えば、

```sql
EXPLAIN
SELECT *
FROM employee
WHERE id = 100;
```

結果（イメージ）

| Operation | Rows |
|-----------|------:|
| Index Scan | 1 |

これは

```
インデックスを利用

↓

1件だけ取得
```

という意味になります。

---

# Index Scanが得意な検索

### 主キー検索

```sql
SELECT *
FROM employee
WHERE id = 100;
```

---

### 名前検索

```sql
SELECT *
FROM employee
WHERE name = '山田';
```

※ `name` にインデックスがある場合

---

### 範囲検索

```sql
SELECT *
FROM employee
WHERE id BETWEEN 100 AND 200;
```

インデックスをたどりながら、

必要な範囲だけ取得できます。

---

# Full Table Scanとの違い

| Index Scan | Full Table Scan |
|------------|-----------------|
| インデックスを使う | インデックスを使わない |
| 必要なデータだけ読む | 全件読む |
| データが多くても速い | データが増えるほど遅い |

---

# 必ずIndex Scanになる？

なりません。

例えば、

```sql
SELECT *
FROM employee;
```

では、

すべてのデータが必要なので、

インデックスを使う意味がありません。

また、

インデックスがあっても、

検索条件によっては

```
フルスキャン
```

の方が速いとデータベースが判断することもあります。

データベースは、

より高速な方法を自動で選択します。

---

# 実務ではどこで使われる？

Index Scanは、

日常的な検索処理で使われています。

### ECサイト

- 商品検索
- 商品ID検索

---

### 社員管理

- 社員番号検索
- メールアドレス検索

---

### SNS

- ユーザー検索
- 投稿検索

---

### 銀行システム

- 口座番号検索
- 顧客検索

このように、

**検索条件によく使われる列**では、

Index Scanが利用されることが多くなります。

---

# Index ScanとIndex Seekの違い

データベースによって呼び方が異なります。

| データベース | 表示例 |
|-------------|--------|
| PostgreSQL | Index Scan |
| Oracle | Index Range Scan |
| SQL Server | Index Seek |
| MySQL | type = ref / range / const など |

どれも、

**インデックスを利用した高速検索**という考え方は同じです。

---

# まとめ

- Index Scanは**インデックスを利用してデータを検索する方法**
- 本の索引のように、必要なデータだけを効率よく探せる
- EXPLAINで実行計画を確認すると表示されることがある
- Full Table Scanより高速な場合が多い
- データベースは状況に応じて、最適な検索方法を自動で選択する

> **一言で覚えるなら**
>
> **「Index Scan = インデックスを使って必要なデータだけを探す検索方法」**
