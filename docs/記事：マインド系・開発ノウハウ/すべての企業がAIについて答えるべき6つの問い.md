## 1. AI導入から「組織の再設計」へ

これまで企業のAI活用では、

- AIを導入するべきか
- どのAIツールを使うか
- ROIは出るのか
- どの業務を効率化できるか

といった問いが中心でした。

しかしAgentic AIが現実的になってきたことで、論点そのものが変わりつつあります。

```
これまで
人間 → AIに依頼 → AIが補助 → 人間が実行
        Assisted AI

これから
人間 → 目標を与える
          ↓
        AI Agent
          ↓
   判断 → ツール利用 → 実行 → 確認
          ↓
        人間が監督
        Agentic AI
```

つまり、

> **「AIをどう使うか」から「AIが存在する前提で会社をどう設計するか」へ**

という変化です。

---

# 問い1：AIを「後付け」していないか？

重要なキーワードが**Redesign（再設計）**です。

よくあるAI導入は、

```
既存業務
 ↓
既存システム
 ↓
既存ワークフロー
 ↓
AIを追加
```

というものです。

たとえば、

> 「今まで人間がExcelに入力していたので、そこだけAIに入力させよう」

という発想です。

しかし本来は、

```
そもそもExcelへの入力は必要？
        ↓
AIが元データを取得できない？
        ↓
AIが処理
        ↓
人間は例外だけ確認
```

のように、**業務そのものから設計し直す**べきです。

### Assisted AI

```
人間の仕事
   ↓
AIが一部を手伝う
   ↓
人間が完成させる
```

### Agentic AI

```
目標
 ↓
AI Agent
 ├─ 情報収集
 ├─ 判断
 ├─ システム操作
 ├─ 処理
 └─ 結果報告
 ↓
必要なところだけ人間が判断
```

AI導入ではなく、**業務プロセスの再設計**が重要になります。

---

# 問い2：「どのAIが一番強い？」で止まっていないか？

企業AIでは、

> 「GPT、Claude、Geminiのどれを使う？」

だけでは不十分になってきます。

重要なのは**AI Architecture**です。

特に次の3つがあります。

### ① マルチモデル

すべての仕事に最高性能モデルを使う必要はありません。

```
簡単な分類
 ↓
小型・低コストモデル

文章生成
 ↓
中程度モデル

複雑な設計・推論
 ↓
高性能モデル
```

つまり、

> **仕事の難易度に応じてAIを使い分ける**

という考え方です。

---

### ② ルーティング

どの仕事をどのAIに渡すか判断する仕組みです。

```
ユーザー
   ↓
AI Router
   ├─ 簡単な処理 → 軽量モデル
   ├─ コーディング → Coding Agent
   ├─ 高度な推論 → 高性能モデル
   └─ 社内検索 → RAG / 社内AI
```

企業ではこの**AI Routing Layer**が重要になります。

---

### ③ Harness

さらに重要なのが、AIを取り囲む仕組みです。

AIモデル単体では企業システムにはなりません。

```
┌──────────────────────┐
│       AI Harness     │
│                      │
│  権限管理             │
│  認証                 │
│  Context              │
│  社内データ            │
│  Tool / API           │
│  Logging              │
│  Guardrails           │
│  Cost Control         │
│                      │
│      AI Model         │
└──────────────────────┘
```

重要なのは、

> **どのAIを使うかより、AIをどう安全に企業システムへ組み込むか**

という考え方です。

---

# 問い3：AIコストを把握できているか？

AIが会社全体に広がると、API利用料やトークン費用も大きくなります。

そこで必要になるのが**AI Observability（AIの可観測性）**です。

たとえば、

```
営業部
GPT：20万円
Claude：10万円

開発部
GPT：80万円
Claude：50万円

マーケティング
GPT：30万円
画像生成：40万円
```

だけでは不十分です。

本当に知りたいのは、

```
誰が
↓
何の業務で
↓
どのモデルを
↓
何トークン使い
↓
いくらかかり
↓
どんな成果を出したか
```

です。

つまり、

> **AI Cost × AI Output**

を見る必要があります。

将来的には、

```
AI利用量
↓
モデル別コスト
↓
部署別コスト
↓
タスク別コスト
↓
成果
```

まで観測することが企業AI基盤の重要機能になっていきます。

---

# 問い4：AI研修だけで終わっていないか？

AI活用というと、

```
社員向けAI研修
↓
動画を見る
↓
プロンプトを学ぶ
↓
終了
```

となりがちです。

しかし実際のAI導入はもっと泥臭いものです。

重要なのは**実際の仕事の中でAIを使うこと**。

```
AIに詳しいチーム
        ↓
      Pairing
        ↓
AIに慣れていないチーム
        ↓
実業務で一緒に使う
```

たとえば、

```
エンジニア
   ×
マーケティング

AIエンジニア
   ×
営業

AI推進チーム
   ×
バックオフィス
```

といった形です。

目的は「全員をエンジニアにすること」ではありません。

重要なのはエンジニアやPMが持っている、

- 問題を分解する
- 要件を整理する
- AIへの指示を構造化する
- 出力を検証する
- 小さく試す
- 改善する

といった**仕事の進め方を組織全体へ広げること**です。

---

# 問い5：AIによってビジネスモデルは変わらないか？

AIは社内効率化だけでは終わりません。

最終的には、

> **「会社が何を売るのか」**

まで変える可能性があります。

たとえば従来のコンサルティングなら、

```
100時間 × 2万円
＝ 200万円
```

という**投入量ベース**の料金体系があります。

AIによって作業時間が大幅に減ると、

```
成果Aを達成
↓
100万円
```

のような**Outcome Based Pricing（成果ベース課金）**が重要になる可能性があります。

さらに、

```
AI Agent
↓
24時間監視
↓
継続的分析
↓
問題発見
↓
自動対応
```

が可能になると、

> 「そもそも今まで販売していたサービスの形は正しいのか？」

というところまで問い直されます。

---

# 問い6：「どうせ作り直す」前提で設計できているか？

AI時代では技術の変化が非常に速いため、

```
2026年
Model Aでシステム構築

↓

数か月後
Model Bが大幅に高性能化

↓

さらに数か月後
Agentの標準仕様が変化
```

といったことが普通に起こります。

そこで重要になるのが**Ephemerality（短命性）**という考え方です。

最初から、

> **「この仕組みは数年固定して使うものではない」**

と考える。

そのため、

```
アプリ
 ↓
AI抽象化レイヤー
 ↓
Routing
 ├─ Model A
 ├─ Model B
 └─ Model C
```

のようにモデルを交換できる構造にしておく。

さらに、

- モデル
- プロンプト
- Agent
- ツール
- API
- RAG
- データソース
- Guardrails

などを可能な限り疎結合にします。

つまり、

> **「変化しないシステム」を作るのではなく、「変えやすいシステム」を作る。**

これがAI時代の設計思想になります。

---

# 6つの問いをまとめる

|問い|重要な考え方|
|---|---|
|① AIを後付けしていないか|業務そのものをRedesignする|
|② モデル選びで止まっていないか|AI Architectureを設計する|
|③ AIコストを把握できているか|Cost / Token / Outputを観測する|
|④ AI研修だけで終わっていないか|実務でPairingする|
|⑤ ビジネスモデルは変わらないか|成果ベース・AIネイティブサービスを考える|
|⑥ 作り直す前提になっているか|交換可能・疎結合な設計にする|

---

# 一番重要な変化

この話の本質は、

```
AIツール導入
    ↓
AI業務活用
    ↓
AI Agent
    ↓
業務プロセス再設計
    ↓
組織再設計
    ↓
ビジネスモデル再設計
```

という流れです。

つまりAI活用の成熟度が、

**「どのAIを使っているか」ではなく、「AIを前提としてどこまで会社を再設計できているか」**

で測られるようになってきています。

特に技術面では、

> **マルチモデル + Routing + Harness + Observability**

という構成が重要です。

そして組織面では、

> **AIに仕事を任せることより、人間が「何を任せ、何を監督し、どこで判断するか」を設計すること**

が重要になります。

一言でまとめるなら、

> **AI時代の企業競争は「一番強いAIを持っている会社」ではなく、「AIと人間が働く仕組みを一番うまく設計した会社」の競争になる。**
