## 共通の認証構造

### 管理画面

`/admin` で始まる画面は、Next.js MiddlewareによるHTTP Basic認証の対象です。認証情報には次の環境変数が使用されます。

- `ADMIN_BASIC_USER`
    
- `ADMIN_BASIC_PASS`
    

認証ヘッダーがない場合は`401 Auth Required`、不一致の場合は`401 Unauthorized`を返します。

### 管理画面が利用するAPI

Middlewareのmatcherでは`api`が除外されています。そのため、`/api/...` は管理画面のBasic認証を通りません。

今回確認した管理用APIの多くは、APIハンドラー側でも管理者認証・管理者ロール確認を行っていません。

つまり、現在の構造は次のとおりです。

- 管理画面URLへのアクセス：Basic認証あり
    
- 管理画面から呼び出すAPI：原則として管理者認証なし
    
- API URLを直接呼び出した場合：Basic認証を経由しない
    

また、管理画面用Basic認証情報には環境変数未設定時の既定値がコード上に存在します。

# 1. 予約管理

## 役割

### 予約一覧

予約一覧画面では、全予約を取得して次の条件で検索・絞り込み・並び替えを行います。

- キーワード
    
- 予約ステータス
    
- 店舗
    
- 車種
    
- 貸出日
    
- 返却日
    
- 各表示列
    

一覧行を選択すると、予約詳細画面へ遷移します。予約一覧は`GET /api/reservations`で取得しています。

### 予約詳細

予約詳細画面では、主に以下を確認・操作します。

- 予約者・会員情報
    
- 予約車種・割当車両
    
- 貸出日時・返却日時
    
- 決済情報
    
- 予約ステータス
    
- レンタル延長
    
- 貸出日時変更
    
- 割当車両変更
    
- キャンセル
    
- 管理者返却承認
    

## 利用API

|Method|API|用途|
|---|---|---|
|`GET`|`/api/reservations`|予約一覧取得|
|`GET`|`/api/reservations/[reservationId]`|予約詳細取得|
|`PATCH`|`/api/reservations/[reservationId]`|日時、車両、ステータスなどの更新|
|`GET`|`/api/vehicles`|車両変更候補の取得|
|`GET`|`/api/vehicles/[managementNumber]`|現在の車両・日別空き状況の取得|
|`GET`|`/api/high-season?month=YYYY-MM`|延長料金計算用ハイシーズン設定の取得|
|`POST`|`/api/admin/return-approval`|管理者による返却完了登録|

予約詳細では、予約・対象車両・車両一覧をそれぞれ取得しています。

## 更新処理

### レンタル延長

1. 延長日数を入力
    
2. 現在の返却日時から新しい返却日時を計算
    
3. 同じ車両が延長期間中に空いているか確認
    
4. `PATCH /api/reservations/[reservationId]`へ`returnAt`を送信
    
5. 更新後の予約情報を画面に反映
    

管理画面内では決済処理を行わず、「別途ユーザーの決済が必要」と確認を表示します。

### 貸出日時変更

貸出日時を変更すると、元のレンタル時間を保ったまま返却日時を再計算し、`pickupAt`と`returnAt`をPATCHします。

API側では日時変更に連動して、車両の日別レンタル状態も更新します。また、返却日時が更新され、既存のKEYBOX PINがある場合はPINの再発行も試みます。

### 割当車両変更

同じ車種内の車両だけを変更できます。

更新内容は次のとおりです。

- `vehicleCode`
    
- `vehiclePlate`
    
- `vehicleModel`
    
- `vehicleChangeNotified`
    

API側では以下を行います。

- 変更先車両が存在するか確認
    
- 予約期間の全日で利用可能か確認
    
- 旧車両の予約期間を解放
    
- 新車両の予約期間を`RENTED`へ変更
    

画面からのPATCH処理は予約詳細に実装されています。

### キャンセル

キャンセルには2種類あります。

#### 返金あり

- ステータスを`キャンセル`へ更新
    
- PAY.JPの決済番号と決済金額を確認
    
- 売上日から180日以内か確認
    
- PAY.JP返金処理を実行
    
- 返金内容を`refundNote`へ保存
    

#### 返金なし

- `skipRefund: true`を指定
    
- PAY.JP返金を実行せずキャンセル
    
- 返金なしであることを`refundNote`へ保存
    

画面側の返金ありキャンセルと返金なしキャンセルは、それぞれ同じ予約PATCH APIを利用します。

### 管理者返却承認

`POST /api/admin/return-approval`へ予約IDを送信し、予約を返却済みに更新します。

## 認証

- 管理画面：Basic認証あり
    
- 予約一覧`GET`：管理者認証なし
    
- 予約詳細`GET`：管理者認証なし
    
- 予約更新`PATCH`：管理者認証なし
    
- 管理者返却承認`POST`：管理者認証なし
    

なお、顧客が予約を作成する`POST /api/reservations`ではCognito ID token cookieを検証していますが、管理画面が利用する予約一覧の`GET`には同じ検証がありません。

# 3. 料金設定

## 役割

### 車種ごとの料金設定

- バイククラス一覧を取得
    
- 車種一覧を取得
    
- 各車種の料金登録状況を表示
    
- 対象車種の日毎料金設定へ遷移
    

親画面では、クラスと車種を並行取得しています。

### 日毎料金設定

- 車種ごとの1～30日料金を表示
    
- 1日・2日・3日・4日・7日の基準料金を入力
    
- 中間日を自動計算
    
- 所属クラスの料金から初期値を生成
    
- 日単位で既存料金を削除
    

## 利用API

|Method|API|用途|
|---|---|---|
|`GET`|`/api/bike-classes`|クラス・クラス料金取得|
|`GET`|`/api/bike-models`|車種・所属クラス取得|
|`GET`|`/api/vehicle-rental-prices?vehicle_type_id=...`|車種別日次料金取得|
|`PUT`|`/api/vehicle-rental-prices`|日次料金の登録・上書き|
|`DELETE`|`/api/vehicle-rental-prices`|指定日の料金削除|

## 更新処理

料金保存では、計算した各日について次の形式で1件ずつ`PUT`します。

JSON

```
{
  "vehicle_type_id": 123,
  "days": 1,
  "price": 10000
}
```

画面側は日次料金を順番にAPIへ送信しており、単一の一括更新APIではありません。

そのため、途中で通信エラーになった場合は、先に処理された日だけ保存される可能性があります。

削除時は対象の`vehicle_type_id`と`days`を`DELETE`へ送信します。

## 認証

- 管理画面：Basic認証あり
    
- クラスAPI：認証・認可なし
    
- 車種API：認証・認可なし
    
- 日次料金API：認証・認可なし
    

料金登録・変更・削除APIも、管理者ロールを検証していません。

# 主な調査結果

## 1. 管理用APIに認証・認可がない

最も重要な点です。

管理画面自体はBasic認証で保護されていますが、Middlewareは`/api`を対象外にしています。

そのため、以下を含む更新APIは管理画面のBasic認証を通りません。

- 予約変更・キャンセル
    
- 管理者返却承認
    
- 会員備考・ブラックリスト更新
    
- 料金登録・削除
    
- 車両登録・更新・削除
    
- 店舗休日登録・削除
    
- お知らせバナー更新
    

これらにはAPI側の管理者認証・管理者ロール判定が必要です。

## 2. 「店舗管理」は休日管理に限定される

現状の対象店舗は2店舗固定で、次の機能はありません。

- 店舗追加
    
- 店舗削除
    
- 店舗名変更
    
- 住所・電話番号変更
    
- 営業時間変更
    

## 3. 「通知管理」はバナー管理に限定される

現状の管理画面では次の操作はできません。

- 会員への個別通知作成
    
- 一斉通知配信
    
- メール通知配信
    
- 通知予約
    
- 配信対象条件設定
    
- 配信履歴確認
    
- 管理者による既読状況確認
    

## 4. 一部の一括処理が非トランザクション

次の処理は複数回のAPI呼び出しで構成されています。

- 車種別の日次料金保存
    
- 車両CSV一括登録
    

途中で失敗すると、一部のみ保存された状態になる可能性があります。
