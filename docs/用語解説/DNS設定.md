## 概要

**DNS（Domain Name System）設定**とは、**「名前」と「IPアドレス」を結び付けるための設定**です。

人間は

```
google.com
```

のような名前なら覚えられますが、

コンピューターは

```
142.250.xxx.xxx
```

のようなIPアドレスで通信します。

DNSは、この変換をしてくれる「電話帳」のような仕組みです。

---

# DNS設定の流れ

実際の案件では、IPアドレス設定と同じタイミングで行います。

```
① DNSサーバーを確認
        ↓
② DNSアドレスを設定
        ↓
③ 名前解決テスト
        ↓
④ 動作確認
```

---

# ① DNSサーバーを確認

設計書にDNSサーバーのIPアドレスが記載されています。

例

|項目|値|
|---|---|
|Primary DNS|192.168.10.2|
|Secondary DNS|192.168.10.3|

Primaryが使えない場合はSecondaryが利用されます。

---

# ② DNSアドレスを設定

## Windows Server

ネットワーク設定画面から設定します。

```
IPv4

↓

Preferred DNS

192.168.10.2

↓

Alternate DNS

192.168.10.3
```

---

## Linux

`nmcli` や設定ファイルで設定します。

例

```
DNS1
192.168.10.2

DNS2
192.168.10.3
```

---

# ③ 名前解決テスト

設定後は必ず確認します。

Windows

```
nslookup google.com
```

Linux

```
nslookup google.com

または

dig google.com
```

結果

```
Name:
google.com

Address:
142.xxx.xxx.xxx
```

が返ってくれば成功です。

---

# DNSが動くイメージ

```
利用者

google.com
      │
      ▼
DNSサーバー
      │
「IPは 142.xxx.xxx.xxx です」
      │
      ▼
Googleサーバー
```

DNSが名前をIPアドレスへ変換してくれるため、通信できます。

```
192.168.10.2
```

```
192.168.10.3
```

```
nslookup

↓

↓

正常応答
```

まで確認します。

---

# DNSがないとどうなる？

例えば

```
google.com
```

へアクセスするとします。

### DNSあり

```
google.com

↓

DNS

↓

142.xxx.xxx.xxx

↓

接続成功
```

---

### DNSなし

```
google.com

↓

×

IPが分からない

↓

接続できない
```

つまり、**名前ではアクセスできなくなります。**

---

# DNSとIPアドレスの違い

|項目|IPアドレス|DNS|
|---|---|---|
|役割|通信先の住所|名前と住所を対応付ける|
|例|192.168.10.20|google.com → 142.xxx.xxx.xxx|
|人が使うもの|あまり使わない|普段はこちらを使う|

---

# 実務でのポイント

実際の企業では、DNSサーバーは社内で運用されていることが多く、サーバーやPCは**社内DNS**を参照するよう設定します。

特にActive Directory環境では、DNSは認証やサーバー探索にも利用されるため、**DNS設定を間違えるとドメイン参加やログインができなくなる**こともあります。

そのため構築時には、

- DNSサーバーのIPが正しいか
- `nslookup` や `dig` で名前解決できるか
- `ping` で通信できるか

を必ず確認して、「DNS設定完了」とします。
