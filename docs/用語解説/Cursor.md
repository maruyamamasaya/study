# Cursorとは？初心者向け勉強会資料

Cursor（カーソル）は、

> **AIを使ったプログラミングに特化したコードエディタ**

です。

見た目や基本操作はVS Codeに近いですが、AIにコードを質問したり、複数ファイルをまとめて修正させたりできる点が大きな特徴です。現在のCursorは、単なるコード補完ツールではなく、AIエージェントと一緒にソフトウェアを作るための開発環境として提供されています。([Cursor](https://cursor.com/?utm_source=chatgpt.com "Cursor: AI coding agent"))

---

# 1. Cursorを簡単にいうと

```text
VS Codeのようなエディタ
          ＋
AIチャット
          ＋
コード生成
          ＋
複数ファイルの調査・修正
```

つまり、

> **コードを書くだけでなく、AIに相談しながら開発できるエディタ**

です。

例えば、AIに次のような依頼ができます。

```text
このエラーの原因を調べて

この画面に検索機能を追加して

この関数を読みやすく書き直して

このプロジェクト全体の構成を説明して
```

# 2. VS Codeとの関係

CursorはVS Codeに近い操作感を持っています。

そのため、VS Codeを使ったことがある人なら比較的移行しやすく、ファイル操作、ターミナル、Git、拡張機能なども似た感覚で扱えます。

```text
VS Code
├─ コード編集
├─ ターミナル
├─ Git
├─ デバッグ
└─ 拡張機能

Cursor
├─ コード編集
├─ ターミナル
├─ Git
├─ デバッグ
├─ 拡張機能
└─ AI機能
```

ただし、CursorはMicrosoftが提供するVS Codeそのものではなく、Cursor社が提供する別の製品です。

# 3. Cursorでできること

## コードの自動補完

コードを書いている途中で、AIが続きのコードを提案します。

```typescript
function calculateTotal(price: number, quantity: number) {
```

ここまで書くと、AIが次のような続きを提案することがあります。

```typescript
  return price * quantity;
}
```

提案内容がよければ、Tabキーなどで採用できます。

---

## AIにコードを質問する

プロジェクトを開いた状態で、AIにコードについて質問できます。

```text
この関数は何をしている？

このAPIはどこから呼ばれている？

このエラーが発生する原因は？

この処理にセキュリティ上の問題はある？
```

通常のAIチャットとの違いは、Cursorが開いているプロジェクトのコードを参照しながら回答できることです。

---

## コードを書き換える

コードを選択して、AIに修正を依頼できます。

例えば、

```text
この処理をTypeScriptらしく書き直して

エラーハンドリングを追加して

重複している処理を関数にまとめて

コメントを追加して
```

といった依頼ができます。

---

## 複数ファイルをまとめて変更する

CursorのAIエージェントは、1つのファイルだけではなく、関連する複数のファイルを調べて変更できます。現在のCursorは、複数リポジトリを含む作業やエージェント中心の開発環境を強化しています。([Cursor](https://cursor.com/blog/cursor-3?utm_source=chatgpt.com "Meet the new Cursor"))

例えば、ログイン機能を追加する場合は、

```text
ログイン画面
API
認証処理
型定義
エラー表示
```

など、複数箇所の変更が必要です。

```text
ユーザーの依頼
   ↓
AIが関連ファイルを検索
   ↓
変更内容を考える
   ↓
複数ファイルを修正
   ↓
人間が確認
```

---

## コードベースを調査する

大きなプロジェクトでは、どこに何が書かれているか分からないことがあります。

Cursorに、

```text
予約登録の処理はどこ？

管理画面の認証方法を調べて

Pay.JPの決済処理の流れを説明して

DynamoDBへ保存している箇所を探して
```

と依頼すると、関連ファイルを探して説明させることができます。

---

## ターミナル操作を支援する

Cursorの中にはターミナルがあります。

```bash
npm install
npm run dev
npm test
git status
```

AIエージェントが必要なコマンドを提案・実行する場合もあります。

ただし、コマンドによってはファイル削除、データ変更、デプロイなどが起こるため、実行内容の確認が重要です。

# 5. Cursorの代表的なAI機能

## Tab補完

入力中のコードの続きを提案します。

```text
人間がコードを書く
       ↓
AIが続きを予測
       ↓
Tabで採用
```

単純な1行だけでなく、周囲のコードを考慮して複数行を提案することもあります。

---

## インライン編集

コード上で直接AIに修正を依頼する機能です。

例えば、処理を選択して、

```text
このコードを短くして
```

と依頼します。

```typescript
if (isLoggedIn === true) {
  return true;
} else {
  return false;
}
```

AIによる修正例：

```typescript
return isLoggedIn;
```

---

## チャット

AIと会話しながらコードを調査できます。

```text
ユーザー：
このファイルの役割を説明して

AI：
このファイルは予約情報を取得し、
画面へ表示する処理を担当しています。
```

---

## Agent

Agentは、AIが目的を達成するために自分で関連ファイルを探し、修正やコマンド実行を進める機能です。

```text
依頼
 ↓
調査
 ↓
計画
 ↓
コード変更
 ↓
テスト
 ↓
結果報告
```

例えば、

```text
お問い合わせフォームを追加して
```

と依頼すると、AIが次のような作業を検討します。

```text
フォーム画面を作成
入力チェックを追加
送信APIを作成
メール送信処理を追加
エラー表示を追加
```

# 6. 通常のAIチャットとの違い

例えば、ブラウザ上のAIにコードを質問する場合、必要なコードをコピーして渡すことがあります。

```text
コードをコピー
   ↓
AIチャットへ貼り付け
   ↓
回答をコピー
   ↓
エディタへ貼り付け
```

Cursorでは、開いているプロジェクト内で作業できます。

```text
Cursorでコードを開く
   ↓
その場でAIに質問
   ↓
その場で修正
   ↓
差分を確認
```

このため、大きなコードベースの調査や複数ファイルの修正で特に便利です。

# 7. Cursorを使った開発の流れ

例えば、新しい機能を追加する場合です。

```text
① Git Pull
   ↓
② Cursorでプロジェクトを開く
   ↓
③ AIに既存処理を調査させる
   ↓
④ 実装方針を考える
   ↓
⑤ 小さな単位でコードを変更する
   ↓
⑥ npm test・lintを実行する
   ↓
⑦ ブラウザで動作確認する
   ↓
⑧ Git差分を確認する
   ↓
⑨ Commit・Pushする
```

重要なのは、AIにすべて任せて終わりにしないことです。

# 9. Cursorの注意点

## AIのコードが正しいとは限らない

Cursorは、もっともらしいコードを生成します。

しかし、

- 存在しない関数を使う
    
- 古い書き方を使う
    
- 要件を勘違いする
    
- セキュリティ上の問題を作る
    
- 既存機能を壊す
    

可能性があります。

```text
AIがコード生成
      ↓
人間が差分確認
      ↓
テスト
      ↓
動作確認
      ↓
採用
```

この流れが必要です。

---

## 大きすぎる依頼は危険

例えば、

```text
このシステムを全部いい感じに修正して
```

という依頼では、変更範囲が広くなりすぎます。

代わりに、

```text
まず予約登録処理を調査して

次に問題点だけ挙げて

その後、入力チェックだけ修正して
```

のように小さく分けます。

---

## データや秘密情報に注意する

プロジェクトには、次のような情報が含まれることがあります。

```text
APIキー
パスワード
顧客情報
決済情報
.envファイル
AWS認証情報
```

AIツールへどの情報が送信される可能性があるか、組織のセキュリティ方針やCursorのプライバシー設定を確認する必要があります。

---

## AIに設計判断を丸投げしない

AIはコードを書くのは速いですが、ビジネス要件や将来の運用まで完全に理解しているとは限りません。

```text
人間
├─ 何を作るか
├─ なぜ作るか
├─ 設計方針
├─ セキュリティ判断
└─ 最終確認

AI
├─ コードの提案
├─ 調査
├─ 修正
├─ テスト作成
└─ 説明
```

基本的には、

> **設計と判断は人間、実装支援はAI**

と考えると安全です。

# 10. 良い依頼の仕方

悪い例：

```text
いい感じに直して
```

良い例：

```text
pages/api/reservations.tsを確認してください。

予約日が過去の日付の場合に、
400エラーを返す入力チェックを追加してください。

既存のレスポンス形式は変更せず、
変更後にテストも追加してください。
```

良い依頼には、次の要素があります。

|要素|内容|
|---|---|
|対象|どのファイル・機能か|
|目的|何を実現するか|
|制約|何を変更しないか|
|完了条件|どの状態なら完了か|
|確認方法|テストや動作確認方法|
