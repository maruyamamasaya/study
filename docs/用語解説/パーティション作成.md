## 概要

**パーティション**とは、**1台のディスクを複数の領域に分けて使う仕組み**です。

例えば、500GBのディスクをそのまま1つで使うこともできますが、

- Cドライブ（OS用）
- Dドライブ（データ用）

のように分けることができます。

---

## パーティション作成の流れ

実際の案件では、**RAID設定が終わった後、OSインストール中またはインストール後**にパーティションを作成します。

```
① RAID設定
        ↓
② ディスク認識
        ↓
③ パーティション作成
        ↓
④ フォーマット
        ↓
⑤ ドライブ作成
        ↓
⑥ OS利用開始
```

---

# ① RAID設定

まずRAIDで1つのディスクとして認識させます。

例えば

```
SSD 500GB ×2

↓

RAID1

↓

500GB
```

---

# ② ディスク認識

WindowsやLinuxからは

```
Disk0

500GB
```

という1台のディスクとして見えます。

---

# ③ パーティション作成

ここでディスクを分割します。

例えば500GBなら

```
500GB

↓

100GB
400GB
```

というように分けます。

---

## イメージ

```

│                        │
│       500GB            │
│                        │

```

↓

```
┌───────┬────────────────┐
│100GB  │     400GB      │

```

# ④ フォーマット

パーティションを作っただけでは使えません。

ファイルシステムを設定します。

Windowsなら

```
NTFS
```

Linuxなら

```
ext4
```

や

```
XFS
```

がよく使われます。

---

# ⑤ ドライブ作成

Windowsなら

```
C:
D:
```

Linuxなら

```
/
/home
/var
```

などになります。

---

# Windows Serverの例

500GBのディスク

```
Cドライブ
100GB

Dドライブ
400GB
```

用途

|ドライブ|用途|
|---|---|
|C:|Windows Server本体|
|D:|ファイル・ログ・アプリケーション|

---

# Linuxの例

500GB

```
/
100GB

/var
300GB

/home
100GB
```

用途

|パーティション|用途|
|---|---|
|/|OS本体|
|/var|ログ・データベース・アプリデータ|
|/home|ユーザーのホームディレクトリ|

# なぜパーティションを分けるの？

例えばログファイルが大量に増えた場合、

```
C:
100%

↓

Windowsが起動しない
```

ということもあります。

そこで、

```
C:
（OS）

D:
（ログ）
```

のように分けておけば、ログが増えてもOSには影響しにくくなります。

---

# 実務でのポイント

パーティション設計は、**サーバーの役割に応じて最初に決める重要な作業**です。

- ファイルサーバーなら「OS用」と「データ用」
- Webサーバーなら「OS」と「ログ用」
- DBサーバーなら「OS」「データ」「トランザクションログ」

のように分けることで、**障害時の影響を減らし、運用しやすい構成**にできます。

---

# RAIDとの違い

|項目|RAID|パーティション|
|---|---|---|
|目的|ディスクをまとめて性能・冗長性を高める|1台のディスクを用途ごとに分ける|
|実施タイミング|OSインストール前|RAID設定後、OSインストール時または後|
|例|SSD×2 → RAID1で500GB|500GB → C:100GB + D:400GB|
|効果|故障対策・高速化|データ整理・運用性向上|

つまり、**RAIDは「複数のディスクをどう使うか」を決める技術**、**パーティションは「1つのディスク領域をどう分けて使うか」を決める技術**です。
