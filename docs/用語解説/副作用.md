フロントエンド、特に **JavaScript / React / Vue** の記事ではかなりよく出てくる言葉です。

一言でいうと、

> **「その処理の外側の世界に影響を与えること」**

です。

## まず普通の処理と比較

例えば単純な計算。

```
function add(a, b) {
  return a + b;
}

const result = add(10, 20);
```

これは、

```
10 + 20
  ↓
30を返す
```

だけです。

外部のデータを書き換えたり、通信したりしていません。

こういう処理は**副作用がない処理（純粋な処理）**と考えられます。

---

## 副作用がある処理

例えばAPI通信。

```
async function getUsers() {
  const response = await fetch("/api/users");
  return response.json();
}
```

これは、

```
JavaScript
   │
   │ HTTP通信
   ↓
APIサーバー
   │
   ↓
データ取得
```

というように、**プログラムの外部とやり取りしています。**

これが副作用の代表例です。

ほかにも、

- API通信する
- DBにデータを保存する
- `localStorage` に保存する
- Cookieを書き換える
- DOMを直接操作する
- タイマーを開始する
- イベントリスナーを登録する
- ログを出力する

なども副作用です。

## Reactで「副作用」が重要な理由

Reactを勉強すると、

```
useEffect(() => {
  // 処理
}, []);
```

をよく見かけます。

`useEffect` の **Effect** が、まさに「副作用」です。

例えば画面を開いたときにAPIからユーザー情報を取得する場合。

```
useEffect(() => {
  fetch("/api/users")
    .then(res => res.json())
    .then(data => setUsers(data));
}, []);
```

イメージすると、

```
コンポーネント表示
      ↓
   useEffect
      ↓
   APIへ通信      ← 副作用
      ↓
 データを取得
      ↓
 setUsers()
      ↓
 State変更
      ↓
再レンダリング
```

となります。

## なぜわざわざ「副作用」と呼ぶの？

Reactでは基本的に、

```
State / Props
      ↓
コンポーネント
      ↓
     UI
```

という**入力からUIを決める処理をシンプルに保ちたい**からです。

例えばコンポーネントの本体で毎回API通信すると、

```
function UserList() {

  fetch("/api/users"); // 危険

  return <div>Users</div>;
}
```

再レンダリングされるたびに、

```
レンダリング
 ↓
API通信

再レンダリング
 ↓
API通信

再レンダリング
 ↓
API通信
```

となる可能性があります。

だから、

```
UIを計算する処理

と

外部に影響する処理（副作用）

を分けよう
```

という考え方が重要になります。

---

## 「副作用＝悪いこと」ではない

ここはかなり重要です。

「副作用」という名前なので悪い処理に聞こえますが、**副作用そのものが悪いわけではありません。**

Webアプリでは、

```
API通信
DB保存
localStorage
Cookie
イベント
タイマー
```

などは当然必要です。

問題なのは、

> **副作用が「いつ・なぜ実行されるのか」が分からなくなること**

です。

そのためReactでは、`useEffect`などを使って副作用を適切なタイミングで扱います。

### 覚え方

```
純粋な処理
「入力を受け取って結果を返す」

例
10 + 20 → 30


副作用
「外の世界と何かする」

例
API通信
localStorage
Cookie
DOM操作
タイマー
イベント登録
```

Reactの記事で**「副作用を避ける」「副作用を分離する」「useEffectで副作用を扱う」**と出てきたら、

> **API通信などの「外部とのやり取り」を、UIを作る処理からちゃんと分離しよう**

くらいに捉えると理解しやすいです。
