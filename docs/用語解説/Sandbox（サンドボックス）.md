**Sandbox（サンドボックス）**とは、一言でいうと

> **「本物の環境に影響を与えず、安全に試せる隔離された実験場所」**

です。子どもが砂場で自由に遊んでも周りが汚れないことから、この名前が付いています。

---

## イメージ

```
あなたのPC
┌────────────────────┐
│                    │
│  Sandbox           │
│  ┌──────────────┐  │
│  │ プログラム実行 │  │
│  │ テスト        │  │
│  │ ファイル操作   │  │
│  └──────────────┘  │
│                    │
└────────────────────┘
```

Sandboxの中で何か問題が起きても、基本的には外側のPCやサーバーには影響しません。

---

## なぜ必要？

例えば、知らないプログラムを実行すると…

- ウイルスかもしれない
- バグでPCが壊れるかもしれない
- 大事なデータを消すかもしれない

Sandboxなら、

- ファイルアクセスを制限
- ネットワークを制限
- 権限を制限

して実行できるため、安全に動作確認できます。

---

# エンジニアが使うSandbox

### ① 開発・テスト環境

本番データを壊さずに機能追加を試せます。

例：

```
本番環境
ユーザー100万人

↓

Sandbox
ユーザー0人
好きにテスト
```

---

### ② AI開発

ChatGPTなどもSandboxで動くことがあります。

例えばこのチャットでも、

- Pythonコード実行
- ファイル作成
- データ解析

などは**隔離された実行環境（Sandbox）**で行われます。

そのため、

- あなたのPCを直接操作するわけではない
- あなたのMacのファイルを勝手に読むことはできない

という安全設計になっています。

---

### ③ ブラウザ

ChromeやEdgeもSandboxを使っています。

例えば悪意のあるWebサイトを開いても、

```
Webページ
    ↓
ChromeのSandbox
    ↓
PC
```

という構造になっており、直接OSへ攻撃しにくくしています。

---

### ④ マルウェア解析

セキュリティ会社では、

```
ウイルス

↓

Sandboxで実行

↓

何をするか観察
```

という使い方をします。

もし本物のPCで実行したら感染してしまうので、Sandbox内だけで動かします。

---

# 実務での例

AWSでもSandboxという考え方があります。

例えば

- 開発環境（Development）
- Sandbox環境
- ステージング環境
- 本番環境（Production）

という構成にして、

```
Sandbox
    ↓
開発
    ↓
ステージング
    ↓
本番
```

の順番で確認してからリリースすることがよくあります。

---

# Dockerとの違い

Dockerも隔離環境を作れますが、役割が少し異なります。

|Sandbox|Docker|
|---|---|
|安全に試すことが目的|アプリを同じ環境で動かすことが目的|
|セキュリティ重視|配布・開発効率重視|
|権限制限が多い|必要に応じて自由に設定できる|

DockerコンテナをSandboxとして利用するケースもよくあります。

# 一言でまとめると

**Sandbox = 「失敗しても大丈夫な安全な実験場」**です。

開発・セキュリティ・AI・ブラウザなど、現代のソフトウェア開発では非常に重要な仕組みになっています。
