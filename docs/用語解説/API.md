## 概要

**API（Application Programming Interface）**とは、

> **ソフトウェア同士がデータや機能をやり取りするための「窓口」や「ルール」**です。

簡単に言うと、

**「プログラム同士が会話するための仕組み」**です。

私たちが普段使うWebサービスの多くは、APIを使ってデータをやり取りしています。

---

## なぜAPIが必要？

例えば、ECサイトで商品一覧を表示するとき、

ブラウザには商品のデータは保存されていません。

そこで、

```
ブラウザ
   │
「商品一覧ください！」
   │
   ▼
API
   │
データベースから取得
   │
   ▼
商品データを返す
```

APIが間に入ることで、

- データを安全に取得できる
- 必要な情報だけ渡せる
- フロントエンドとバックエンドを分けて開発できる

というメリットがあります。

---

# 基本的な仕組み

APIは、

**リクエスト（お願い）**  
と  
**レスポンス（返事）**

のやり取りで動きます。

```
フロントエンド
      │
      │ リクエスト
      ▼
      API
      │
      │ データ取得
      ▼
データベース
      │
      │ データ
      ▼
      API
      │
      │ レスポンス
      ▼
フロントエンド
```

---

## リクエストとは？

APIへ送るお願いです。

例えば、

```
ユーザー情報をください
```

というリクエストを送ります。

実際には

```
GET /users/1
```

のようになります。

---

## レスポンスとは？

APIから返ってくる返事です。

例えば、

```
{
  "id": 1,
  "name": "山田太郎",
  "age": 30
}
```

JSONという形式で返ってくることが多いです。

---

## HTTPメソッド

APIでは目的ごとに使うメソッドが決まっています。

|メソッド|意味|実務例|
|---|---|---|
|GET|取得|商品一覧取得|
|POST|新規作成|会員登録|
|PUT|更新|ユーザー情報更新|
|PATCH|一部更新|メールアドレス変更|
|DELETE|削除|予約キャンセル|

---

# 具体例

## 商品一覧を取得

```

```

レスポンス

```
[
  {
    "id":1,
    "name":"ノートPC",
    "price":120000
  },
  {
    "id":2,
    "name":"マウス",
    "price":3000
  }

```

---

## 会員登録

```
POST /users
```

送信するデータ

```
{
  "name":"山田太郎",
  "email":"test@example.com"
}
```

成功すると

```
{
  "message":"登録しました"
}
```

が返ります。

---

## 予約システムの例

あなたが作成していたような予約システムでは、

```
予約画面
      │
      ▼
POST /reservations
      │
      ▼
API
      │
予約を保存
      ▼
RDS(MySQL)
```

という流れになります。

# APIがあるメリット

## フロントエンドとバックエンドを分けられる

```
React / Next.js
        │
        │ API
        ▼
Node.js
        │
        ▼
RDS
```

フロントエンド担当とバックエンド担当が並行して開発できます。

# 関連知識

## REST API

現在最もよく使われるAPIの設計方法です。

特徴

- URLが分かりやすい
- HTTPメソッドを使い分ける
- JSONで通信することが多い

例

```
GET /users
POST /users
DELETE /users/1
```

---

## JSON

APIで最も使われるデータ形式です。

```
{
  "name":"田中",
  "age":25
}
```

---

## 認証

誰でもAPIを使えると危険です。

そのため、

- ログイン
- APIキー
- JWT
- OAuth

などを利用して本人確認を行います。

---

## ステータスコード

APIは処理結果も返します。

|コード|意味|
|---|---|
|200|成功|
|201|作成成功|
|400|リクエストが不正|
|401|未認証|
|403|権限なし|
|404|データが見つからない|
|500|サーバーエラー|

---

# APIとデータベースの違い

|API|データベース|
|---|---|
|データの受け渡しを担当|データを保存する|
|アプリとの窓口|データの保管場所|
|HTTPで通信する|SQLで操作する|

---

# まとめ

APIとは、

**「ソフトウェア同士が安全にデータや機能をやり取りするための窓口」**です。

現在のWebサービスでは、フロントエンド・バックエンド・データベース・外部サービスをつなぐ中心的な役割を担っています。

```
利用者
   │
   ▼
フロントエンド（React・Next.js）
   │
   │ API
   ▼
バックエンド（Node.js・Java・PHP）
   │
   ▼
RDS（MySQL・PostgreSQL）
```

このように、**APIは「フロントエンド」と「バックエンド」をつなぐ橋渡し役**として、実務では欠かせない存在です。ｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖｖ
