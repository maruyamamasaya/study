
enumは **「予約状態はこの3種類だけ」のように、使える値を名前付きで限定する仕組み**

TypeScriptの通常の `enum` の欠点は、**型として使うだけなのに、JavaScriptコードが生成される**こと

「バンドル」とは？
ブラウザに送るために、何百・何千ものJavaScriptファイルを1つ（または数個）にまとめたファイル

tree shaking　木を揺らす
「使っていないコードを最終的なバンドル（bundle.js）から自動的に削除する仕組み」

即時実行関数（Immediately Invoked Function Expression: IIFE）
「定義した瞬間に、その場で1回だけ実行される関数」
オブジェクトを初期化したい+グローバル関数化しない→スコープを閉じ込める　ということ

IIFEの関数は副作用があるコードとして扱われやすい。つまり動作が変わるような感じなので、Treeshakingで振り落としづらい


→
TypeScriptは、**古いJavaScript環境でも動くコードを生成できる**ことを重視して設計されました。

そのため、`enum`をJavaScriptに変換するときも、**昔から広く使われていたIIFE（即時実行関数）を使ってオブジェクトを組み立てる方式**を採用しています。

現在のJavaScriptでは `const` や `class`、ES Modules が使えるため、自分でIIFEを書く機会はほとんどありません。しかし、TypeScriptが生成したコードを見ると、**JavaScriptの歴史的な書き方の名残**を見ることができます。



TypeScriptのデザインゴールは、「JavaScriptを壊さずに、大規模開発をしやすくすること」です

３
実行時オーバーヘッドを課さないとは、TypeScriptの型情報はコンパイル時だけに使われ、実行時にはすべて消えるため、JavaScriptだけで書いた場合とほぼ同じ性能で動作する、という意味です

TypeScriptコンパイラ
→TypeScriptのコードをJavaScriptに変換するプログラムです。その変換を行う前に、型の間違いや文法エラーがないかをチェックしてくれます。

TypeScriptは
プログラムを実際に動かさなくても、コードを見て問題を見つけてくれる
つまり、エラーになりやすい構造を静的に特定するとは、プログラムを実行する前に、型の不一致や存在しないプロパティへのアクセスなど、バグになりそうな箇所をコード解析で見つけることです。

ECMAScript提案とは、「JavaScriptに将来追加したい新機能の案」のことです。

クロスプラットフォーム開発とは、1つのソースコードを複数のOSや実行環境で利用できるようにする開発手法です。TypeScriptはJavaScriptへ変換されるため、ブラウザやNode.js、React Nativeなどさまざまな環境で利用でき、クロスプラットフォーム開発に適しています。

完全に消去可能（Fully Erasable）
**実行速度はJavaScriptとほぼ同じ**になります。


> 通常のTypeScriptの型はコンパイル後に消えるが、`enum` は実行時の値として残るため、「完全に消去可能な型システム」という思想とは例外的な位置づけになる

という理解で合っています。

型の制限だけが目的なら、こちらの方が思想に合っています。

```
type Status = "pending" | "paid";
```

これはJavaScriptには何も生成されません。


Node.jsが直接TypeScriptを実行するときに行うのは、基本的に、

> 型を取り除いて実行すること

です。

**TypeScriptの型が正しいかどうかはチェックしません。**

Node.jsでビルドなしのTypeScript実行するには、enumは使えない
